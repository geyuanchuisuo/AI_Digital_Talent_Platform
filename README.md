## Git 拉取后先做这些

先读 [AGENTS.md](AGENTS.md)、[更新记录](更新记录.md)、[协作操作指南](docs/协作操作指南.md) 和 [模块归属](docs/模块归属.md)。确认本人 A/B/C/D 角色，再读对应 [A](tasks/A.md) / [B](tasks/B.md) / [C](tasks/C.md) / [D](tasks/D.md) 任务卡及最新交接。

需求与协作基线已于 2026-11-06 发布到 `origin/master`（`5c3df08`）。任何成员与 Agent 都不得在 `master` 开发或创建开发提交；它仅用于经明确授权的集成与发布。每个人在自己的个人分支开发；`master_YB` 只是本次用户的个人分支，其他成员继续使用各自的分支。

Git 不会自动安装 hooks：每人在自己的 clone 确认角色后运行 `python scripts/setup_collaboration.py --actor B --branch <本人分支>`（B 换成本人角色，分支换成本人已有分支）。个人分支登记仅在本人 clone 生效，不会要求其他成员切换分支。新任务也可使用 `feature/B/<任务>` 等角色分支。分支名不代表角色，不要在角色未知时运行或猜测身份。规则与脚本的新变更提交到远端后，其他人 pull 才会取得。

已提供提交前路径检查、独立更新记录及跨模块请求模板；它们减少误改，不是不可绕过的权限系统。共享文件由指定角色集成，远端保护与评审另由仓库负责人配置。业务尚未实现，协作工具的通过不等于产品测试通过。

## 模型与配置

已指定对话模型：Agnes `agnes-3.0-flash`；基础地址：`https://api.agnes-ai.cn/v1`。尚未在本项目验证协议、结构化输出和其他能力。不要默认它提供 Embedding、OCR 或图片输入；实际需要时分别验证或采用独立适配器。

技术选型可自主决定。四人试行方案推荐 React + Vite、FastAPI、SQLAlchemy、MySQL 与本地文件；具体见技术框架。原先 SQLite 为单人方案建议，现在优先验证 MySQL 以统一四人数据与事务行为。Milvus、Redis、Dify、Vanna.ai 等不作为一期前置组件；后续有明确业务需要再引入。所有版本需验证后锁定。

密钥从本地环境配置读取，不写入源码、文档、浏览器响应或日志。需要真实接口验收时，由本机提供有效凭据；没有凭据的验证应记录为未执行或阻塞，不以模拟响应代替。

## 数据与演示

使用虚构或脱敏样例，至少覆盖两种账号、两个岗位、混合简历格式、不同难度题目、课程和授权范围不同的知识文档。所有模块通过稳定的 person_id 关联，不能按姓名认定同一人。

演示顺序建议：岗位→批量简历→档案→匹配与复核→测评/面试→培训→知识/档案问答→自由问数与报告→工作流和真实工作台统计。另验证失败文件、模型超时、重试幂等、个人端越权和重启后的数据保留。

旧 `docs/test/seed_data.sql` 与 JSON 只作历史参考，不直接当成新系统可用的初始化脚本或准确率证明。新样例、模型输出和评测结果应区分保存。
