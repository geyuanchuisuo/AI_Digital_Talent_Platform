# 需求拆解与模块边界

## 1. 产品与角色

产品核心不是通用聊天机器人，而是有人才主数据和业务状态的人才管理系统。推荐统一主线：项目需求→岗位条件→简历上传解析→候选人档案→匹配推荐→测评/面试→录用/入职→培训→画像更新→统计决策。知识库和智能体为所有域提供能力。

| 角色 | 核心操作 | 数据范围建议 |
|---|---|---|
| 员工 | 本人档案、考试、课程、制度问答 | 本人+已授权公共知识 |
| HR | 简历、岗位、候选人、测评与面试 | 分配的招聘项目和组织范围，不能只假设HR所属部门 |
| 业务负责人 | 项目需求、缺口、推荐与培训建议 | 本部门/项目授权范围 |
| 管理层 | 指标、问数、报告 | 授权组织聚合数据，敏感明细单独授权 |
| 管理员/运维 | 身份、权限、模型、Agent与运行监控 | 管理权限与敏感业务数据阅读权限分别控制 |
| 候选人（补充待确认） | 外部邀约、考试和面试 | 仅授权任务，区别内部员工账号 |

## 2. 模块分类与交付要求

优先级是建议开发顺序，不代表删减完整要求。完整交付仍覆盖全部PRD。

| 编号/域 | 需求拆解 | 输入→输出 | 原型/原测试 | 首批优先 |
|---|---|---|---|---|
| B01 人才档案 | PDF/Word/图片/扫描件解析、失败重试、查重合并、标签画像、自然语言检索、单批档案问答 | 文件→结构化字段/证据/统一人才档案 | 简历筛选、画像；TC-RES01–06 | 高 |
| B02 测评研判 | 题库、出卷、作答、自动评分、自适应难度、能力评级、错题复习、面试记录 | 岗位能力+题库→试卷/成绩/能力维度 | 智能测评；TC-EXM01–06 | 中 |
| B03 岗位匹配 | 项目需求、岗位结构化、硬条件过滤、向量召回、0–100评分与解释、缺口预警、储备推荐 | 岗位+人才证据→匹配明细/推荐名单 | 岗位匹配；TC-MAT01–04 | 高 |
| B04 培训成长 | 能力诊断、个性化计划、课程附件、学习进度、有效学时、防挂机、结业测评、成长历史 | 测评缺口→学习任务→更新画像 | 个性化培训；TC-TRN01–04 | 中 |
| B05 数据决策 | 自然语言问数、指标定义、受控查询、图表、解释、Word/PDF导出 | 授权指标数据→结果/建议/可下载报告 | 智能问数；TC-DEC01–03 | 中 |
| P01 RAG知识 | 分类、上传解析、切片索引、检索重排、来源定位、分级访问、拒答、版本更新删除 | 企业知识→有来源答案 | 知识库；TC-RAG01–04 | 高 |
| P02 AI中台 | 5种Agent、模型/Prompt管理、LangGraph流程、Dify接入、Skills、触发、重试、人工节点、日志 | 业务事件→可追踪工作流执行 | 编排中心；TC-AGT01–05 | 高（先最小工作流） |
| P03 身份安全 | 登录、组织、角色、菜单、按钮、行字段权限、导出权限、日志、限流 | 身份/策略→授权结果与审计 | 系统管理；TC-SYS01–05 | 最高 |
| V01 门户运营 | 指标卡、任务状态、预警、运行健康 | 各域事实→驾驶舱 | 智能工作台 | 中 |

JD投放、智能邀约、多轮面试、花名册、项目群、IM账号、数字机器人属于支撑业务扩展。它们出现在历史菜单/表中，应在范围表中逐项确认深度，尤其外部投放/IM发送需要真实渠道、账号和回执，不能由一个按钮推定已经实现。

## 3. 关键业务规则建议

- 档案：人才person_id贯穿候选、员工、测评与学习；文件与解析结果分开，保留原文页码、字段置信度、人工修订和历史版本。百级标签是标签体系规模，不能强制每人凑满100个标签。
- 匹配：硬条件是否一票否决先配置；软项归一权重总和为1，保留每项证据。向量相似度与业务匹配分不同，匹配分与准确率不同。原型年限不足却高分的情况需通过规则明确解释。
- 测评：随机抽题不等于真正自适应；需记录逐题难度、能力估计、选题策略、题目曝光与终止条件。主观评分保存量表和复核渠道。
- 培训：缺口指标连接具体课程、完成标准和复测；浏览器心跳只证明在线，不能单独证明学习。服务端记录有效区间并去重，不信任前端累计秒数。
- RAG：授权过滤在召回和生成之前完成；引用到文档版本、切片、页码/章节。无证据、矛盾证据、权限不足分别响应，不伪造引用。
- Agent：五类Agent是职责边界，不必每次都启动五个模型；确定性规则由代码执行，AI处理抽取、解释和推荐，关键业务变更保存确认与证据。
- 问数：招聘完成率、缺口、人均学时先形成指标字典；报告数据与页面同一快照，不让语言模型凭空编数字。

## 4. 第一个可演示闭环

管理员建用户权限→HR建岗位→上传真实简历→队列解析→人工确认字段→创建人才档案→匹配打分并展示证据→知识库问答给出引用→工作台展示真实任务统计。随后增加测评—培训—画像更新、问数—报告两个闭环。

## 5. 页面补充规格

11页只是总览。每个业务页补齐加载、空数据、权限不足、处理失败、重试、取消、分页、导出与删除确认；上传需要格式/大小限制和解析进度；查重需要差异对比、主档选择、撤销；工作流需要版本、校验、试运行、发布与回滚；考试需要截止时间、自动保存与重复提交规则。
