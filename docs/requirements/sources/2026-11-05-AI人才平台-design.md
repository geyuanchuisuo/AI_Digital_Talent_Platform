# AI数字化人才平台：第一版设计方案

日期：2026-11-05。状态：用户已确认（2026-11-05）；本文件是brainstorming设计产物，不是实施计划。原始PRD、design、test和两份原型保持不变。

## 1. 目标与依据

为老师布置的项目实现可在本人Windows电脑运行演示的人才平台，基础功能以两份原型与PRD业务要求为依据，使用真实后端与持久化数据。之后能迁移至服务器，通过网址供老师和同学访问。

已由用户明确：选择保留其余技术方向、分阶段实施的路线A；老师明确不需要PostgreSQL、Dify、Vanna.ai；首期调用在线模型API并保留本地模型切换能力；第一版本机演示，后续可能部署服务器；没有明确截止时间和额外验收标准。

当前只有资料包和pre_work分析，没有前后端源码。暂按从零开发设计；若随后取得ai_talent仓库，先盘点复用与冲突，不直接覆盖。原文中的历史“已落地”不作为完成证据。pre_work/01–06是早期资料审查，其中全栈含PgSQL/Dify/Vanna的建议被本次用户确认的排除项覆盖。

成功标准：用户能完成上传简历、查看与修订档案、岗位匹配、测评、培训、知识问答、问数导出、工作流运行和权限管理，并能从真实记录看见结果、状态与失败原因。系统重启后业务数据仍在，关键操作可追踪。第一版不以复刻截图里的固定人数/准确率作为完成标准。

## 2. 路线选择与边界

讨论过的方案：A保留指定技术方向分阶段交付，环境较多但贴近项目材料；B先大量精简组件以完成业务，起步较轻但存在回填与验收风险。用户选择A，并根据老师要求去掉三个组件。模型方式讨论过在线API与本地推理，用户选择在线优先。部署采用本机优先、容器化配置可迁移的方式。

以下技术提案已随全文获得用户确认：

- 一个业务后端按模块分层，配独立异步Worker；首期不拆成多个拥有独立数据库的微服务。这样降低本机运维复杂度；与PRD严格微服务表述的差异明确保留，不能宣称已实现微服务。以后有独立扩缩容需求再拆AI执行或报表服务。
- 保留MySQL、Milvus、Redis、LangChain、LangGraph及SQLAlchemy；不引入三个已排除组件。Neo4j不放第一版，它属于额外增强，知识溯源先用文档、页码与切片。
- 自然语言问数采用“模型识别指标与筛选条件→受控ORM查询→图表与解释”，不执行模型生成的任意SQL。这样保留问数体验并遵守业务查询的ORM约束；超出支持指标的问题清楚提示暂不支持。
- 第一版防挂机使用服务端有效学时、可见性/播放事件和交互检查，不进行人脸识别；AI面试先支持文字多轮，不接音视频实时通话。JD/IM等外部渠道先不真实投递，页面不伪装发送成功。
- 本机部署、在线推理属于混合部署，不能称为100%私有化或离线。2000人并发、全年可用率、国产化、解析99%等指标保留为后续独立验证目标，不作为第一版本机演示的已达成承诺。

## 3. 第一版范围与角色

### 3.1 功能范围

| 模块 | 第一版必须可操作的内容 | 边界 |
|---|---|---|
| 智能工作台 | 人才/任务/匹配/问答统计、Agent运行、缺口与失败入口 | 全部来自真实记录，未运行的指标显示无数据 |
| 简历筛选 | 多文件上传、PDF/DOCX/图片扫描件解析、任务进度、失败重试、条件筛选、重复检测 | 老式.doc明确提示转换为.docx；不承诺任意格式无损解析 |
| 人才档案 | 主档、经历技能标签、来源证据、人工修订、完整度、语义搜索、单/批档案问答、合并确认 | 不要求每个人凑满100标签；合并可撤销，不只按向量相似度自动合并 |
| 测评研判 | 题库题目、岗位出卷、受控自适应选题、作答提交、评分、能力雷达、错题与复习、文字面试记录 | 主观分可人工复核；不声称经过心理测量验证的能力评估 |
| 岗位匹配 | 项目需求、岗位规则与版本、硬条件、0–100分、分项证据、排序、缺口与人才储备推荐 | 硬条件与软分开，推荐不代表录用；人确认状态变更 |
| 培训成长 | 缺口诊断、AI生成计划、课程附件/内容、报名学习、有效进度、交互检查、结业测评、成长历史 | 支持文本/附件和可上传视频；不依赖人脸或第三方直播平台 |
| 智能问数 | 招聘完成率、岗位缺口、匹配通过率、测评分布、有效学习时长等受控指标，图表、解释、Word/PDF导出 | 不承诺对任意未知表自由查询；返回指标定义和数据时间 |
| RAG知识库 | 分类、上传、解析、切片、向量化、版本/删除、按授权问答、来源跳转、无据拒答 | 文档/页码/切片可溯源，图谱不是前置条件 |
| Agent编排 | 五类Agent配置、Prompt/模型关联、简化节点拖拽连线、流程校验/版本/试运行/发布、运行日志、手动/定时触发与重试 | 内置有限节点类型，不是任意代码执行平台；数字员工为任务归属与调度视图 |
| 系统管理 | 登录、用户部门角色菜单、操作权限、行范围、字段脱敏、导出授权、操作与AI日志、模型配置 | 单组织多部门；不做SaaS多租户 |
| 技术现状 | 展示实际依赖健康、版本、尚未验证的能力 | 管理员可见，不把原型数字复制成已达标 |

原型中每个有意义的按钮需进入真实操作、详情或明确的暂不支持提示，不能用无效果点击充数。第一版不含招聘网站直连、短信/IM发送、真实人脸校验、实时语音视频、知识图谱和高可用集群；若这些成为老师明确要求，作为范围变更评估。

### 3.2 用户与数据范围

- 员工：本人档案、学习测评、已授权公共知识。
- HR：被授权部门/项目的岗位、候选人、匹配、面试与培训；联系方式按权限显示。
- 业务负责人：本人管理的部门/项目需求、缺口、匹配和学习统计。
- 管理层：授权组织范围内统计和问数；明细及敏感字段另行授权。
- 管理员：组织、账号、权限、模型与工作流管理；业务明细访问有明确权限，不由管理身份隐式绕过。
- 候选人：第一版由HR创建候选人和测评安排，使用限时、限定任务的访问令牌完成答题/文字面试，无公开注册系统。

本地提供虚构演示账号与样例；账号密码通过初始化配置设置，不在仓库固定生产密码。多角色切换用于真实登录后的演示，不用前端“选择角色”冒充授权。

## 4. 用户路径与界面

沿用原型左侧导航、顶部搜索、主内容区、卡片/表格/图表的布局与蓝色视觉方向，使用组件库实现可访问交互。PC浏览器是第一版主要端，窄屏可阅读和完成核心操作，不制作独立手机App。原型风格已有依据，不额外重做品牌。

页面结构示意：

```text
左侧导航       顶栏：搜索 / 当前账号
智能工作台     标题 + 当前筛选 + 主操作
简历筛选       实时统计卡
人才档案       筛选栏 / 列表 / 分页
测评 / 匹配    详情或编辑抽屉 → 来源、任务进度、修订历史
培训 / 问数    失败可重试，空数据有下一步入口
知识库 / Agent
系统 / 技术现状
```

三个演示主流程：

1. HR建岗位→上传真实样例→任务解析→复核字段→人才档案→匹配分与证据→确认候选状态→工作台统计更新。
2. 配题出卷→候选人限时作答→评分/人工复核→能力缺口→培训计划→学习检查→复测→成长轨迹。
3. 导入制度→索引完成→员工问答带引用→越权/无据拒答；管理层问统计→授权图表→下载同一数据快照的报告。

所有列表/详情/表单补齐加载、空数据、失败、权限不足、校验、分页和状态提示。AI处理中显示真实阶段而非虚构精确百分比；不能推算时用阶段与耗时。

## 5. 技术架构与部署

### 5.1 组件职责

| 组件 | 职责 |
|---|---|
| Next.js + React + TypeScript | 页面、路由、表单、角色门户、任务与聊天界面 |
| Ant Design + ECharts（技术提案） | 统一后台表格表单、图表与雷达；避免维护多套组件库 |
| FastAPI + Pydantic | API、请求校验、认证授权、统一错误、进度/流式事件 |
| SQLAlchemy + Alembic + MySQL | 业务持久化、事务、版本迁移及受控统计查询 |
| Redis + Celery Worker/Beat | 缓存、限流、撤销记录、长任务、定时调度 |
| Milvus Standalone | 人才/岗位/知识向量索引，实际使用而非只安装 |
| LangChain | 模型适配、结构化输出、检索工具与提示链 |
| LangGraph | 五类Agent协作、流程节点状态、人工暂停与恢复 |
| 对象存储适配器 + MinIO兼容服务 | 简历/知识附件/课程/报告，私有桶与鉴权下载 |
| 文档适配器 | PyPDF文本、DOCX提取、OpenCV预处理+CPU OCR、必要时在线视觉模型 |
| 在线模型网关 | 对话/结构化抽取、Embedding，支持分别配置服务商和模型 |

MinerU保留适配点，第一版不强制在本机运行完整GPU解析链路；先以文本解析+CPU OCR满足普通样例，复杂版式可配置在线视觉能力。是否进一步接入MinerU由样例效果决定。模型供应商、模型名称和依赖具体版本在实施计划前置验证中锁定，不凭历史文档版本直接安装。

### 5.2 运行形态

```text
浏览器
  → 前端 / 同源API入口
    → FastAPI业务模块
      → MySQL / Redis / 对象存储
      → 异步Worker → 解析、索引、匹配、Agent、报告
      → Milvus
      → 模型网关 → 在线API
```

开发可用本机Node/Python配容器数据库，中间件以Docker Compose统一管理；标准演示环境提供容器启动配置、初始化与健康检查。第一版低并发运行，解析/索引限制Worker并发，避免本机资源争抢。不用SQLite或假向量库替代已保留的组件。

未来服务器：保持同一代码与容器定义，通过环境变量调整域名、数据库/存储地址、密钥、代理和资源配额；增加HTTPS反向代理、备份任务和必要监控。浏览器只访问前端与受控API，数据库、Redis、Milvus、对象存储不直接公开。文件访问不使用Windows绝对路径或写死localhost链接。

检测到Python 3.13.5、Node v24.21.0和Docker客户端29.8.1。Docker守护进程当前未连接，配置目录读取有访问限制；这不是已验证的容器运行环境。系统硬件信息读取被拒，内存/显卡未知；由于采用在线推理，不据此假定有GPU。项目当前不是Git仓库。此次只读取环境，未安装依赖、启动Docker、创建仓库或修改系统配置。

实施计划须安排环境兼容验证和Docker启动/资源检查；若Docker或资源不可用，需要先解决或确认远程中间件方案，不静默删组件。Python/Node是否调整使用项目独立环境，不覆盖全局安装。

## 6. 数据与接口契约

### 6.1 数据主体

以person为人才主档，连接candidate/employee身份、简历文件与解析结果、标签/能力快照、测评答卷、课程学习与匹配结果。姓名不是关联主键。岗位和条件、题目与试卷、Prompt与流程均有版本。匹配保留人才/岗位/规则版本和分项证据；报告保留指标参数和数据快照。

知识文档包含版本、分类、可见范围、原文件；切片包含页码/章节、文本和索引版本。向量附带文档ID与授权过滤信息，MySQL保存索引状态，可重建。工作流定义、发布版本、运行、节点attempt、人工操作及检查点均持久化。

学习需记录报名、学习会话、服务端有效时间、检查结果、课程完成和复测。权限包含角色、菜单/操作、部门/项目资源范围、字段读/导出策略；接口和AI工具共享同一策略。

### 6.2 API原则

沿用/api前缀，实施时生成OpenAPI而不是把原接口表推导项当成已存在。普通响应统一code/message/data并带trace_id；列表分页有上限。错误使用准确HTTP状态，内部错误详情不返回给前端。

上传、解析、向量化、匹配批次、培训生成和报告返回持久化任务ID。任务状态queued/running/waiting_review/succeeded/failed/cancelled，解析子阶段与索引状态分别记录。进度通过SSE或任务轮询获取，断线不丢任务；可取消/重试的操作明确标记。

上传采用受限格式、大小与批量数量（初始建议单文件20MB、每批20个，部署可配置）；校验扩展名和内容，不允许用户指定服务端任意目录。文件下载鉴权并设置短期链接或代理响应。

### 6.3 一致性

MySQL为业务事实源，Redis不作为唯一持久化位置。数据库事务创建任务/outbox，Worker原子认领带租约，按业务对象+版本幂等处理，失败有限重试；重试不重复建档、计分或累加学时。数据库提交与文件/向量操作分别记录状态并补偿、对账，不假设跨存储事务。

删除/权限变更联动索引、文件授权与缓存失效。合并保留来源字段和撤销记录，不仅物理删除副档案。试卷冻结题目快照，提交按任务及考生幂等，截止与用时由服务端判定。

## 7. AI能力的具体约束

### 7.1 解析、匹配与查重

文本PDF/DOCX先本地提取，图片/扫描件OCR；抽取文本经网关做schema化字段解析，校验类型、范围、证据和置信度。没有读取到的字段留空，允许人工修订。损坏/加密文件给出失败原因。老式Word转换不调用任意系统命令或自动执行宏。

同文件用hash去重，同人识别用规范化联系方式等证据；语义相似候选只作待确认。岗位匹配先硬条件再软分，权重归一，分数与原因可回溯至证据；硬条件缺失与明确不满足区分，未知不凭空补齐。

### 7.2 测评和培训

智能出卷按岗位能力、题型、难度、题量/总分配置。自适应首版为规则式有界选题：题目经标注难度与能力维度，按前面已评分题目的表现调整下一题难度；保存逐题选择依据，遵守覆盖率、无重复和最大题数，不把随机出卷称作自适应。主观题异步评分，不阻塞选择后续客观题；人工复核后生成正式结论。

培训方案从授权课程中推荐，不能生成不存在的课程链接；允许HR编辑确认。学习有效时间由服务端检查会话事件、合理上限和重复事件，视频快进不直接等于完成；文本/附件阅读配简单交互检查。完成条件写入课程配置，计划完成后触发复测并生成新的能力快照，不覆盖历史。

### 7.3 RAG、问数和模型配置

检索前限制授权资源，重排后再校验，模型只收到允许的切片。回答引用到文档版本/章节/页码（来源不存在页码时用段落），无证据拒答。档案批量问答限定授权人才、批量上限与上下文预算。

问数首批指标：按时间/部门/岗位的需求数、已录用数/招聘完成率、岗位缺口、匹配通过率、考试均分/通过率、学习完成率/人均有效学时、解析任务和AI调用统计。指标字典明确分子分母、去重、时间字段与零分母处理。模型只输出合法指标ID和过滤参数，后端验证并用ORM计算；结果表是解释和图表的唯一数字来源。系统说明统计相关性不等于因果，不自动执行招聘或管理建议。

对话模型与Embedding分别配置，不能假定一个聊天API也提供向量。视觉模型/重排是可选能力；没有视觉时仍须能用本地OCR处理基本扫描件，重排可先采用确定性融合。保存Embedding模型ID、版本与维度，切换模型需要重建对应集合，不能在旧索引中混用向量。

模型密钥只在后端使用；配置页显示掩码，数据库保存密钥引用或加密值，解密主密钥由环境提供。调用设超时、有限重试、并发/输出长度限制与用量统计；失败可见并可重试，不返回预设成功结果。未配置模型时系统可登录与管理数据，但AI操作明确提示未配置；真实AI验收必须有可用密钥。具体服务商与费用额度属于后续配置，不阻止架构定稿。

### 7.4 简化工作流编辑器

支持固定节点：触发、解析、检索/向量化、五类Agent、条件、人工确认、报告/结束。管理员拖拽连线并配置表单；后端校验引用、入口/出口、条件类型、权限和可达性。第一版不开放任意脚本、任意HTTP地址或无限循环；需要循环的能力使用有限次数的内置节点。发布保存不可变版本，运行绑定版本并记录每步输入输出摘要。

五类Agent分别是档案解析、测评分析、岗位匹配、培训赋能、数据决策，复用业务服务而不绕过权限。LangGraph主导业务状态，Celery执行投递；定时器只发起运行，不另造冲突状态机。人工节点可暂停恢复，重试按节点幂等，取消为尽力取消并保留已完成记录。内置Agent的基础流程由用户操作发起，高影响变更需要人工确认。

## 8. 数据、安全与验收

第一版使用虚构/脱敏样例，上传在线模型前剔除任务不必要的个人字段；API外发边界在文档与配置中说明。日志不记录密钥或完整敏感简历；知识文档视作不可信内容，不允许其指令修改工具权限。密码哈希、限流、令牌失效、会话授权、下载/导出范围检查统一实现。第一版浏览器使用HttpOnly会话凭据，同源部署、状态变更校验来源与CSRF令牌；上线HTTPS时启用Secure并收紧允许来源。

原test/seed_data.sql不直接装入新库，它有占位密码、推断列和固定向量ID；按新模型用ORM生成可重复演示数据与真实附件，向量必须实际生成。评测器与标注新建，不改原测试。

第一版验收：

- 上述三个演示主流程以真实数据跑通，浏览器刷新/服务重启后结果保留。
- 所有保留组件有实际业务调用证据；无PgSQL/Dify/Vanna依赖。
- 员工/HR/负责人/管理层不能通过列表、详情、导出、文件、检索和问数越权，字段脱敏一致。
- 覆盖PDF/DOCX/扫描图片、损坏文件、重复文件/人、模型超时、Worker中断、重复交卷、知识无据和SSE断线等场景。
- Word/PDF报告可实际打开，数据与图表可读且属于提问者权限范围。
- 准确率报告给出样本、指标定义、版本和失败案例；不把小样本全对等同广泛达到99%。原型里的统计值与时延不作真实测试证据。
- 提供本机启动/停止/初始化/备份恢复手册、模型配置说明、演示步骤，以及可迁移服务器的部署说明。

单元测试可以隔离外部依赖，但集成/端到端验收必须用真实数据库、索引和可用模型API。没有密钥或Docker环境时明确报告被阻塞的验证，不能拿mock通过率替代。
