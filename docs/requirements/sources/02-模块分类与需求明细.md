# 模块分类与需求明细

所有R编号为本次计划的新需求编号。P0=身份与主闭环，P1=第一版仍需完成但可后做；“后续”是已确认暂不做。PRD章节和原型页面是需求来源，不是实现证据。

## 1. 分类与流程

业务域：人才档案、招聘匹配、能力测评、培训成长、数据决策。公共能力域：身份权限、文件任务、模型与RAG、Agent工作流。展示域：工作台、系统配置、技术现状。

统一人才person_id串起“需求岗位→简历档案→匹配→考核面试→录用/入职→培训复测→画像成长”，制度知识与Agent作为共享能力。每项需求都有页面、服务、数据和可观察结果，不能只实现静态菜单。

## 3. 页面与操作补齐

登录→工作台。简历页提供上传、队列、失败详情；人才页提供详情、字段编辑、证据、差异合并、问答；岗位页提供项目/需求/条件配置和匹配列表。测评页下有题库、出卷、安排、答卷复核、错题复习、文字面试；培训页有课程、方案、我的学习、成长。问数页有历史、指标解释、图表、报告任务；知识页有分类文档、版本/ACL、索引任务、问答/来源；Agent页有列表、画布、发布、运行、人工任务、调度；系统页有身份组织、权限、模型和日志。技术现状仅管理员访问。

每个有意义按钮都列入浏览器测试的可操作清单；暂不支持的外部渠道显示清楚，不伪造成功通知。窄屏允许横向表格或卡片，但表单和关键按钮不被遮挡。

## 4. 确认后的范围差异

不做PgSQL/Dify/Vanna、独立移动App、完整微服务集群、招聘网站/短信/IM真实发送、人脸校验、实时音视频、知识图谱和本地推理部署。性能/准确率目标如2000并发、99%解析、95%RAG不删除，但首版只出真实基线，不承诺未经验证达标。
