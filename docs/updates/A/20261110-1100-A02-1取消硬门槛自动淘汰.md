## 四、跨域边界：A02-2 未做，已发请求

V2.6 §5 还要求「**语义相似度不等于业务匹配分，不强制加入 0.7/0.3 或 40/30/15/15 的公式**」。本轮**未改**公式，原因是客观跨域依赖，不是取舍：

- `evaluate()` 调 `chat_json(..., MatchScoreOutput, prompt_name="match")`；运行时校验走 A 的 Pydantic，但 `prompt_name="match"` 会把 **D 归属**的 `PROMPT_C_SCHEMA`（`backend/app/core/prompts/schemas.py:152`，`additionalProperties: False`）拼进 system prompt。若 A 单方面给 `MatchScoreOutput` 加必填 `overall_score`，**真实 LLM 按旧 schema 不会输出该字段 → Pydantic 校验失败 → 全批评分失败**；单元测试用假件返回 Pydantic 对象反而发现不了。
- D 的 `test_prompts.py::test_prompt_c_schema_contract` 还断言属性清单与两个 prompt 字面串。

故 A 发 [REQ：A02-2 Prompt C 综合分输出契约](../../requests/A/20261110-D-A02-2-PromptC综合分契约.md)，请 D 在其归属内加 `overall_score` 并同步断言；A 承诺 D 响应后移除 `0.7/0.3` 向量合成与 `40/30/15/15` 加权，改以模型综合分为唯一业务分（`dimension_scores` 降为分项依据、`vector_similarity` 降为参考留痕）。**A 不越界代改，也不替 D 判定断言去留。**
