## 3. 演练中发现并修复的两个真实缺陷

1. `npm exec next dev -p <port>` 的 `-p` 被 npm 吞掉 → Next 报 `Invalid project directory ...\frontend\3100`，自定义前端端口起不来。改为用 `node` 直接执行 `node_modules/next/dist/bin/next dev -p <port>`（回退分支补 `--`）。详见 [231000 记录](20261106-231000-端到端演练发现的前端启动缺陷修复.md)。
2. Windows `Popen(shell=True)` 只杀掉 `cmd.exe`，uvicorn 变孤儿进程继续监听。改为 `shell=False`。同上记录。

另在演练前加固了端口/容器名隔离能力（[225800 记录](20261106-225800-交付环境端口隔离加固.md)），修掉「客户机 3306/19530 被别的项目占用时会跳过容器并连进别人的库」的隐患。
