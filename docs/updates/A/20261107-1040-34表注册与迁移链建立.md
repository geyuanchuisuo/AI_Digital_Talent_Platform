## 过程发现并处置的三个集成问题

1. **循环导入（真实，已修）**：C 的 `registry.py` 捆绑导出模型+路由，router→`api.deps`→`app.models` 链与「deps 先于 models 加载」的入口（`tests/C/c_harness.py`）成环，`pytest tests/C` 收集即 ImportError。处置：`models/__init__.py` 改为直接 import 三域 `models.py`（模型注册不需要 router），`main.py` 仍用 `ALL_ROUTERS`；建议 C 拆分注册表（已写入 A→C 请求）。
2. **C 表 `updated_at` 无 `ON UPDATE CURRENT_TIMESTAMP`（差异，待 C 收敛）**：C 的 `CTimestampMixin` 应用层维护时间戳，与公共 `UpdatedAtMixin`（MySQL 维护）语义不同；结构测试对 C 域按现状断言并登记，已发请求请 C 收敛到公共 mixin。
3. **Windows GBK（环境坑，已修）**：alembic 1.20.1 以 `encoding="locale"` 读 `alembic.ini`（不可配置），中文/非 ASCII 字符直接炸启动；已把 ini 改为纯 ASCII 并加 `source_encoding = utf-8`（迁移脚本文件不受影响）。
