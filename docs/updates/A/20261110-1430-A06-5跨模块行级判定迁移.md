## 一、背景与真实漏洞

A06-1 已把 `workflows` / `inventory` / `reports` 的管理侧守卫统一到
`scope.account_is_management`（聚合 `sys_user_roles`），但 **C 归属的两个模块仍用旧字符串判断**：

| 位置 | 旧实现 | 问题 |
|---|---|---|
| `modules/assessments/service.py:66` | `ADMIN_ROLES = {"admin","hr"}` + `is_admin(user) = user.role in ADMIN_ROLES` | `system_admin` 被**误拒**；非标准 `"admin"` 被**误放行** |
| `modules/interviews/ai_router.py:26` | 同上，8 处 `user.role (not) in ADMIN_ROLES` | 同上；且 `is_admin` 被 `interviews/service.py` 与 **`training/service.py`（3 处）共享** |

这是台账里 A06 整行的最后一项（「assessments/interviews 内联 `ADMIN_ROLES` 行级判定迁移」）。

## 二、交付内容

### 修改 `backend/app/modules/assessments/service.py`（C 归属）
- `is_admin(user)` 改为开 `SessionLocal` 调 `scope.account_is_management(db, user)`：
  system_admin / hr → True；dept_manager / trainer / employee / candidate / personal → False。
  **函数签名不变**（`interviews/service.py`、`training/service.py` 的复用点零改动）。
- `ADMIN_ROLES` 常量保留（兼容外部 import），加注释标明**不再用于判定**。
- `require_admin(user)` 的**错误消息保持** `"仅管理员可执行该操作"`，仅内部判定换源。

### 修改 `backend/app/modules/interviews/ai_router.py`（C 归属）
- 顶部引入 `account_is_management`，新增 `_is_management(db, user)`；
  **7 个端点各算一次** `is_admin = _is_management(db, user)`，替换全部 8 处内联字符串判断
  （`create_session` / `list_sessions` / `start_session` / `add_question` / `list_questions`
  / `submit_answer` / `finish_session`）。
- **业务逻辑零改动**：错误消息、`answer_text` 可见性规则（管理侧或已非 pending 才可见）、
  「本人 or 管理」行级语义、`retry_judge` 全部保持原样；`git diff` 逐行核对仅权限判定变化。

### 新增 `backend/tests/test_a06_c_module_gates.py`（UNASSIGNED → 走 `collab.integration`）
12 例：常量兼容、`is_admin` 四种角色、非标准 `"admin"` 不再被放行、
`require_admin` 403 且消息不变 / system_admin 放行、HTTP `POST /api/ai-interviews/sessions`
（system_admin 200【旧代码 403】、legacy hr 200、dept_manager 403、personal 403、未登录 401）、
`GET /sessions` 非管理侧行级过滤。临时账号 / 面试 session / event 在 teardown 直连清理。

## 三、设计取舍与跨归属治理

- **只换判定源，不改业务规则**：`retry_judge` 无权限判断，保持原样（曾误引入海象运算符，已还原）；
  所有 403 文案不变，避免影响前端既有提示。
- **`is_admin` 查库的性能**：每次调用开一次 `SessionLocal`（与 A06-1 的 `require_management_guard`
  同形）；`ai_router` 每端点只算一次，不在列表推导内重复查库。
- **跨归属透明登记**：两个 `service.py` / `ai_router.py` 归 **C**，新 test 为 UNASSIGNED。
  按 `DEC-20261107-GITFLOW-RELAX` 使用本地 `collab.integration=1` 整合模式（check_scope 报
  cross-owner authorized 警告、无错误）。**未改 C 的业务规则，仅把权限判定切到 A 的 RBAC 口径**；
  不改 `ownership.json`、不替 C 决定行为。
