## 为什么要改

准备做 T-A71 真实演练时发现：本机 3306 是旧 `main` 的 `mysqld`、19530/9091 是既有 `aitalent-milvus-*` 容器；而 `bootstrap.py` 把 Milvus 端口写死 19530、compose 把端口和容器名全部写死。按原逻辑演练会「检测到端口已占用 → 跳过容器创建 → `init_db.py` 连进同名 `ai_talent` 库」，**触碰用户现有数据**。这也是客户机 3306/19530 被别的项目占用时的真实交付隐患。

## 具体改动

1. compose 端口改为 `${MYSQL_PORT:-3306}:3306`、`${MILVUS_PORT:-19530}:19530`、`${MILVUS_METRICS_PORT:-9091}:9091`。
2. compose 容器名改为 `${CONTAINER_PREFIX:-aitalent}-*`。**不能用 `COMPOSE_PROJECT_NAME` 插值**：Compose 会把该变量自动设为项目名（目录名 `milvus`），导致默认容器名从 `aitalent-mysql` 变成 `milvus-mysql`，属于破坏性变更；已实测并修正。
3. `bootstrap.py`：新增 `derived_runtime()` 由 `MILVUS_PORT` 派生 `MILVUS_URI`（客户显式指定 URI 时优先）；`ensure_infra()` 从 `MILVUS_PORT`/`MILVUS_URI` 解析端口，metrics 端口随 Milvus 端口联动（19530→9091），并向 compose 注入端口、`COMPOSE_PROJECT_NAME`、`CONTAINER_PREFIX`。未指定项目名时**不注入**，保持原有项目名与卷名不变。
4. 根 `.env.example` 增加「端口冲突 / 多套环境并存」可选覆盖示例（全部注释，默认不生效）。
