# A06-4 系统管理域 CRUD 路由（接 require_roles 门禁）

- 模块：A（系统管理域）
- 执行表：A06 第 4 子单元（P0）
- 提交（待推送后填真实号）：本地 `feature/A/continuation` ahead 1（基于 `2eca164`）
- 关联：A06-1（角色/职责门禁，2026-11-10 11:40 已发布 `2eca164`）

## 一、背景

A06-1 已在 `core/auth/scope.py` 落地基于 `sys_user_roles` 聚合的角色判定（`get_role_codes` /
`account_is_management`）与 `api/deps.py` 的 `require_roles` / `ManagementDep`。但系统管理域
**六张 sys_* 表（departments/roles/user_roles/role_permissions/menus/operation_logs）此前无 router**，
`main.py` 未注册任何 `/api/system/*` 端点——管理侧无法通过 API 操作角色/菜单/部门，A06-1 的
门禁也无真实 API 边界可验证。

本单元补齐系统管理域 CRUD 路由，并整域接 `require_roles("system_admin")`，使 A06-1 的角色门禁
在真实 HTTP 边界端到端生效。

## 二、交付内容

### 新增 `app/modules/system/schemas.py`
入参 Pydantic 模型（Department/Role/Menu 的 Create/Update、UserRoleBind、PermissionItem/
RolePermissionSet），仅承载入参校验；出参走 `_row_to_dict` 直接序列化 ORM 列。

### 新增 `app/modules/system/router.py`（`prefix=/api/system`，整域依赖 `require_roles("system_admin")`）
- `GET/POST /departments`、`GET/PUT/DELETE /departments/{id}`：部门树 CRUD（重名 409）。
- `GET/POST /roles`、`GET/PUT/DELETE /roles/{id}`：角色 CRUD；内置 `system_admin` 角色禁止删除（409）；
  `data_scope` 仅允许 all/dept/self（400）。
- `GET /roles/{id}/users`、`POST/DELETE /roles/{id}/users/{user_id}`：账号↔角色绑定/解绑
  （账号不存在 404、重复绑定 409、绑定不存在 404）。
- `GET/PUT /roles/{id}/permissions`：角色权限矩阵全量替换（action 白名单、data_scope 校验）。
- `GET/POST /menus`、`GET/PUT/DELETE /menus/{id}`：菜单树 CRUD（`menu_type` 三值校验）。
- `GET /operation-logs`：操作审计只读（按 module/action 过滤，倒序分页）。
- 高影响写操作经 `audit_service.record_operation` 落 `sys_operation_logs`（F09）。
- 统一 `ok()` / `paginated()` 返回；404/409/400 走 `BizError` 归一错误体。

### 修改 `app/main.py`
新增 `app.include_router(system_router)`，`include_router` 计数 **17 → 18**。

### 修复 `app/api/deps.py`（A06-1 遗留 bug）
`require_roles` / `ManagementDep` 依赖内部 `raise BizError(403, DENY_MESSAGE)` 引用了未导入的
`DENY_MESSAGE`，此前仅测了 service 层、未触发 FastAPI 依赖而漏网；本次补 `from app.core.auth.scope
import DENY_MESSAGE`。**属 A 归属文件（`deps.py` owner=A），本单元无跨归属改动**。

## 三、设计取舍

- **门禁用 `require_roles("system_admin")` 而非 `ManagementDep`**：系统管理（角色/菜单/部门配置）
  仅对系统管理员开放；`hr` 虽属管理侧（可看全量人才），但不应碰系统配置，避免权限膨胀。
- **不触及 `sys_settings`**：`SysSetting` 定义在共享的 `app/models/user.py`（非 A 模块 `system/models.py`），
  不在本单元范围，留待后续。
- 部门行级（A06-2）、字段级（A06-3）仍待办：`User` 无 `department_id` 列，本单元未引入。
