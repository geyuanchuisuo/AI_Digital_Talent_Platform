## 一、偏差与需求依据

| 项 | 内容 |
|---|---|
| 旧实现 | `get_account_scope(user)` 纯函数仅读 `users.role`（`hr`→可看全量、`personal`→本人、其余 deny-by-default）；管理侧/导出/任务入口的守卫分散且口径不一致：`workflows` 用 `can_view_all_persons`、`inventory` 用 `ADMIN_ROLES={"admin","hr"}` 字符串、`reports` 导出用 `can_view_all_persons`。`sys_user_roles` 多职责表已建但**从未被授权判定消费** |
| 需求口径 | 执行表 A06「补部门经理/管理层/培训职责权限，逐入口/任务/导出拒绝越权」；V2.6 §3.1 一人多职责由 `sys_user_roles` 承载 |
| 真实漏洞 | `users.role` 现值只有 `hr`/`personal`；一个 `system_admin` 账号（role=`system_admin`）会被 `can_view_all_persons` 与 `ADMIN_ROLES` 双重判为「非管理侧」→ **系统管理员反而无法访问管理侧入口**；`dept_manager`/`trainer` 等职责在入口层完全没有被识别与拒绝 |
| 裁决依据 | A 设计方案 M1 架构探针；`tasks/A.md`；Master 执行表 A06「部分基础实现 → 补职责权限、逐入口拒绝越权」 |

## 二、本单元交付（全部在 A 归属内）

| 文件 | 改动 |
|---|---|
| `backend/app/core/auth/scope.py` | 新增 `ROLE_CODES`（六类角色）与 `MANAGEMENT_ROLES=("system_admin","hr")`；`AccountScope` 加 additive 字段 `role_codes`（默认 `()`，既有构造向后兼容）；新增 `get_role_codes(db,user_id)`（sys_user_roles 聚合优先、无记录回退 users.role、未知→personal deny-by-default）、`account_is_management(db,user)`（角色集与 MANAGEMENT_ROLES 有交集）、`require_management_guard(user)`（无 db 时内部开 SessionLocal 计算）。`get_account_scope` **保持纯函数不变**，数据范围消费方语义不受影响 |
| `backend/app/api/deps.py` | 新增 `require_roles(*codes)` 依赖工厂（账号生效角色与给定角色集无交集→403，deny-by-default 不泄露对象存在性）与 `ManagementDep` / `_require_management_dep`（非 system_admin/hr→403） |
| `backend/app/modules/workflows/service.py` | `_require_management(user)` 由 `can_view_all_persons` 改为 `require_management_guard(user)`（统一角色口径，router 与生命周期函数共用，调用点不变） |
| `backend/app/modules/inventory/service.py` | `_require_admin(user)` 由 `user.role in ADMIN_ROLES` 改为 `require_management_guard(user)`；`ADMIN_ROLES` 常量保留注释，仅用于该行内「本人 or 管理」行级判定（不在本单元边界） |
| `backend/app/modules/reports/service.py` | `_check_export_permission(user,snap)` 由 `can_view_all_persons` 改为 `account_is_management(db,user)`（管理侧 = system_admin/hr）；快照创建者仍放行；dept_manager/trainer/employee/candidate/personal 即使误带管理侧数据范围也无法导出他人快照 |
| `backend/tests/test_a06_rbac_gates.py` | 新建：10 例——角色聚合（legacy hr/personal 回退、未知→personal、sys_user_roles 聚合覆盖 users.role、管理侧真值矩阵、非管理侧守卫抛 403）+ 入口端到端（数字员工任务列表拒绝 dept_manager / 放行 hr；盘点汇总导出拒绝 dept_manager） |

**明确不做（留后续，避免越界与破坏数据范围消费方）**：
- 不改 `get_account_scope` 的 `can_view_all_persons` 语义 → 现有 talents/analytics/notifications 等数据范围消费方行为不变；
- 不做**部门行级过滤**（需 `users.department_id` 列 + 查询改造，当前无该 FK）——故 A06 的「行」级仍依赖既有 `can_view_all_persons`/本人判定，本单元只补齐**职责（角色）/动作**层门禁与越权拒绝；
- 不做**字段级**权限（设计上需字段白名单 + 序列化裁剪）；
- 不迁移 `assessments`/`interviews` 内联的 `ADMIN_ROLES` 行级判定（属行级「本人 or 管理」，非本单元边界），仅记录为待办。
