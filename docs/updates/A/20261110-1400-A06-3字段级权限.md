# A06-3 字段级权限白名单 + 序列化裁剪（A06 P0 收口子单元）

- 模块：A（系统管理域）
- 执行表：A06 第 3 子单元（P0）
- 提交（待推送后填真实号）：本地 `feature/A/continuation` ahead 1（基于 `6ee1ebe`）
- 关联：A06-1（角色门禁 `2eca164`）、A06-2（部门行级过滤 `6ee1ebe`）、A06-4（系统管理域 CRUD 路由 `78d946e`）

## 一、背景

A06-2 已补齐部门**行级**过滤，但账号花名册的**字段**对所有能进入的角色完全一致（只是硬编码剔除
`password_hash`）。V2.6 §3 / design §8.3 要求「组织·角色·行·字段」四级权限，其中字段级尚未落地：
dept_manager 不应看到 `person_id` / `last_login_at` / 时间戳等审计与绑定类字段。

本单元把字段级权限做成**服务端策略 + 可复用序列化裁剪**，叠加在 A06-2 的行级过滤之上，
并作为下游（B/C/D）字段裁剪的统一入口。

## 二、交付内容

### 修改 `backend/app/core/auth/scope.py`（A06-3 机制层）
- `SENSITIVE_FIELDS`（硬底线）：`password_hash` / `password` / `token` / `secret` / `api_key`，
  **任何角色、任何白名单都不可覆盖**——即便策略误写进白名单也会被 `filter_columns` 剔除。
- `ACCOUNT_BASE_FIELDS`：`id/username/display_name/role/department_id/is_active`（dept_manager 最小集）。
- `FIELD_POLICIES`：资源 → 角色 code → 可见字段白名单；`None` 表示「全部非敏感列」。
  当前 `accounts` 策略：`system_admin → None`、`dept_manager → ACCOUNT_BASE_FIELDS`。
- `resolve_visible_fields(db, user, resource)`：基于 A06-1 的 `get_role_codes` 聚合角色；
  **deny-by-default**——未知资源 / 无任何匹配角色返回 `()`（一个字段都不给）。
- `filter_columns(columns, visible)` / `serialize_fields(obj, visible)`：裁剪 + 脱敏的纯函数/序列化入口。

> 策略当前为服务端常量：V2.6 §8.3 的 `sys_role_permissions` 只有 menu×action×data_scope，
> **无字段维度**，本单元不擅自改表结构；后续可迁到配置表，调用方形状不变。

### 修改 `backend/app/modules/system/account_router.py`
`GET /api/system/accounts` 与 `PUT /{id}/department` 的出参统一走
`serialize_fields(obj, resolve_visible_fields(db, current_user, "accounts"))`，
替换 A06-2 的硬编码 `_row_to_dict`。system_admin 看全部非敏感列；dept_manager 仅基础字段。
**字段裁剪与部门行级过滤同时生效、互不破坏**（`apply_department_filter` 管行、`serialize_fields` 管列）。

### 新增 `backend/tests/test_a06_field_scope.py`（UNASSIGNED → 走 `collab.integration`）
12 例：硬底线常量、`filter_columns` 三种口径（None 全量 / 白名单交集 / 空集 deny）、
白名单里写 `password_hash` 仍被剔除、`resolve_visible_fields` 三种角色 + 未知资源、
端到端（dept_manager 字段集 == 基础集、system_admin 含审计字段但无密码哈希、
行级过滤未被裁剪破坏、PUT 返回同策略、401 门禁不变）。

## 三、设计取舍

- **只在 A 自有的 `accounts` 资源落地**：人才主档 / 简历 / 员工数据属 B/D 归属，A 不越界改其序列化；
  机制（`resolve_visible_fields` / `serialize_fields`）做成通用入口，下游注入同一套即可。
- **不改 A06-4 的 `/api/system` router 出参**：那批接口整域仅 system_admin 可进，字段级差异无意义，
  且改已发布行为会动 A06-4 的 7 个断言；本单元保持其行为不变。
- **deny-by-default**：无匹配角色返回空集而非「全量」，避免新增角色时静默扩大可见面。
