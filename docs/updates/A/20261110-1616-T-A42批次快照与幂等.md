## 三、设计取舍（写清楚，避免后续误改）

1. **请求级幂等，不是内容级自动去重**。需求 §105 要求「岗位/档案变更新建一轮」，因此不能按「同岗位 + 同 scope + 同快照」永久复用旧批次——那会在档案内容变化但名单不变时错误复用。本单元采用客户端显式 `idempotency_key`：重复提交同一请求返回原批次；不传键或换键即新建一轮。
2. **组合唯一而非单列唯一**。幂等键限定在同一岗位内，避免不同岗位复用同一 key（如前端按 `"round-001"` 生成）时互相冲突；唯一约束与查询条件同为 `(job_profile_id, idempotency_key)`。
3. **快照版本优先 + 历史兼容回退**。`A_0010` 之前的历史批次确实没有版本字段，强行 `snapshot["model_version"]` 会让历史 failed 批次无法 retry；`resolve_batch_model_versions` 回退当前配置并告警，明确标注「历史批次无法追溯」，不静默伪装成已固定。新批次一律从创建时固定。
4. **不改响应 DTO**。重复请求返回同一个 `batch_id` / `total` / `status` / `estimated_llm_calls` 即可核对，避免给前端引入新字段。`ScreenBatchCreatedData` / `MatchBatchCreatedData` 保持原样。
5. **不碰主验收库 `ai_talent`**。迁移只在隔离库 `ai_talent_a_probe` 实跑；主库 stamp/结构落后问题按既有约定保持「待人工重建授权」。8101/3101 未重启。
