## 1. 最小引用字段

A 的招聘记录只保存以下引用，不复制面试内容：

| A 字段 | C 字段 | 说明 |
| --- | --- | --- |
| `interview_round_id` | `round.id` | C 创建后返回，A 只存 ID，不存轮次正文 |
| `candidate_user_id` | `candidate_user_id` | 候选人平台账号；个人端可见性据此判定 |
| `talent_profile_id` | `talent_profile_id` | B 人才主档 ID，可空；A 不按姓名联表 |
| `job_id` | `job_id` | 岗位 ID，可空 |
| `job_version` | — | **C 不保存岗位版本**；A 在自己的招聘记录中保存当时版本快照 |
| `round_status` | `status` | `pending` / `completed` / `cancelled` |
| `candidate_visible` | — | **不落库**；按下方规则实时判定，A 不存布尔快照 |

- `job_title` 是 C 轮次内的展示快照，不作为岗位版本依据。
- `mode`：`onsite` / `online` / `phone`。
- 轮次删除：C 不提供删除，只允许 `cancelled`；A 不应自行删除引用。

## 2. 可见范围判定

- 内部可见：`role in {"admin","hr"}`，或当前用户在 `interviewer_user_ids` 中。可见内部备注、变更事件、结构化反馈。
- 候选人本人可见：`candidate_user_id == 当前用户 id` 时可见本人轮次的时间、方式、地点/链接、状态；**不返回内部备注、事件和反馈**。
- 其他员工、无关人员一律 403。
- C 没有“向候选人公开反馈”的开关；一期结构化反馈始终只对内部授权人员可见。A 个人端不得展示 `evaluation/evidence/strengths/weaknesses/recommendation`。
- 反馈字段：`evaluation`、`evidence`、`strengths`、`weaknesses`、`recommendation`（`advance` / `hold` / `reject`）；无总分。

## 3. 幂等与校验归属

- 预约创建：`POST /api/interviews/rounds` 支持可选 `client_request_id`（≤64 字符，全局唯一）。同键重复提交返回首次创建的轮次，不重复写事件。A 应为每次邀约生成稳定键并保存返回值。
- 反馈提交：`PUT /api/interviews/rounds/{id}/feedback` 以 `round_id` 为业务键，每轮唯一；重复提交为更新，`version` 递增。
- 未完成面试不得有反馈：C 在轮次 `status != completed` 时返回 400；校验归属 C，A 不应自行写反馈或补造记录。
- 同一候选人同一岗位多轮：用不同 `round_no` 和不同 `client_request_id` 创建，C 不做“一人一岗只允许一轮”的限制。
