## 三项对齐的处置

### 1. `CTimestampMixin` 是否收敛到公共 `UpdatedAtMixin`：不收敛，附实测证据

- 实测：用公共口径 `server_default=text("CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP")` 在 SQLite 建表，报 `sqlite3.OperationalError: near "ON": syntax error`；同一定义用 MySQL dialect 编译 DDL 正常（`DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`）。
- 影响：C 的 `tests/C` 集成测试用 SQLite 内存库直接 `create_all`；收敛后 32 张 C 表无法建表，49 项测试全部无法运行。
- 结论：C 保留 `CTimestampMixin`（应用层维护 `updated_at`），并在 C 契约 §2 已注明原因。若 A 要统一口径，需先给公共 mixin 增加 dialect 感知的默认值（MySQL 走 `ON UPDATE`，其他 dialect 用 `CURRENT_TIMESTAMP`）；A 交付该能力后，C 再随表结构变更提交 `C_*.py` 迁移切换，并把结构测试的 C 域特例收紧。
- 不对 A 已完成的结构测试断言做改动（C 只在自己提交里同步 45 表口径）。
