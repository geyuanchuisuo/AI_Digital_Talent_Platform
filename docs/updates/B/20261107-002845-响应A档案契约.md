## 1. person_id 映射规则

- `person_id` **直接复用 `talent_profiles.id`**，类型为整数（`PK_TYPE`，数据库自增主键），不是 UUID，也不是字符串。
- 生成规则：档案行创建时由数据库生成；A 不需要第二套主档，可直接在 `users` 存 `person_id`（建议 `BIGINT`，可空，个人账号唯一）。
- 唯一性：由 `talent_profiles` 主键保证；一个 `person_id` 只对应一个档案。
- 有效期：创建后终身不变；重新解析、人工修订、合并、恢复都不改变编号。
- 失效处理：只做软删除（`deleted_at` 非空），编号不复用、不重新分配。
- 合并：保留主档案的 `person_id`，被合并编号标记失效；历史报告引用原快照，不把旧编号重新指向新人。
- A/C/D 统一使用该整数 ID；禁止按姓名、手机号或邮箱二次关联。

## 3. 批量读取与分页约定

- 单次 `person_ids` 最多 **100** 个；重复 ID 去重；空列表返回空页。
- `limit` 默认 20，最大 **50**；按 `person_id` 升序稳定分页，`cursor` 为上一页最后一个 `person_id` 的不透明编码。
- 批量接口永远返回 **200 + 逐项状态**，不因个别人失败而整批报错。
- 每项状态：
  - `ready`：档案可用；
  - `processing`：解析等待/执行中，`profile` 可为空；
  - `failed`：解析失败，带 `reason`；
  - `deleted`：软删除，默认不参与新评分；
  - `not_found`：无此 `person_id`；
  - `version_not_found`：指定版本不存在（仅显式传入 `version` 时）。
- `coverage`：`complete` / `partial`；`partial` 时必须在 `missing_fields` 或 `review_fields` 中体现原因。
- `missing_fields` 是“资料没有”，不是“不符合”；A 的评分必须按未知处理，不得据此扣分或判不符合。
- `review_fields` 是待人工核实字段；A 可带入评分但需在结果中标注“待核实”。
- `truncated=true` 表示原文被截断；A 应把未覆盖经历标为未知，不推断“没有”。
- 顶层 `partial=true` 表示至少一项非 `ready`；`requested_count`、`returned_count`、`next_cursor` 一并返回。

## 4. 证据批量读取约定

```python
def get_person_evidence(
    person_ids: Sequence[int],
    *,
    version: int | None = None,
    field_paths: Sequence[str] | None = None,
    scope: AccountScope,
    cursor: str | None = None,
    limit: int = 50,
) -> EvidencePage: ...
```

- 单次最多 50 个人员；每页最多 200 条证据；`snippet` 最长 300 字，不返回 `raw_text` 全文。
- 每条证据字段：`person_id`、`version`、`field_path`、`file_id`、`page_no`、`snippet`、`source`（`text`/`ocr`/`llm_derived`/`manual`）、`confidence`、`review_status`。
- 证据不可用时返回 `evidence_status="unavailable"` 与空数组，**不报 404**，避免 A 把“暂无证据”当成“没有经历”。
- `field_paths` 可按字段过滤，如 `["educations","employments","projects"]`；未知字段返回 400。
- 分页规则同快照：`cursor` 稳定、按 `person_id + id` 排序；单页超限返回 400。
- 个人账号只能读本人证据；`scope.role="system"` 供 A 的 Worker 使用；越权返回 403。

1. 用 ≥2 份不同档案对同一岗位生成有差异、有依据的评分。
2. 对 `missing_fields` 非空的档案，验证结果是“待核实/未知”，不是“不符合”。
3. 验证 `config_snapshot_json` 旧键不变，新键可读，历史批次不随档案更新变化。

5. 验证解析中/失败/删除档案分别返回 `processing`/`failed`/`deleted`，不混为“无能力”。
