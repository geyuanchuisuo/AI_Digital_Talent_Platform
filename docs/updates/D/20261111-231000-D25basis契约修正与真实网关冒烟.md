## 一、为什么改（真实冒烟暴露的契约缺陷）

D25 接线后的首次真实网关冒烟发现：`_EnhanceList` 校验通过、LLM 返回结构正确，但 **LLM 的 `basis` 用事实序号引用（`["1","2"]`），而消费侧只认事实段 key（`headline`/`top_gap`）**——全部增补段因「无有效依据」被丢弃，静默回退 `generator="rule"`。Prompt 要求「填事实编号」、代码要求「填事实 key」，两侧契约对不上，属实现缺陷（非模型问题）。

## 二、修正内容

1. **Prompt 契约统一为「事实序号」**：事实按序号（1 起）编号呈现，明确 `basis` 必须填列出的事实编号；事实段以序号引用对 LLM 更稳定。
2. **消费侧双向解析**：`basis` 同时接受事实序号（`"1"` → 映射回事实段 key）与事实段 key（`"headline"`，兼容既有测试与潜在直连调用方）；两种都解析不到才丢弃。
3. `_EnhanceItem.basis` 放宽为 `list[Any]`（LLM 可能返回数字或字符串，统一按标量接收后转字符串映射）。
4. 因果守卫、`_LLM_ENHANCE_MAX_INFERENCES=2`、文本截断 200 等既有防线不变。
