## 具体改动说明

### 问题

生成器原逻辑：模型返回任何非空、非 `CANNOT_ANSWER` 的文本都当作 SQL 交给校验器。若模型返回自然语言（如「我不知道」「抱歉，我无法回答」），校验器会以 `refused_unsafe` 拒绝，而非 `refused_unmappable`，导致审计语义不准。

### 修复

在 `OpenAICompatGenerator.generate_sql()` 中新增启发式：

```python
if not re.match(r"^\s*(SELECT|WITH)\s", text, flags=re.IGNORECASE):
    return None
```

- `SELECT ...` / `WITH ...`（CTE）→ 交给校验器
- 其余文本（自然语言/空/歧义）→ 返回 None，service 记为 `refused_unmappable`

### 新增测试

- `test_openai_compat_generator_non_sql_text_returns_none`（4 例参数化：中文不知道 / 中文抱歉 / 英文抱歉 / 空串）
- `test_openai_compat_generator_with_cte_accepted`（`WITH c AS (...) SELECT ...` 不误伤）

### 审计语义

修复后拒答路径统一：
| 场景 | stage | HTTP |
|---|---|---|
| 模型返回 `CANNOT_ANSWER` | `refused_unmappable` | 422 |
| 模型返回非 SQL 文本 | `refused_unmappable` | 422 |
| 模型返回 SQL 但校验器拒绝 | `refused_unsafe` | 422 |
| 生成通道不可用 | `refused_unmappable` | 503 |
