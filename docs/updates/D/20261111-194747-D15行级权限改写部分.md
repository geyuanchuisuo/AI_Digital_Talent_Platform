## 设计缺口：行范围 SQL 注入

### 当前状态

- nl2sql service 仅允许 `hr` 角色（`scope.role not in ("admin", "hr")` → 403）。
- `hr` 角色 `can_view_all_persons=True`，无需行级过滤。
- `get_account_scope` 当前只处理 `personal` 和 `hr`；`dept_manager` 等角色映射为 `personal`（deny-by-default）。

### 未做部分

1. **角色扩展**：未在 `get_account_scope` 中支持 `dept_manager` 等角色的 `department_ids` 解析。
2. **SQL 行范围注入**：未实现将 `WHERE department_id IN (...)` 注入任意 SQL 的机制。
   - 直接字符串注入不可靠（JOIN/子查询/CTE 场景复杂）。
   - 备选方案：PostgreSQL RLS（需副本策略）、SQLAlchemy 子查询包装（仅适用简单 FROM）、或校验器拒绝含 `department_id` 过滤缺失的 SQL（最保守）。
3. **副本表核对**：未确认 PG 副本中哪些表有 `department_id` 列（ETL 可能未同步该列）。

### 已做部分

- 补 `test_personal_denied_403_no_pg`：personal 角色 403，且不泄露对象存在性（`message == "无权访问该资源"`）。
- 待办清单标注为 `⚠️` 部分完成，记录设计缺口。

### 建议决策点

1. nl2sql 是否应对非 `hr` 管理侧角色开放？若否，当前 403 已足够，行级注入不需要做。
2. 若是，优先用 RLS（数据库层强制，最可靠），还是 SQL 改写（应用层，需覆盖所有 SQL 形态）？
3. 副本表是否有 `department_id`？若 ETL 未同步，需先补 ETL。
