## 具体改动说明

### 1. `validator.py` 禁写关键词补全

新增 `INTO`、`EXPLAIN`、`ANALYZE`、`PERFORM`：

- `INTO`：拦截 `SELECT ... INTO new_table`（建表）与 `INTO OUTFILE`（写文件）
- `EXPLAIN`：拦截 `EXPLAIN ANALYZE`（会真实执行查询，DoS 向量）
- `ANALYZE`：拦截维护命令
- `PERFORM`：拦截表达式执行（可触发函数副作用）

### 2. `_has_top_level_limit` 子查询 LIMIT 误判修复

**问题**：原实现用 `stmt.flatten()` 扫描全树，子查询里的 `LIMIT` 会被误判为顶层 LIMIT，导致外层不限行。
**修复**：改为按括号深度扫描，仅 `depth == 0` 的 `LIMIT` 计入顶层。
**影响**：`SELECT * FROM (SELECT ... LIMIT 5) sub` 现在会被正确包装为 `SELECT * FROM (...) AS _q LIMIT 100`。

### 3. `_walk_tables` 子查询别名误判修复

**问题**：`(SELECT ...) AS sub` 被 sqlparse 解析为含 `Parenthesis` 子节点的 `Identifier`，原逻辑把别名 `sub` 当表名加入白名单核对，导致合法子查询被拒（`表不在白名单：sub`）。
**修复**：含 `Parenthesis` 子节点的 `Identifier` 不作为表名，但仍递归提取内部真实表引用。
**影响**：修复了既有缺陷，使子查询场景能正确校验。

### 4. 新增测试（`tests/D/test_nl2sql.py`）

- `test_validator_subquery_limit_not_counted_as_top_level`：子查询 LIMIT 不算顶层
- `test_validator_top_level_limit_still_not_wrapped`：顶层 LIMIT 仍不包装（回归保护）
- `test_validator_dangerous_read_like_statements_rejected`：INTO/EXPLAIN/ANALYZE/PERFORM 负例
- `test_validator_into_inside_string_not_false_positive`：引号内 INTO 不误伤
- `test_validator_comment_write_keyword_not_executed`：注释内写关键词不执行
- `test_validator_union_non_whitelist_table_rejected`：UNION 注入非白名单表拒绝
- `test_validator_union_whitelist_tables_allowed`：UNION 白名单内放行

### 5. 确认非缺口

- **注释绕过**：注释内关键词不执行，校验放行是安全的；注释拆分关键字（`SEL/**/ECT`）被 sqlparse 判为 UNKNOWN 且非 WITH 开头，已拒绝
- **UNION 注入**：非白名单表被表引用核对拦截；白名单内 UNION 安全
- **`pg_sleep`/`generate_series` 滥用**：函数调用非关键词，由执行层 `statement_timeout` + 行上限兜底，非校验器职责
