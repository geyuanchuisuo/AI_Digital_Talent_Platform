## 一、映射设计（以 Dify 1.19.0 锁定源码实核为准，不凭记忆）

对接目标为 T-D05 锁定的 Dify 1.19.0（commit `8e689e868b63`），其源码在本机部署目录（`%TEMP%\dify-kickoff\`，非 Git 管理）。本轮实核三个决定性事实：

1. **DSL envelope**：`api/services/entities/dsl_entities.py::make_app_dsl` + `api/models/workflow.py::WorkflowContentDict` → `{version, kind: "app", app{name/mode/icon/...}, workflow{graph{nodes,edges}, features, environment_variables, conversation_variables, rag_pipeline_variables}}`；`CURRENT_APP_DSL_VERSION = "0.7.0"`。
2. **导入校验是轻量结构校验**：`api/services/workflow_service.py::validate_graph_structure` 不按节点类型 schema 强校验（仅 start/trigger 共存拒绝 + human_input 数据校验）——因此以 `data.type = "ait_<域节点类型>"` 的 1:1 映射 DSL **可被真实导入**，域语义完整保留在节点数据里。
3. **features 空对象合法**：`WorkflowAppConfigManager.config_validate` 走 `validate_and_set_defaults`，缺失键由 Dify 侧补默认。

据此映射（契约 §2）：六类域节点 1:1 映为 `ait_*` 自定义节点（node_key 即 Dify node id，config/inputs/outputs 原样进 `data.ait_*`）；branch → `sourceHandle`；condition → `data.ait_condition`；**不注入合成 start/end**——触发经 run params，1:1 映射保证「导出 → 导入」图恒等（对账验收②的基础）。

## 二、验收实测（真实退出码，SQLite 夹具，无外部依赖）

| 验收项 | 实测 |
|---|---|
| ②版本对账一致 | 导出→导入后 `normalize_graph(v1) == normalize(v2)` 恒等断言 ✓；`reconcile(导出的 DSL)` **identical=True** ✓；drift 场景（改名/删节点/删边/增节点）报告逐项命中且**不建版本**（版本数仍 1）✓ |
| ③画布外改动不静默进落库 | 异类节点（`llm`）→ 422 点名 node id +「不静默丢弃」；游离连线（→ 异构节点）→ 422；未知 `ait_` 类型 → 422 白名单提示；坏 envelope（无 app 段/mode 非 workflow/版本 9.9.9/YAML 损坏）→ 422；空图 → 422 ✓ |
| 版本锁定 | 导入只建 `draft`（version=max+1），已发布版本的节点/连线行数与内容不变 ✓ |
| 回写 | `DIFY_RUN_TRACE_URL` 未配置 → skipped（业务零副作用）；假传输捕获载荷（schema/steps/错误截断 ≤300）；传输失败 → `sent=False` 不抛出；`sync_run_status` waiting 不回写、进入终态回写、succeeded→cancelled 照常回写 ✓ |
| 门禁 | 3 端点 personal **403**（HTTP 层）、hr 200 ✓ |
| 回归 | workflows 相关 6 文件 **68 例全绿**（含 sync_run_status 挂钩影响面） |

**实现过程中的坑（供避坑）**：①ORM 的 `JSONDict` 是 `MutableDict`（dict 子类），PyYAML SafeRepresenter 按精确类型查找 → `RepresenterError`，导出处一律 `_plain()` 递归转纯容器；②`normalize_graph` 须兼容 service 载荷（`key`）与 `get_version_detail`（`node_key`）两种形状。
