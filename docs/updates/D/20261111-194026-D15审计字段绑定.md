## 具体改动说明

### 1. `Nl2SqlAudit` 模型新增两列

- `executed_sql: Mapped[str | None]`（Text）：校验后实际执行的 SQL（含 LIMIT 包装）。原 `generated_sql` 保留模型原始输出，不再被覆盖。
- `truncated: Mapped[bool]`（TINYINT(1)，NOT NULL，server_default 0）：结果是否因行上限被截断。

### 2. `service.py` 写入逻辑

- 校验通过时：`_audit_update(..., executed_sql=sql)`（原来错误地写 `generated_sql`，会覆盖原始输出）。
- 执行完成时：`_audit_update(..., truncated=result["truncated"])`。

### 3. 迁移 `D_0013_nl2sql_audit_fields`

- `down_revision = "C_0010_capability_ratings"`（当前唯一 Alembic 头）。
- 幂等 ALTER：Inspector 检查列是否存在，避免重复执行报错。
- `downgrade` 先删 `truncated` 再删 `executed_sql`。

### 4. 新增测试

- `test_audit_records_executed_sql_and_truncated`：验证 `generated_sql` 保留原始输出、`executed_sql` 记录包装后 SQL、`truncated=True` 落库。
- `test_audit_not_truncated_defaults_false`：验证未触发截断时 `truncated=0` 且 `executed_sql` 为 NULL。
- 全链测试补断言：`audit.generated_sql` 含测试数据、`audit.executed_sql == audit.generated_sql`、`audit.truncated == 0`。

### 5. 审计与快照/反馈关联的说明

nl2sql 不创建 `AnalyticsQuerySnapshot`（快照仅用于登记指标查询），`MetricFeedback` 的 `snapshot_id` 指向快照而非 nl2sql 审计。因此 nl2sql 审计与快照/反馈无直接外键关联，本项不涉及跨表关联反例。
