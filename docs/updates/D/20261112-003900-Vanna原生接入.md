## 一、原生边界（对齐执行表 D14 验收口径）

「不以普通模型适配器替代集成」的落实：SQL 生成链路中 **LLM 通道与 Agent 编排全部由 vanna 自身实现承载**——`vanna.integrations.openai.OpenAILlmService`（vanna 自带 OpenAI 兼容实现，网关为其原生参数）+ `vanna.Agent`（自带 SystemPromptBuilder/消息流/记忆）。自研侧仅保留：同步协议适配（`asyncio.run` 驱动异步流——nl2sql service 经 `asyncio.to_thread` 调用生成器，worker 线程无事件循环）、输出校验（与 OpenAICompatGenerator 同一套 CANNOT_ANSWER/非 SQL 拒答规则）、错误卡转 `GeneratorUnavailable`。

**关键实测发现（vanna 2.0.2 行为，供后续避坑）**：
1. LLM 失败时 Agent **不抛异常**，而是产出 `status_card(status=error, title="Error Processing Message")` 组件（原始错误被 vanna 通用文案吞掉）——适配层识别错误卡后转 `GeneratorUnavailable`，不做半残输出；
2. Agent 输出文本在 **嵌套字段** `rich_component.content` / `simple_component.text`（顶层 UiComponent.content/markdown 为 None）；
3. `pip show` 发行版 2.0.2 与包内 `__version__` 常量（0.1.0）不一致——前者为准，requirements 声明无问题。
