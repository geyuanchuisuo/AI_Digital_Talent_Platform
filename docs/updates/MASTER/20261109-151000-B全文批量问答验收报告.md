## 本轮实现

1. 新档案版本冻结已保存的逐页原文，分片600字符、重叠100字符，绑定文件/物理页或DOCX文本定位、字符范围和质量。历史版本保持原样，不用当前原文冒充旧版证据；旧档案可由管理端刷新索引形成新版本，相同内容不重复增版。全文范围指已成功提取的页，不证明OCR覆盖了原始文件的所有内容。
2. B专属Milvus集合`talent_vectors_b_qa_chunks_v1`，名称派生自本机既有集合配置。按人员、版本、正文与Embedding配置摘要过滤；确定性ID可重试，部分写入不当作完整缓存。搜索返回ID再与当前快照核验，引用不采信存储任意文本。该过滤方式参考[Milvus官方过滤检索文档](https://milvus.io/docs/filtered-search.md)，本项目授权仍在B服务端先执行。
3. 管理端批量接口`POST /api/talents/questions/batch`：最多20人、重复ID去重、全部授权后才检索。逐人记录回答、不足或失败，返回请求数/已回答数/partial；不将检索前几名冒充全量统计。单人记录继续持久化人、版本、上下文、Prompt、模型、检索策略与结果。
4. 人才列表增加当前页勾选与逐人问答卡，回收站禁选，切数据清空选择；回答展示人员、版本和引用。管理详情提供`刷新全文索引`按钮；个人端不开放管理索引操作。
5. 软删除清理人才向量及问答片段；失败沿用vector_deleted=false，数据库删除不回滚。即使索引残留，撤权/删除状态也先于检索核对。恢复后按授权快照重新建立索引。
