## 设计与选择

复用 detect → flag → resolve/merge_journal，不另建第二套合并实现。比较仅靠向量相似度、手机号首命中、联合身份规则三种方案：选联合身份规则，保留公共 normalize_phone/normalize_email 名称和中置信人工处理；向量相似只表示内容相似，不能据此自动认定同人。

- 自动/人工复用既有字段保护、版本、原件、合并日志、向量半写和撤销。利用 talent_profile_edits 私有审计字段保存规则版本、信号、冲突字段名及执行方式；不新增公共模型注册或表结构。
