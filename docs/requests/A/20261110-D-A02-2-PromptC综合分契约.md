## 背景与依据

V2.6 §5 明确：「岗位匹配采用 AI 综合评分，由模型结合岗位与简历给出分数、匹配依据和不足」「**语义相似度不等于业务匹配分，不强制加入 0.7/0.3 或 40/30/15/15 的公式**」。A 设计方案 M4 要求以「模型分析岗位 + 完整档案 → 0–100 分 + 匹配依据 + 不足 + 待核实」替代 `hard_gate` + 权重公式 + `0.7/0.3` 向量混合。

A 本轮已完成 **A02-1**（取消硬门槛自动淘汰、不符项仍可见、缺失证据标待核实），详见 `docs/updates/A/20261110-1100-A02-1取消硬门槛自动淘汰.md`。剩余 **A02-2** 是「模型直接给 0–100 综合分」，需要给 Prompt C 输出契约加一个字段。

## 跨域阻塞点（实测）

`app.service.match_engine.evaluate()` 调用 `chat_json(user_text, MatchScoreOutput, prompt_name="match")`：

- **运行时校验**走 A 的 Pydantic `MatchScoreOutput`（`backend/app/schemas/match.py`，A 归属）——A 可以自行加 `overall_score`；
- 但 `prompt_name="match"` 会让 `build_messages` 把 D 的 `PROMPT_C_SCHEMA`（`backend/app/core/prompts/schemas.py:152`）拼进 **system prompt**，真实 LLM 按该 JSON schema 输出。若 A 单方面给 `MatchScoreOutput` 加必填 `overall_score` 而 D 的 schema 仍是 `additionalProperties: False` + 无该字段，**真实模型不会输出综合分 → Pydantic 校验失败 → 全批评分失败**；单元测试用假件返回 Pydantic 对象，反而发现不了这个不一致；
- `backend/tests/test_prompts.py::test_prompt_c_schema_contract`（D 归属）还断言 `list(props) == ["skills","experience","education","others","reason"]`、维度键为 `["score","hits","misses"]`，以及 match prompt 含 `llm_experience`、`不要自行判定淘汰`。
