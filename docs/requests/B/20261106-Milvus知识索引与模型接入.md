# 请求：Milvus 知识索引、Embedding 与问答模型接入

- 请求 ID：REQ-B-20261106-04
- 请求方：B（知识库/档案问答）
- 目标维护人：D（统一模型、任务框架、Embedding/Milvus）
- 对应需求：F06 知识检索与问答、档案问答版本引用
- 状态：待处理；未调用模型、未创建索引

## 目标

在不复制 D 的模型/向量/任务框架前提下，让 B 建立知识文档索引、执行制度问答和档案问答。

## 请求 D 提供

1. **Embedding 与 Milvus 复用方式**：确认 B 直接复用现有 Embedding 客户端与 Milvus store，还是由 D 暴露统一服务接口。
2. **知识 collection 约定**：
   - collection 名称/前缀（建议 `knowledge_` 或按环境加前缀）；
   - 向量维度、距离度量、主键；
   - metadata 字段：`document_id`、`document_version`、`chunk_no`、`permission_scope`、`index_version`、`category_id`；
   - 删除、按文档重建、按版本失效的接口。
3. **问答模型调用**：制度问答与档案问答使用统一模型网关；确认超时、有限重试、失败返回方式，禁止 B 自行保存密钥或另建客户端。
4. **Prompt 归属**：B 负责业务提示词内容（知识问答、档案问答、拒答规则），请确认放置路径与加载方式。建议放在 B 已拥有的 `backend/app/modules/knowledge/prompts/`，由 D 的 loader 读取；如必须使用 `core/prompts/`，请将对应文件加入 B 的 ownership。
5. **任务执行**：知识文档分段/索引是否复用 D 的 TaskRunner；如复用，请给出任务类型与阶段命名（如 `extract`、`chunk`、`embed`、`index`）。
6. **索引版本**：确认 `index_version` 的生成规则与查询时如何选择当前有效版本。

## B 承诺的实现

- 只实现业务层：文档提取、分段、权限过滤、引用组装、拒答、问答记录。
- 不复制 Embedding/Milvus/LLM 客户端，不修改 D 的模型或任务框架。
- 检索先按权限过滤再召回；引用必须能定位文档、片段、页码。
- 模型/索引失败明确提示，不返回预设答案；业务已保存与索引待处理分开显示。
- 用虚构公共文档与管理员文档验证引用、拒答与隔离。

## 兼容与影响

- 知识索引为新增 collection，不影响现有人才画像向量 collection。
- 删除文档时同时删除 MySQL 片段记录与该文档向量；删除失败要可重试并显示状态。
- 档案问答复用现有画像数据，不新增向量副本。

## 验收

- 文档索引、删除、重建可重复执行且不产生重复有效片段。
- 制度问答返回文档名与可核对片段；无关问题拒答。
- 档案问答返回 person_id、profile_version 与证据。
- 模型或 Milvus 不可用时明确失败，前端状态可重试。
