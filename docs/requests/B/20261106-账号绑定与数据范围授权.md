# 请求：账号-person 绑定与数据范围授权

- 请求 ID：REQ-B-20261106-02
- 请求方：B（人才主档/知识/档案问答）
- 目标维护人：A（身份、账号、公共路由与页面外壳）
- 对应需求：F02 个人端隔离、F06 个人端只能查本人、12.4 权限提示
- 状态：待处理；未改动任何账号或权限代码

## 目标

让 B 的档案检索、原件下载、知识问答和档案问答能够按账号范围强制过滤，而不是只靠前端隐藏。

## 现状

- 现有接口只要求登录；`GET /talents/{id}/resume-file` 仅校验文件属于该画像。
- 没有账号与 `person_id` 的绑定关系，也没有个人端/管理员端的数据范围对象。
- B 无法判断当前账号能看哪些人员、哪些知识文档。

## 请求 A 提供

1. 账号与人员档案的绑定关系（建议字段：`user.person_id`，个人账号唯一绑定；管理员不绑定或可空）。
2. 统一的授权依赖/服务契约，建议形如：

```text
get_account_scope(current_user) -> {
  role: "personal" | "hr" | "admin",
  person_id: string | null,
  can_view_all_persons: bool,
  knowledge_scope: "public" | "admin"
}
```

3. 文件下载授权入口：`authorize_file_access(scope, file_id, action) -> allow | deny(reason)`。
4. 确认个人端页面路径归属：
   - 本人档案页、授权问答页是否由 A 组装外壳、B 提供组件与接口；
   - 若归 B，请将对应前端路径加入 `ownership.json` 的 B 范围（当前 B 只有 `frontend/src/app/(main)/talents/**`、`knowledge/**`）。
5. 提供个人账号的测试账号与绑定样例（虚构数据）。

## B 承诺的实现

- 在人才列表、语义检索、档案问答、知识问答、文件下载中，先按 `scope` 过滤再查询/召回。
- 个人账号只能查询/下载本人档案；禁止通过请求参数指定他人 `person_id`。
- 个人账号只能召回公共知识，不得召回管理员知识。
- 越权返回统一拒绝，不泄露人员是否存在。
- 新增负例测试：他人档案、他人原件、管理员知识、指定他人 ID 四类。

## 兼容与影响

- 需要 A 的用户模型/迁移与登录依赖配合；B 不修改 `models/user.py`、认证依赖或公共布局。
- 现有管理员功能保持可用；个人端为新增范围。
- 若暂无账号绑定数据，B 先按“管理员可全量、个人拒绝”实现并标注未联调。

## 验收

- 个人账号访问他人档案/原件/管理员知识/他人问答全部被拒。
- 管理员按角色正常访问。
- 语义检索在召回前完成权限过滤，不出现“先 top-k 再过滤”的越权或漏召回。
- 前端仅作提示，后端为最终授权点。
