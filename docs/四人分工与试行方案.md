## 2. A：身份、公共基础、岗位招聘与匹配

**继承什么：**后端 api/deps.py、认证相关 api/dao/schemas/service、models/user.py、models/job.py，以及 job_profiles、screen、match 对应 api/dao/schemas/service 与 tasks/screen_worker.py、tasks/match_worker.py。前端继承登录、岗位和匹配页面、Next.js 布局及路由骨架、公共 components 与 lib/http.ts、auth.ts、types.ts。screen 页面由 A 组装，A 维护 ScreenBatchPanel，不能把整个 screen 目录视为 A 所有。

**剩余任务：**核对登录与权限、账号到人才的关联、双端入口、数据库初始化及迁移基线；完善人才需求、JD 草稿、招聘状态与邀约记录。核对现成筛选/匹配算法与当前 AI 综合评分要求的差异，正式 Worker 未带完整经历/项目证据，需接 B 的版本快照补齐；复用已有岗位版本与批次成员快照，补档案版本、分数线边界、自动初筛与人工复核记录，保留旧行为的兼容记录，不据源码存在直接认定满足 F03。年龄、性别不进入本版匹配评分。人工面试内容由 C 维护，A 的招聘记录只关联安排与结果引用。

**跨包依赖：**B 提供以现有 talent_profile_id 映射 person_id 的档案快照、版本和证据；D 提供真实模型调用、任务及健康状态。A 维护公共配置、依赖、数据库连接、迁移链和入口注册，接入 B 的 screen 上传/队列组件及 D 的任务组件，不替其他人重写业务。match.txt 业务模板归 A，公共 loader/schemas 框架变更请求 D 配合。

**验收：**真实登录后可创建岗位、生成并保存 JD、上传档案后匹配、按分数线初筛、人工改判并刷新查看；岗位/档案改版后历史输入仍可追溯。验证阈值等于、评分失败、重复请求、越权及持久化。浏览器实测与服务检查分别记录。

## 3. B：文件/OCR、人才档案、知识与档案问答

**继承什么：**resumes/talents 相关 api/dao/schemas/models/service、tasks/parse_worker.py、core/normalize.py、core/profile_text.py，以及上传、队列、talents 页面。screen 中 UploadPanel、QueuePanel、api、types、utils 及对应测试归 B；page.tsx 和 ScreenBatchPanel 由 A 维护。core/prompts/parse.txt、profile.txt 的业务模板归 B，不能因位于 core 就交 D 单独维护。

**剩余任务：**核对现成提取链路实际支持的格式，补图片、扫描及混合 PDF OCR、逐页证据和无法识别提示；批量失败隔离、只重试失败阶段、文件去重与身份判断分开。沿用 TalentProfile 主档及 talent_profile_id，先提供 person_id 映射并补版本、原文引用、人工修订记录和确认值保护，不新建第二套人才主档。现成画像和雷达不能当作真实测评成绩。补制度知识处理、权限检索、引用、单人/批量档案问答与删除后的索引一致性。

**跨包依赖：**A 提供身份、文件下载授权入口和页面组装；D 维护 Embedding/Milvus/模型与任务框架，B 负责业务分段、权限、证据和索引生命周期。现有 Milvus 语义检索先复用，索引失败如实标注，不丢已保存业务数据。向 A/C/D 提供稳定人员映射、版本快照和证据读取服务，不直接替对方建业务表。

**验收：**文本 PDF、DOCX、图片、扫描 PDF 加损坏/重复文件组成混合批次，合法项能形成可核对档案，失败项独立提示且重试不重复建结果；人工修改可追溯。制度及单/批档案问答均有真实引用、人员范围和版本，无法覆盖时明确说明；个人端不能读他人档案或受限知识。

## 4. C：动态自适应测评、人工面试、培训成长

**继承什么：**保留 backend/app/modules/assessments、interviews、training 及前端同名 features 的既有空目录与归属。压缩包的招聘筛选源码不等于已经实现这些模块；C 通过服务继承 A 的身份/岗位、B 的人才快照、D 的模型/任务和轮询能力，不复制它们。

**剩余任务：**维护题库、岗位出题与管理员确认、测评分配、逐题作答、客观评分和真实 AI 简答评分。按已答表现、知识点与题量动态选择下一题，保存题目快照、理由、评分和进度；补错题、复习、能力分析、人工修分与历史。人工面试保存岗位、人员、时间、面试人、状态、记录及人工评价，实际字段与可见范围先登记契约，内部评价不自动对本人公开；不把招聘备注当成完整面试模块。补课程、基于实际课程的 AI 培训计划、管理员编辑分配、个人学习状态和成长历史。AI 文字提问、追问和自动面试评价放二期。

**跨包依赖：**A 接入页面路由和账号权限，A/C 对齐招聘与人工面试的引用；B 提供 person_id 映射和带版本档案；D 提供模型、任务、固定流程节点及错误处理。C 负责测评/培训业务提示与评分规则，需要公共 schema/注册变更时请求 D。向 D 提供经确认的测评、人工面试、学习指标口径，区分未参加、处理中、失败与未通过。

**验收：**相同初始条件下，答对/答错两条路线产生可解释的后续选题差异；不重复题，刷新可恢复，重试不重复提交。管理员及本人可见同一真实成绩，另一账号被拒绝。人工面试可安排、更新、记录评价并与招聘关联；未参加不生成虚构评价。培训推荐存在的课程，个人学习更新后管理端可查，复测不覆盖历史。

## 5. D：公共模型任务、指标问数、报告、固定流程与工作台

**继承什么：**core/llm_client.py、embedding_client.py、milvus_store.py、worker_state.py、prompts 的公共 loader/schemas 框架、tasks/runner.py、api/health.py，以及前端 lib/usePolling.ts 和测试。prompts 目录按文件分工：parse/profile 模板 B，match 模板 A；D 维护加载、版本组织、公共结构框架，不接管业务模板。parse/screen/match 执行体仍分别由 B/A/A 负责。

**剩余任务：**先复用 API 生命周期内的单进程 TaskRunner，核对注册、状态、并发、幂等、有限重试和中断恢复；不宣称独立 worker 已落地，不另造调度框架。保留来源 Spark 调用事实和独立 Embedding 配置，验证 Agnes 文本及结构化输出后再记录适配结论；不假定 Agnes 可提供 Embedding/OCR。补白名单指标目录、参数校验、只读查询及超范围提示，保存分析快照、真实图表解读和同快照 DOCX/PDF。补两条固定流程“解析→档案→匹配”“测评完成→能力分析→培训草稿”、分步输入输出、失败阶段重试、双端工作台真实统计。

**跨包依赖：**A/B/C 各自确认指标、授权范围、状态与时间口径，并提供服务/节点；D 编排而不复制业务算法。A 集成启动配置、路由、依赖和公共页面，D 提交自有任务组件；共享 http/auth/types 与 components 不由 D 修改。

**验收：**白名单指标在声明的维度/筛选下与人工查询一致，歧义和超范围明确返回；不执行模型原始 SQL。真实模型失败可见，任务恢复及重试不重复产物，向量不可用不伪装正常。DOCX/PDF 同源快照且中文、表格和图表可读，下载重新授权。两条固定流程有真实节点记录，工作台统计能回到业务记录核对。
