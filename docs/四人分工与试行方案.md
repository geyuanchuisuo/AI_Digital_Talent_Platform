# 四人分工与试行方案

日期：2026-11-06。需求依据：[统一需求文档 V2.1](需求文档.md)。状态：试行建议，尚未开发验证。小组人数与基础前后端能力已确认，具体姓名暂以 A/B/C/D 表示。周期暂沿用 3–4 个工作日，技术建议见 [技术框架](技术框架.md)。

## 1. 分配结论

采用四个业务工作包，每人负责自己模块的页面、接口、数据、模型提示及必要验证。四条线同时启动，统一公共契约并每天集成。全模块范围保持不变；早期只覆盖简历筛选的四人方案作废。

- A：基础平台、岗位招聘与匹配复核——F01、F03，F09 的登录和双端入口。
- B：文件解析、人才档案与知识问答——F02、F06。
- C：自适应测评、文字面试与培训成长——F04、F05。
- D：自由问数、报告、任务运行与预置工作流——F07、F08，F09 的工作台汇总和日志页面。

C 的测评与培训工作量较大；D 负责公共模型与任务执行器，使 C 不另写异步调度、模型客户端和日志体系。A 先交可运行的最小外壳，B 复用文档处理链路完成简历和知识问答，四人都复用基础表单、列表和任务进度组件。

## 2. A：基础平台、岗位招聘、匹配复核

### 交付内容

完成登录/退出、管理员与个人端布局、账号与 person_id 绑定、权限依赖和公共 API 响应；提供能运行的前后端骨架、路由注册方式和配置模板。用户端只能访问本人数据，演示期不建复杂组织授权后台。

完成岗位、人才需求、JD 草稿、招聘状态及邀约面试备注；岗位保存版本与分数线。完成选人匹配、AI 综合评分、按分数线初筛、人工改判和理由详情。人工结论与自动结果分别保存，不加入未经确认的固定加权公式或硬淘汰规则。

负责公共数据库连接与迁移汇总；每人编写自己的模型和迁移，由 A 整理迁移顺序，不替其他人设计全部表。

### 所有权与接口

维护后端 `core/auth`、`core/db`、`modules/identity`、`modules/recruitment`、`modules/matching`；前端 `app`、`shared`、`features/identity`、`features/recruitment`、`features/matching`。

提供用户上下文、岗位版本与需求读取服务；从 B 取得档案快照，调用 D 的模型/任务入口执行匹配；向 D 提供岗位、需求、匹配、复核查询字段和指标解释。

### 完成标准

管理员可建岗位、生成真实 JD、发起真实匹配并人工调整；个人端越权访问被拒绝；刷新及重启后岗位和结果仍在。分数线临界值、评分失败、重复请求和批次快照有验证记录。

## 3. B：文件解析、档案与知识问答

### 交付内容

提供批量上传、文件鉴权下载、文件指纹去重；文本 PDF/DOCX 提取，图片及扫描页 OCR，保存页码/片段与字段证据；实现任务进度、单文件失败隔离和失败阶段重试。形成统一人才主档、原文、标签、摘要及人工修订记录。

提供知识文档处理、分段索引、公共/管理员知识权限、问答和引用；单人/批量档案问答注明查询范围、人员与输入版本，无据时明确提示。精确人数不得用少数召回片段代替完整统计。

简历和知识库复用文件与文本处理适配器，但业务状态和访问策略分开。OCR 出错不标为模型解析成功；索引失败不丢已保存业务数据。

### 所有权与接口

维护后端 `modules/files`、`modules/talents`、`modules/knowledge`；前端对应三个 feature。提供 `get_person_snapshot`、`get_person_evidence`、`authorize_file_download` 等契约。

person 主档由 B 维护；A 通过服务关联账号，C 通过 person_id 保存测评/培训记录，不自行复制一套人才档案。D 查询经授权的档案与字段目录，不直接改人才表。

### 完成标准

一批混合 PDF、DOCX、图片、扫描 PDF 与损坏文件中，合法文件各自完成，失败项可重试；原文与生成内容可核对；重试不重建同一档案；制度问答及单/批档案问答均返回真实引用。个人端不能读取他人档案或管理员文档。

## 4. C：测评、文字面试与培训成长

### 交付内容

完成题库、岗位出题、管理员确认、测评分配及个人端逐题答题。按已答表现动态改变后续难度/知识点，保存题目快照、选题理由和答案。单选客观评分，简答 AI 评分，支持管理员复核、错题复习与能力展示。

完成按岗位发起文字面试、根据回答追问、会话保存与恢复、结束评价；笔试与面试结果分别保存，不自行合成未经定义的最终分数。

完成课程基础维护、从实际课程生成培训计划、管理员编辑分配、个人学习状态与备注、成长历史。复用答题和能力结果生成培训建议，不开发防挂机、音视频面试和完整视频课程系统。

### 所有权与接口

维护后端 `modules/assessments`、`modules/interviews`、`modules/training`；前端同名三个 feature。A 提供身份和岗位，B 提供档案快照，D 提供模型、后台任务及流程记录。

向 D 提供能力摘要、实际课程目录、测评/面试/学习的字段与时间口径，支持跨模块问数。正式结果读取服务区分未参加、评分中、失败及未通过，不将它们合并为一类。

### 完成标准

两个个人账号只能访问各自任务；同一初始条件下分别走答对/答错路径，下一题确实按策略变化；刷新恢复且重试不重复答题。面试有一次真实追问和有依据的评价；培训推荐真实课程，个人更新学习记录后管理端可见。

## 5. D：问数、报告、任务与工作流

### 交付内容

最初两小时提交统一 `ModelGateway`、任务提交/查询契约和模型错误示例，随后实现模型调用适配、持久化任务执行器、有限重试、并发限制和运行日志。任务类型由各模块注册，D 不接管各模块内部的业务算法。

实现自由问数：自然语言生成受控查询计划，按可访问实体/字段、关联与权限校验后，以 ORM 查询实际数据，再给出表格、图表和解读。可表达跨模块筛选/汇总，不收缩为四个预设问句；不执行模型返回的任意 SQL。

保存分析快照并生成 DOCX/PDF；提供报告权限下载，中文和图表可读。实现两条预置流程的运行编排、分步结果和失败重试，以及管理端/个人端实际工作台汇总。

### 所有权与接口

维护后端 `core/ai`、`core/tasks`、`modules/analytics`、`modules/reports`、`modules/workflows`、`modules/dashboard`；前端同名 feature 及任务进度组件。A 维护公共布局，D 的组件由 A 接入，不同时改布局文件。

读取 A/B/C 提供的数据目录和服务；问数需要的派生统计由数据所属人一起明确，不自行猜字段或按姓名关联。工作流节点调用相应负责人提供的服务，不复制解析、评分或培训逻辑。

### 完成标准

真实跨模块问题能回答且结果可人工核对；无数据、歧义、非法字段和写操作有明确处理。DOCX/PDF 来自同一快照，文件可打开；两条流程展示真实步骤，重试不重复建业务结果。模型失败有原因，密钥不进前端或日志。

## 6. 所有人第一天共同确定的契约

前两小时各自提交一页接口/字段样例，不等待全量设计完毕：

1. 身份：`user_id/role/person_id`，用户上下文由服务端解析；个人端不能自报任意 person_id 作为授权依据。
2. 核心数据：`person_id/person_version`、`job_id/job_version`；档案缺失值用 null，输入快照与原文证据分开。
3. 异步结果：提交返回 task_id；任务含 type/status/stage/attempt/result_ref/error。统一 waiting/running/completed/failed/cancelled；各业务状态另存。
4. 模型入口：请求包含任务名、提示版本、结构化输入和输出 schema；输出不合法走失败路径，不把 JSON 修复当成功保证。
5. 响应：`{code,message,data,trace_id}`；列表 data 为 `{items,total,page,page_size}`。前端错误处理共用一个入口。
6. 查询目录：每人列出自己数据的字段、关系、时间、状态和已完成结果定义；D 组装自由问数目录。

契约样例只用于并行开发，不属于验收结果。真实集成前移除或明确关闭演示替身，不能在模型故障时自动返回样例成功。

## 7. 四天试行节奏

### 第 1 天：先验证，再同时推进

前两小时：A 交登录/路由/数据库骨架；D 交模型/任务契约并验证 Agnes 文字及结构化调用；B 验证扫描 PDF 与图片 OCR；C 提交题库、会话与培训的字段样例。各自同时开展模块，不等骨架全部完善。

午前检查：四人的前端与后端都能单独启动；模型真实返回可校验 JSON，OCR 能得到中文，D 生成带中文和图表的一页 DOCX/PDF。若有失败，当天集中解决，不把依赖验证推到最后。

下午：A 做岗位和匹配；B 跑通一份真实简历；C 跑通题库及一次答题持久化；D 跑通一类持久任务、查询计划样例和报告下载。用同一 person_id 做一次真实跨模块读取，不只交换 JSON 文件。

日末必须能展示：创建岗位→上传一份简历→真实解析→档案入库→单次匹配；同时 C 的真实答题记录可供 D 读取。未完成项列出负责人、原因及下一检查时间。

### 第 2 天：主线贯通

A 完成初筛、人工复核和招聘记录；B 完成批量 OCR/重试并接知识问答；C 完成动态选题、文字追问和培训计划；D 完成跨岗位/测评的真实查询、两格式导出和首条流程。

午间共同跑招聘主线，日末共同跑测评→能力→培训→学习记录。答对/答错路线都需检查，不能用随机抽题代替自适应。测试失败按模块归属修复。

### 第 3 天：全模块串联并冻结

上午接通制度/单人/批量档案问答、培训与测评跨模块问数、第二条流程、工作台真实统计。下午停止加新功能，覆盖权限、空数据、超时、重复提交、失败重试与重启恢复。

文档、演示数据与启动说明同步整理，每人提交本模块验证结果和已知问题。所有要求保留，装饰性排版、高级组合筛选和额外图表不抢占主流程时间。

### 第 4 天：换环境验证与交付

选一台最终演示机，从空数据库按说明启动；核对依赖、OCR 模型文件、中文字体、模型配置和数据库迁移。全组演示完整流程并修复阻断项，交付源代码、启动/停止说明、配置模板、测试样例、验证记录和已知限制。

如果只有 3 个工作日：第 2 天结束前必须将上述全模块最小链路接通，第 3 天专门验证交付。检查点未达到时当天说明差距，另行讨论范围或时间，不静默砍掉已确认模块。

## 8. 试行数据与验收场景

仅使用虚构数据。至少准备 1 个管理员、2 个个人账号、2 个岗位、5 份覆盖四种格式的合法简历及损坏/重复反例；准备足以覆盖不同难度路线的题库、课程、公共制度和受限文档。

每人对自己的完整业务负责，并交叉复核：A 复核 D 的自由问数/报告口径，D 复核 A 的评分与改判；B 复核 C 的个人端隔离，C 复核 B 的解析与引用。

按统一需求 F01–F09 验收，每条记录“输入、预期、实际结果、模型/配置版本、通过或阻塞、证据位置”。第一轮侧重能真实运行，第二轮侧重失败与恢复，两轮都要覆盖模型和数据库实际数据。没有实测的事项保持未验证。

三条试行路线：

- 招聘路线：岗位/JD→混合批量上传→档案/人工修订→匹配→初筛→复核→招聘记录。
- 成长路线：分配动态测评→个人答题→文字面试→评分/能力→真实课程计划→个人学习→成长历史。
- 智能路线：制度及档案问答→跨模块自由问数→图表→DOCX/PDF→预置流程与任务日志。

## 9. 协作与集成规则

同一仓库，一人一个 feature 分支，不在四台电脑共享同一工作目录和同一开发数据库。A 维护主入口和迁移合并；其余三人提供模块路由注册与迁移，不同时手改主入口。主分支保持能启动，尚未完成功能可以明确显示未就绪，不能伪装成功。

各人本机独立数据库与文件目录，初始化脚本使用一致业务测试键；最终集成机由 A 协调。不要将四份数据库直接相互覆盖，演示数据由脚本重复生成，模型产生的结果通过真实调用建立。

每天午间与日末各集成一次；日末每人提交实际完成、验证结果、当前阻塞、下一交付点。D 组织集成清单，全体修复各自问题。共用契约变更先同步受影响人并更新样例，不私自改字段。

## 10. 二期继续按原责任深化

A 改善岗位规则、复核体验与权限；B 改善 OCR、检索质量与同人合并；C 校准自适应与评分、完善培训和复习；D 扩充查询能力、报告模板和任务恢复。每人先针对一期实际失败样例做一项可测改进，再考虑画布、音视频、复杂组织和生产部署。

工作量判断：四人具备基础前后端能力使该拆法可并行，但 OCR、自由问数和自适应仍需实际验证。第 1 天两个检查点用于检验方案是否可执行，不代表已保证四天全部完成。
