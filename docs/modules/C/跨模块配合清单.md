## 接口阶段必须对齐的最小信息

- A→C：用户上下文、人员资格、岗位快照与招聘关联；授权接口输入为当前用户、动作、资源引用，输出允许/拒绝和必要数据范围。不要只返回“已登录”。
- B→C：人员 ID/版本/事实/证据及可读取原件引用；不把最新档案当作历史输入。
- C→D：任务用途、执行人及对象引用、幂等键、输入版本、业务 schema/handler；D→C 返回 task_id、阶段、尝试、结果引用与明确错误。具体函数名/HTTP 路径在维护人响应后确定。
- C→A/D：分别提供内部授权结果与本人公开结果，不能共用未经裁剪的完整对象。请求/响应样例只用虚构数据，不提供密钥或真人资料。
- 所有人统一现有 API 信封和错误处理，业务版本/状态保留映射；数据库迁移与主路由由 A 汇总，不改他人迁移解决冲突。

## 依赖顺序与可并行工作

1. A 先交身份/岗位及注册契约，D 先交模型/任务扩展契约，B 先交人员快照样例和服务边界；每人记录已有与待实现，不能将约定写成已上线。
2. C 可独立设计领域模型、固定试卷和计分规则、人工面试及课程计划结构。实际接入前不以静态用户或固定模型响应冒充运行成功。
3. 真实简答评分需要 D；真实人员及权限联调需要 A/B；员工培训固定流程需要 A 的身份资格与 C/D 的结果契约。
4. 集成验收覆盖两个个人账号越权、招聘公布前后及修分版本、面试轮次授权、候选人禁止培训、员工身份关联与流程重试。未通过的依赖单列，不标整包验收通过。
