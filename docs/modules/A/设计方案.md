## 3. 设计原则（不改的底线）

1. **探针先行**：M1 未实跑前，M2–M5 只做设计与契约，不写"已完成"；任何外部依赖未测写明未验证。
2. **person_id 由 B 定义**：A 只做「账号 ↔ person_id」绑定与授权消费，**不新建第二套人才主档**，不按姓名联表（需求 §6、§12.1）。
3. **兼容优先**：`{code,message,data}`、`request_id`、分页结构、八个错误码、`health`/blob 例外原样保留；目标契约差异登记在模块契约，不全仓改写。
4. **快照不可变**：批次创建时固定岗位版本、分数线、人员名单、档案输入快照、模型/Prompt 版本；重试只补失败项，需要新输入就开新一轮。
5. **自动 ≠ 人工**：自动初筛只是内部建议；人工结论单独落库，评分失败单独状态，都不等于录用或终结申请。
6. **只写授权路径**：所有改动先用 `scripts/check_scope.py` 校验；B/C/D 文件不碰，缺口走 `docs/requests/A/`。
7. **真实调用**：模型/OCR/导出一律真实调用并记失败，严禁 mock 或静态常量冒充验收（根 AGENTS.md §5）。

### M2 · 身份、person_id 绑定与双端授权（T-A01 ~ T-A05）

- `backend/app/models/user.py`：User 增 `person_id`（可空、唯一索引由迁移控制）与账号端类型；**不新建 person 主档**。
- `backend/app/core/auth/**`、`backend/app/modules/identity/**`：新增 `require_admin`、`require_self(person_id)` 依赖；`dao/users.py`、`schemas/auth.py::UserOut`、`service/auth_service.py` JWT payload 带 `person_id` 与端类型。
- `backend/scripts/init_db.py`：seed 补 1 管理员 + **≥2 个个人端账号**及其 person_id（需求 §3.3），演示数据用虚构值。
- `frontend/src/lib/auth.ts::AuthUser`、`lib/types.ts`、`components/AuthGuard.tsx`、登录页：端识别与跳转；`frontend/src/features/identity/**` 放个人端组件。
- **后端授权为准**：个人端只能读自己的档案/成绩/学习记录，改请求 ID 访问他人须 403（需求 §3.2、F09）；前端隐藏按钮不算授权。
- 兼容：保留 `role=hr` 与现有 token 结构可被旧页面消费，新字段追加不删旧字段。

> ⚠️ **R-A01 阻塞**：`frontend/src/app/(person)/page.tsx` 等**新路由组路径未登记**，`check_scope.owner_of()` 返回 `None`。按根 AGENTS.md §3，归属变更需用户明确指示并**单独交付**，本方案不擅自改 `.collaboration/ownership.json`。一期可先在已授权的 `frontend/src/app/login/**`、`frontend/src/features/identity/**` 与 `frontend/src/app/page.tsx` 做端分发与组件，路由壳等授权后再落。

### M3 · 人才需求、AI JD、招聘状态与邀约（F01）

- 新增实体落在 **`backend/app/modules/recruitment/**`（A 通配授权）**：人才需求（岗位、`headcount`、说明、状态）、招聘记录（候选人 person_id、岗位版本、当前状态、邀约时间/方式/状态/说明、面试备注）、JD 草稿（来源岗位版本、模型/Prompt 版本、原文结果、人工可编辑值）。
- 路由聚到 A 已授权的 `backend/app/api/job_profiles.py`（或 `main.py` 注册 `modules/recruitment` 下的 router），页面落 `frontend/src/app/(main)/job-profiles/**` 与 `frontend/src/features/recruitment/**`。
- AI JD 由**真实模型**生成且可编辑保存；失败明确提示，不返回样例。邀约只存记录，不发邮件/短信、不接外部平台（需求 §5 F01）。
- 页面展示需求人数、人工标记进入下一步人数、剩余需求，并**写明统计口径**（§12.3 人工推进 ≠ 已录用）。
- 与 C 的边界：A 只保存人工面试安排/结果的**引用 ID**，不复制 C 的面试评价模型；重复提交不重复创建。

### M4 · AI 综合评分替换来源评分（F03 / C05）

- `backend/app/service/match_engine.py`、`tasks/screen_worker.py`、`tasks/match_worker.py`、`core/prompts/match.txt`、`backend/app/modules/matching/**`：以「模型分析岗位 + 完整档案 → 0–100 分 + 匹配依据 + 不足 + 待核实」替代 `hard_gate` + 权重公式 + `0.7/0.3` 向量混合。
- **输入补全**：从 B 的带版本档案快照读入经历/项目证据、`current_title`、`tags_json`、`ability_scores_json`、档案版本；不得拿历史评测脚本的较丰富输入替代正式链路验收。
- **输出校验**：后端校验分数范围与字段；保存岗位版本、档案输入快照、**模型名/Prompt 版本**、模型原始返回与结果快照（F03）；刷新只展示已保存结果，不触发重算。
- **边界**：等于分数线归「初筛通过」（§5 F03）；评分失败单独状态、不计未通过；技能词边界避免 Java/JavaScript、C/C++ 误判；缺失证据标待核实而非不满足；年龄/性别不参与评分；语义相似度不等于业务匹配分。
- 保留来源实现为可对照的兼容记录，**不静默删除**；不把模型自报准确率当实测准确率。

### M5 · 分数线、快照、逐结果失败与人工结论分离（F03 / §12.1）

- `models/job.py`（A）：`match_results` 补人工结论字段，对齐 `screen_results.manual_verdict*`；批次/结果补 `model_version`、`prompt_version`、逐结果 `failure_reason`/`attempt`；分数线由管理员按岗位设置，不沿用 75/60 作为已确认默认。
- 初筛结论改**两档**（通过/未通过）、人工复核**三态**（待复核/建议进入下一步/暂不推进）+ 备注；来源三档 `passed/pending/rejected` 在契约里登记映射，不全仓重命名、不重写历史数据（技术框架 §4）。
- 批次创建时固定岗位版本、分数线、人员名单、档案与 Prompt/模型版本；retry 只补失败项，不重新圈人（D-E）；岗位/档案变更后**新建一轮**计算，保留历史人工意见。
- 迁移链：`backend/migrations/versions/A_*.py`（A 通配授权；**架构核查：该目录当前不存在，需先建骨架**）+ `models/__init__.py` 的 13 表断言同步修改 + `scripts/init_db.py` 与 `scripts/backup_db.py` 清单同步；**`create_all` 不会 ALTER 已有表**，必须先确认本机是空库还是要升级，否则"刷新/重启可追溯"会假通过。
