# 招聘申请契约（applications，供 C 的 interview_rounds.application_id 引用）

> 版本：v0.1　|　日期：2026-11-07　|　维护：A　|　消费者：C（多轮人工面试）、D（招聘阶段事件）
> 对应：C 的 REQ-C-20261107-153521「招聘申请 application_id 契约」；实现 `backend/app/modules/recruitment/`（M3-V2.6，master 已集成）。

## 1. 实体与标识

- **application_id = `applications.id`**（BIGINT UNSIGNED 自增，PK_TYPE 同 B/C/D 主键）。
- 一个候选人（`talent_profile_id` = person_id，B 契约）对同一岗位（`job_profile_id`+`job_profile_version` 快照）一条在途申请；重新申请产生新行。
- **同岗在途 409**：创建时 service 校验同 `(talent_profile_id, job_profile_id)` 存在非终态申请即拒绝。

## 2. C 可读字段（interview_rounds.application_id 关联消费）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | application_id |
| talent_profile_id | BIGINT | person_id（B 契约） |
| job_profile_id / job_profile_version | BIGINT/INT | 申请岗位快照 |
| internal_stage | VARCHAR(30) | 内部状态 10 值（new/screening/matched/invited/interviewing/deciding/offer_accepted/rejected/withdrawn/job_closed） |
| external_stage | VARCHAR(20) | 对外五阶段（submitted/screening/interviewing/deciding/closed），**按已确认映射随内部状态自动更新** |
| result_category | VARCHAR(20) NULL | 终态结果类别（hired/not_hired），**HR 确认（result_confirmed_by 非空）后才对外发布** |
| resume_file_id | BIGINT NULL | 简历原件引用（B 的 file_id 同源） |
| stage_reason / stage_updated_by / stage_updated_at | | 阶段迁移原因与操作留痕 |

C 的 `interview_rounds.application_id` 直接存 `applications.id`；面试轮次的创建/查询由 C 的接口负责，A 侧不重复建模（T-A41 约定）。

## 3. 接口（已上线，OpenAPI 实测）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/recruitment/applications` | 创建（同岗在途 409） |
| GET | `/api/recruitment/applications` | 列表（talent_profile_id/job_profile_id/external_stage 过滤） |
| PATCH | `/api/recruitment/applications/{id}/stage` | 人工推进内部阶段（对外自动映射；终态不可流转） |
| POST | `/api/recruitment/applications/{id}/result-confirm` | HR 确认终态结果类别（幂等） |

响应统一 `{code,message,data}`；列表 `{items,total,page,page_size}`。

## 4. 面试事件衔接（站内通知，V2.6 F09 封闭清单）

- `interview.invited` / `interview.rescheduled` / `interview.cancelled`（各自独立事件）由 **C 在面试轮次变更时产生**，ref 指向 `interview_rounds.id`；A 的招聘阶段变化事件（`recruitment.stage_changed`）ref 指向 `applications.id`。
- 幂等键与 schema 见 A→D 契约响应（20261107-1130）。

## 5. 边界

- 内部评分（screen/match）与面试反馈**不进入** applications 行；对外仅 `external_stage` 与（确认后的）`result_category`。
- 阶段自动更新边界（哪些内部动作触发哪些阶段迁移）已按映射实现；终态重开、跨阶段跳转属 V2.6 §16「岗位关闭/退出/爽约/终态重开」待细化项，当前终态不可流转。
