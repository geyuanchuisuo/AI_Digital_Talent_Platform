## 1. 交付形态与边界

采用**混合一键**：Docker 只负责基础设施（MySQL / Milvus），项目环境由跨平台脚本创建。选择原因：全部落在 A 现有授权路径内，**不需要修改 `ownership.json`、不需要用户额外授权、不触发跨角色冲突**；同时避免 Windows 卷挂载下 Next.js 热更新与权限换行符问题。

| 层 | 内容 | 是否自动 |
|---|---|---|
| L1 系统运行时 | Python 3.11+、Node 20+、Docker Desktop | ❌ 客户预装（任何 Git 仓库都无法代装系统软件） |
| L2 基础设施 | MySQL 8、Milvus 2.6 + etcd + minio | ✅ 检测端口，缺哪个起哪个，命名卷持久化 |
| L3 项目环境 | `backend/.env`、`frontend/.env.local`、`backend/.venv`、`node_modules`、13 张表 + seed、向量 collection、前后端进程 | ✅ 全自动 |

**唯一不能自动的**：讯飞 Spark / 阿里百炼的 API Key。外部凭据不能写进 Git；客户在仓库根 `.env` 填一次（脚本首次运行会自动从 `.env.example` 生成该文件）。不填也能把环境完整建好，只是简历解析、AI 评分、向量检索不可用——脚本会打印明确警告，不假装成功。

> 因此准确表述是「clone 后执行一条命令（或双击），环境全自动建好」，不是「clone 动作本身触发安装」：Git 不会在 clone 时执行任意脚本。

## 3. 关键设计决策

1. **配置单一来源**：客户只改根 `.env`；`bootstrap.py` 读 `backend/.env.example` 取默认值 → 用根 `.env` 覆盖 → 自动生成 `backend/.env`。环境变量优先级最高，便于 CI/容器注入。
2. **不覆盖客户配置**：`backend/.env` 已存在时只同步客户在根 `.env` / 环境变量里**显式改过**的键（空值与占位值忽略），自动生成的 `JWT_SECRET` / MySQL 密码保持不变，因此「填完 Key 重跑一次即生效」成立；`frontend/.env.local` 的 API 基址随 `APP_PORT` 同步。`JWT_SECRET` 用 `secrets.token_urlsafe(48)` 只生成一次；`init_db.py` 幂等且「不删除不覆盖」。
3. **不动客户已有服务**：按 `MYSQL_PORT` / `MILVUS_PORT`（默认 3306/19530）探测，端口已占用才跳过对应容器；两者原本写死，客户机端口被别的项目占用时会「跳过容器并连进别人的库」，现已支持在根 `.env` 指定独立端口、库名、collection 与 `COMPOSE_PROJECT_NAME`，compose 端口和容器名同步参数化（默认行为不变）。本机已有 MySQL 但密码不同，覆盖 `MYSQL_PASSWORD` 即可；缺 Docker 又缺服务时明确报错退出，不静默降级。
4. **MySQL 启动竞态**：端口通 ≠ 初始化完成，`init_db.py` 失败自动重试 5 次（每次间隔 5 秒）；compose 的 mysql 带 `mysqladmin ping` healthcheck。
5. **Milvus collection 不手工建**：`main.py` 的 `lifespan` 启动时调用 `ensure_collection()`，脚本只负责把 Milvus 服务拉起来。
6. **供应商默认值修正**：旧模板是 DeepSeek 占位（`deepseek-chat` / `api.deepseek.com`），与历史 main 实配不符，客户照抄只填 Key 会失败。现改为 `LLM=spark-x2.6 @ maas-api.cn-huabei-1.xf-yun.com/v2`、`Embedding=text-embedding-v3 @ dashscope.aliyuncs.com/compatible-mode/v1`（1024 维）。Agnes `agnes-3.0-flash` 是现行需求目标但待 D 验证，故不作为默认；切换只需改根 `.env` 三行。
7. **安全**：`.env` / `.env.local` / `.venv` / `node_modules` 均被 `.gitignore` 忽略；模板里的 `aitalent_2026` 是隔离容器默认密码，README 明确要求生产环境修改；seed 账号 `hr/hr123456` 同样要求改。
8. **端口与容器名可隔离**：`MYSQL_PORT` / `MILVUS_PORT` / `MILVUS_METRICS_PORT` / `CONTAINER_PREFIX` / `COMPOSE_PROJECT_NAME` 均可由根 `.env` 或环境变量覆盖；容器名不能用 `COMPOSE_PROJECT_NAME` 插值（Compose 会自动把它设为目录名，导致默认容器名被改），改用 `CONTAINER_PREFIX`。
9. **前端启动不经 npm 参数**：`npm exec next dev -p <port>` 的 `-p` 会被 npm 吞掉，Next 会把端口当项目目录；改用 `node` 直接执行 `node_modules/next/dist/bin/next dev -p <port>`。后台进程用 `shell=False`，避免 Windows 下 `terminate()` 只杀 cmd 留下的孤儿进程。

## 5. 给客户的最短操作

1. 安装 Python 3.11+、Node.js 20+、Docker Desktop（并启动 Docker）。
2. `git clone <仓库>` → 进入目录。
3. Windows 双击 `scripts/A/bootstrap.cmd`；Linux/macOS 执行 `bash scripts/A/bootstrap.sh`。
4. 打开根 `.env` 填 `LLM_API_KEY`（和 `EMBEDDING_API_KEY`），保存后重跑一次；浏览器打开 http://localhost:3000，登录 `hr/hr123456`。

## 6. 已知限制 / 后续

- 默认占用宿主机 3306 / 19530 / 9091。若已被别的项目占用，在根 `.env` 指定 `MYSQL_PORT` / `MILVUS_PORT` / `MILVUS_METRICS_PORT` / `COMPOSE_PROJECT_NAME`，并配独立 `MYSQL_DB`、`MILVUS_COLLECTION`，bootstrap 会起一套完全隔离的容器；**不要**让脚本直接复用别的项目实例。
- `init_db.py` 用 `create_all(checkfirst=True)`，只建新表不 ALTER；表结构升级仍走 A 的迁移链（R-A04），本封装不改变这一约束。
- 若客户要求「连 Python/Node 都不装」，需要补一层全容器编排（新增 Dockerfile 与新 compose 路径），按 AGENTS.md §36 需用户明确授权并单独交付归属变更，本轮未做。
- MySQL 默认密码与 seed 账号是演示值，生产交付前必须替换；建议在交付包附一份「上线前改密清单」。
