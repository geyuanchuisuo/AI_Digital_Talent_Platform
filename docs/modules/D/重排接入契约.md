# 重排接入契约（D22）

> 版本：v1.0　|　日期：2026-11-11　|　维护：D　|　状态：接入框架就绪，等 B 的 F06 检索改造对接
> 对应需求：PRD D22　|　跟踪表：D22　|　代码：`backend/app/core/rerank_client.py`

本契约定义重排适配层的调用方式、降级策略与候选抽象。调用方（B 的人才检索主链）按此接入；D 侧只提供框架，不宣称检索已重排。

---

## 1. 调用入口

```python
from app.core.rerank_client import RerankCandidate, RerankOutcome, rank_candidates

out: RerankOutcome = rank_candidates(
    query="Python 后端工程师",
    candidates=[
        RerankCandidate(id="101", text="Python 后端，5 年 FastAPI", score=0.82),
        RerankCandidate(id="102", text="前端 React", score=0.71),
        RerankCandidate(id="103", text="算法 Milvus", score=0.65),
    ],
    mode=None,      # None → 读 settings.rerank_mode；也可显式 "off"/"api"/"local"
    top_n=None,     # 重排后截断；None → 不截断
)
```

## 2. 数据结构

### `RerankCandidate`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `str` | 候选唯一标识，用于回写检索结果（如 talent_profile_id 的字符串形式） |
| `text` | `str` | 参与重排打分的文本（如简历摘要、JD 文本） |
| `score` | `float` | 召回阶段分数（保留原值，不参与重排排序） |
| `rerank_score` | `float \| None` | 重排分；未重排时为 `None` |

### `RerankOutcome`

| 字段 | 类型 | 说明 |
|---|---|---|
| `candidates` | `list[RerankCandidate]` | 最终顺序的候选列表 |
| `reranked` | `bool` | `True` = 已按重排分降序；`False` = 降级为原序 |
| `error` | `str \| None` | 降级原因（仅 `reranked=False` 时非空） |

## 3. 模式与配置

| 模式 | 说明 | 关键配置 |
|---|---|---|
| `off` | 默认；不重排，召回序原样返回 | 无 |
| `api` | HTTP rerank 端点（百炼 gte-rerank / OpenAI 兼容 `/rerank`） | `RERANK_BASE_URL`、`RERANK_API_KEY`、`RERANK_MODEL`、`RERANK_TIMEOUT` |
| `local` | 进程内 CrossEncoder（bge-reranker-base 等） | `RERANK_LOCAL_MODEL_PATH`、`RERANK_LOCAL_DEVICE` |

- 模式由 `settings.rerank_mode` 控制；`rank_candidates(mode=...)` 显式参数优先。
- `api` 模式缺 `RERANK_BASE_URL` → 明确报错（不静默降级）。
- `local` 模式缺 `RERANK_LOCAL_MODEL_PATH` 或未装 `sentence-transformers` → 明确报错含安装指引。
- 非法模式值 → 明确报错。

## 4. 降级策略（核心契约）

**原则：保持候选集合不变，只改顺序；不静默重排。**

| 场景 | 行为 | `reranked` | `error` |
|---|---|---|---|
| `mode=off` | 原序返回 | `False` | `None` |
| 空候选 | 返回空列表 | `False` | `None` |
| 单候选 | 原序返回（重排无意义） | `False` | `None` |
| 重排调用失败（网络/超时/配置/HTTP 非 200） | 原序返回 | `False` | 失败原因 |
| 重排结果数量与候选不一致 | 原序返回 | `False` | `"重排结果数量与候选不一致"` |
| 成功 | 按重排分降序 | `True` | `None` |

- 调用方**必须**检查 `reranked` 字段；`False` 时不得宣称结果已重排。
- 降级不抛异常（`RerankError` 被捕获并转为 `error` 字段）；调用方无需 try/except。

## 5. 分数可比性

- 分数仅供**同一次召回内**排序。
- `api` 与 `local` 模式分制不同，**不可跨模式比较**。
- 召回分（`score`）与重排分（`rerank_score`）保留各自原值，不混合排序。

## 7. 验收对照

| 验收项 | 用例 |
|---|---|
| 三模式行为与配置一致 | `test_off_mode_returns_none_by_default` / `test_api_mode_missing_config_raises_clearly` / `test_local_mode_missing_path_or_package_raises_clearly` |
| 关闭模式零模型调用 | `test_rank_candidates_off_mode_returns_original`（httpx.post 被替换为 fail） |
| 失败/超时降级不改变候选集合 | `test_rank_candidates_failure_falls_back_to_original` / `test_rank_candidates_inconsistent_count_falls_back` |
| 成功重排排序正确 | `test_rank_candidates_success_sorted` |
| 候选集合完整性 | `test_rank_candidates_success_sorted`（集合相等断言） |
| 契约文档可被 B 直接消费 | 本文 |

## 8. 边界与不在本契约内

- 不改变召回数量与召回顺序（重排只改顺序）。
- 不做重排准确率评测（B 用评测集验证）。
- 不接 Vanna（D14）；重排与 NL2SQL 无依赖。
