## 1. 首个指标：`jobs.active` 活跃岗位数

| 项 | 值 |
|---|---|
| 口径 | `job_profiles.is_active=1` 且该行为其 `title` 的最新 `version`（A 交付 §1 原文） |
| SQL | `version = (SELECT MAX(version) FROM job_profiles j2 WHERE j2.title = jp.title)` 相关子查询 |
| 允许角色 | `admin`/`hr`（personal → 403 DENY_MESSAGE，不泄露存在性） |
| 数据源 | `ANALYTICS_DB_URL` 非空 → PgSQL 副本；空/连不上 → 降级主库 MySQL（结果带 `source` 字段，不静默） |
| 缓存 | data 类键 `jobs.active:v1`，TTL 300s（未配置 Redis = 无缓存直查） |
| 快照 | 每次计算（含命中）落 `analytics_query_snapshots` 一行（54 表基线，D_0003） |

## 2. 端点

- `GET /api/analytics/metrics/jobs/active` → `{metric_id, name, value, source, cache_hit, data_time, snapshot_id}`
- `GET /api/analytics/metrics/jobs/active/events` → SSE（`StreamingResponse` 实现，**未引入 sse-starlette**——T-D06 正式任务再评估）；事件 `progress(started)` → `progress(computed{value,source,cache_hit})` → `done{value,data_time,snapshot_id}`；鉴权先于流（403 不进流）；真实阶段回放，不虚构百分比。

## 3. 切片暴露的集成问题清单（T-D01b 验收③）

1. **redis.asyncio 跨事件循环崩溃**（已修复）：CacheClient 全局实例在多次 `asyncio.run` 的脚本/测试里报 "Event loop is closed"——已按运行循环重建底层连接（`client.py:_client`），回归测试 `test_client_rebinds_across_event_loops`（真实 Redis 6399）。FastAPI 单循环场景本就无恙。
2. **models 直连入口循环导入**（既有约束，登记）：`app.modules.analytics.models` 不能作为 import 入口（C 域同款纪律），消费方一律先 `import app.models` 或经包导入；uvicorn 路径无恙（deps 先加载 app.models）。
3. **mysql 双引号陷阱**（ETL 已修）：MySQL 默认 SQL 模式下 `"id"` 是字符串字面量——副本源查询必须反引号（etl_pgsql.py 已带回归）。
4. **前端测试基建**：jest-dom 未安装，断言用 `toBeTruthy()` 惯例（与既有页面测试一致）。
