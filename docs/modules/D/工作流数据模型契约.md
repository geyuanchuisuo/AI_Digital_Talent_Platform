## 1. 表清单与职责

| 表 | 职责 | 关键约束 |
|---|---|---|
| `workflow_definitions` | 流程定义 | `uk_workflow_definitions_code`（code 唯一，小写蛇形 ≤64） |
| `workflow_definition_versions` | 定义版本 | `uk_workflow_version`(definition_id, version)；status: draft→published→deprecated |
| `workflow_nodes` | 版本内节点 | `uk_workflow_node_key`(version_id, node_key)；node_type 白名单 |
| `workflow_edges` | 版本内连线 | `uk_workflow_edge`(version_id, source, target, branch)；branch 默认空串 |
| `workflow_runs` | 业务运行实例 | `uk_workflow_runs_thread`(thread_id)；**version_id 启动时钉死** |
| `workflow_run_steps` | 节点步骤记录 | `uk_workflow_step_attempt`(run_id, node_key, attempt) |

无物理外键（基线纪律）；归属一致性由 service 同事务保证。索引：versions(definition_id,status)、nodes/edges(version_id)、runs(status/definition_id)。

## 2. 版本生命周期与版本锁定（T-D14 验收① / T-D15 验收①②）

- 状态机：`draft →(submit)→ pending_review →(审核通过)→ published →(停用)→ deprecated`；驳回退回 draft（review_note 留审核意见，重新提交后覆盖为最近一次审核结论）；
- **版本锁定**：运行实例 `start_run` 时**钉死 version_id**（缺省取最新 published；draft/pending_review/deprecated 拒绝启动）；已发布/待审/废弃版本拒绝 `update_draft_version`（409 版本锁定）——改版 = 新建更高版本号草稿；发布版本节点/连线行永不修改；
- **回滚**：目标版本（published/deprecated）重新成为唯一发布版，其余 published 一并停用；运行中实例钉死自身 version_id 不受影响，新运行缺省即回滚目标；
- **权限口径（阶段 1）**：定义/版本查看、创建、改图、提交 = 管理侧（`can_view_all_persons`）；审核（通过/驳回）= 管理侧 + **四眼原则**（提交人不可自行审核发布，403，T-D15 验收②）；停用/回滚 = 管理侧。service 的 `publish_version`/`deprecate_version` 为内部原语（回滚/测试复用），router 只暴露受控路径；
- 引擎侧 thread_id → `workflow_engine_runs`（T-D04）+ 检查点，由 T-D17/T-D18 接线。

## 3. 节点白名单（验收②）

五类任务 + 人工审批（T-D17 落执行器；白名单外 422 拒绝入库，建版/落步骤两处把关）：

| node_type | 含义 |
|---|---|
| `profile_parse` | 档案解析 |
| `job_match` | 岗位匹配 |
| `assessment_analysis` | 测评分析 |
| `training_suggestion` | 培训建议 |
| `data_analysis` | 数据分析 |
| `human_approval` | 人工审批（等待态不被恢复/心跳重置，T-D04 语义） |

分支规则：仅 `human_approval` 出边可带 `branch`（必须 `approve`/`reject`）；其余节点出边 branch 为空串；自环/端点越界/重复连线/空图发布均拒绝。

## 4. 输入/输出引用（验收③）

**inputs_json**（节点输入引用数组，`as` 节点内唯一）：

```json
[
  {"as": "resume_id",  "from": {"kind": "trigger"}},
  {"as": "min_score",  "from": {"kind": "form_field", "field": "min_score"}},
  {"as": "profile",    "from": {"kind": "node_output", "node_key": "parse_1", "field": "profile_id"}},
  {"as": "threshold",  "from": {"kind": "literal", "value": 60}}
]
```

- `kind` 白名单：`trigger` / `form_field` / `node_output` / `literal`；未知字段/缺必填拒绝；
- `node_output` 允许指向同版本图内任意节点（前向引用合法，与声明顺序无关）。

**outputs_json**（节点输出声明，`as` 唯一）：`[{"as": "profile_id", "type": "int", "desc": "可选"}]`。

可审阅：`get_version_detail` 一次返回定义/版本/节点（含 position/config/inputs/outputs）/连线（含 branch/condition），T-D15 审核页与 T-D16 对账共用。

## 5. 运行与步骤

- `workflow_runs.status` 与引擎登记同状态机：running → (waiting | succeeded | failed)；waiting 仅人工推进；cancelled 供管理面；终态落 `finished_at`；
- `trigger_type`: manual / event / schedule（定时默认关闭，T-D18 启用 + 审计）；`trigger_ref` 留作事件幂等键；
- 步骤记录 (run, node_key, attempt) 唯一：同 attempt 重放幂等覆盖，重试记新 attempt——T-D18「失败阶段重试不重复生成已成功产物」的审计依据；skipped 供条件分支未走到时留痕。

## 5d. 节点执行器（T-D17，`app/modules/workflows/nodes/`）

- 状态形态：`RunState{trigger, form, vars}`；vars 按 node_key 命名空间累积（vars[key][as]）；输入引用四来源（REF_KINDS）由节点包装解析，缺目标如实 422；
- 执行器接线（**不自查他域表**）：profile_parse→`app.service.parse_service`（B，真实 LLM）；job_match→`app.service.match_service.create_batch`（A，建批落库，跑批归 TaskRunner，节点产出 batch_id）；assessment_analysis→`assessments.service.get_result`（C）；training_suggestion→`training.service.create_ai_draft`（C，真实 LLM）；data_analysis→`analytics.service.query_metric`（D，registry 角色白名单强制，越权 403 节点失败）；human_approval→langgraph interrupt（等待由检查点承载，任何恢复/心跳不重置）；
- 节点包装每节点落步骤 running→succeeded/failed（BizError 码随文本留痕）；审批挂起时步骤记 waiting（负载含 deadline）；
- 图构建：确定性（同版本同图）；图名 `wf_v{version_id}_{thread_id}` 防引擎编译缓存跨版本/跨运行串图（节点闭包持有本次运行 run_id/user_id，每次运行独立编译）；审批出边恰 approve/reject 条件路由；普通多出边须逐条 condition（`{from:{kind,node,field}, equals}`，不命中走无 condition 缺省边）；并行汇流一期不支持（422）；
- 运行编排：`run_service`（引擎单例 + 会话工厂可注入，测试替换）；手动触发一期，事件/定时触发归 T-D18；超时一期为恢复口墙钟拒绝（409），定时催办扫描归 T-D18。
