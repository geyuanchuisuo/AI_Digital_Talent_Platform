# 工作台契约（T-D22 管理员工作台）

版本：v1.0（2026-11-09）。需求依据：统一需求 V2.6 F09「管理员工作台显示岗位、档案、待复核、待评分、培训计划与人才缺口预警等真实数量，提供业务入口」；原 PRD 执行跟踪表 D19（D/A）。
范围：管理员工作台后端 + 前端一页。T-D23 个人工作台另立（AccountScope personal 侧，前置同一门禁体系）。

## 1. 端点

| 端点 | 说明 |
|---|---|
| GET `/api/ai-platform/admin-overview` | 六类数量卡片（管理侧；personal 403；实时查询无缓存） |

挂载于 T-D20 AI 中台既有 router（`/api/ai-platform` 前缀）；无新表、无迁移。

## 2. 六类口径（逐域授权依据，2026-11-09 核对）

| 卡片 | key | 口径 | 授权来源 |
|---|---|---|---|
| 活跃岗位 | `jobs` | `job_profiles` is_active=1 且 title 最新 version | A 指标口径交付 v0.2 §1（复用 T-D08 `compute_active_jobs` 同一实现） |
| 人才档案 | `profiles` | `talent_profiles.deleted_at IS NULL` 计数 | B 契约 §6「人才档案数 = 未删除 person_id 数」 |
| 待复核 | `reviews` | 三分项合计：①初筛 `screen_results` 有效结论（COALESCE(manual_verdict, verdict)）=pending；②匹配 `match_results.manual_verdict IS NULL`；③盘点 `inventory_reviews.status IN (draft, submitted)` | A v0.2 §2（H-A06 有效结论）/ §3；C F10 契约状态机 |
| 待评分 | `scoring` | `assessment_assignments.status = 'grading'` | C 契约状态机（交卷后存在未评分项；completed 不再计） |
| 培训计划 | `training` | `training_plans.status IN (draft, assigned)` | C 契约 §43 状态枚举全集 |
| 缺口预警 | `gaps` | 预警数 = gap>0 的需求行数；缺口 = headcount − HR 确认已录用（逐需求非负）；总缺口求和 | A v0.2 §7 权威公式（与 analytics `_GAP_SQL` 同口径） |

## 3. 响应形状

```json
{
  "role": "admin",
  "cards": {
    "jobs":       {"count": 0, "label": "活跃岗位", "caliber": "...", "entry": "/job-profiles"},
    "profiles":   {"count": 0, "label": "人才档案", "caliber": "...", "entry": "/talents"},
    "reviews":    {"count": 0, "label": "待复核", "caliber": "...", "entry": "/screen",
                   "breakdown": {"screen_pending": 0, "match_unmarked": 0, "inventory_pending": 0}},
    "scoring":    {"count": 0, "label": "待评分", "caliber": "...", "entry": "/assessments"},
    "training":   {"count": 0, "label": "培训计划", "caliber": "...", "entry": "/training"},
    "gaps":       {"count": 0, "label": "缺口预警", "caliber": "...", "entry": "/analytics",
                   "breakdown": {"demand_count": 0, "total_gap": 0, "note": "..."}}
  },
  "data_source": "replica | primary"
}
```

- `entry` 为前端业务入口路由（AppShell 菜单已含各页）。
- `data_source` 沿用 T-D02 数据源契约（副本优先、降级主库，不静默）。
- `data_source` 的岗位统计走 engine（analytics 同源）；其余五类走请求 session（同库）。

## 4. 边界（F09 验收对应）

- **验收①数字可回查**：每卡 `caliber` 字段注明口径；计数实现与各域交付口径同源（jobs/gaps 直接复用 T-D08 受控统计实现）。
- **验收②敏感不出现**：响应只含计数、口径字符串、入口路径——未公布成绩（AssessmentResult）、面试评价文本（interview_feedback）、人才池类别（inventory_talent_pools）均不进入任何字段；测试断言响应字符串化结果不含 `grid_cell`/`performance_score`/`nominated` 等敏感标识与人名。
- **验收③实时变化**：无缓存实时查询；测试断言插入业务行前后计数递增。
- 权限：`can_view_all_persons` 门禁（与 AI 中台 `_require_management` 单一实现）；personal/未知角色 403。

## 5. 前端

`frontend/src/app/(main)/dashboard/`：`api.ts`（类型 + fetch）+ `page.tsx`（六卡 + 分项 + 口径说明 + 点击跳转）+ `page.test.tsx`（vitest 4 例）。AppShell 菜单追加「工作台」项（跨模块说明同 T-D24 模式：A 维护的公共布局，菜单项一行 + 图标 import 一行，A 集成时复核）。

## 6. 测试

`tests/D/test_dashboard_t22.py` 12 例：personal 403（服务层 + HTTP 层）、空库全零、jobs 活跃口径（新版未启用不算）、档案软删排除、待复核三分项（有效结论/人工优先/盘点状态）、待评分仅 grading、培训计划状态集、缺口公式（headcount−确认已录用、逐需求非负、预警行数）、敏感内容不出现、计数随新增变化、入口与口径齐全。
