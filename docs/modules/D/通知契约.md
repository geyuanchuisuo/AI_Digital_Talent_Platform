## 2. notifications 表 schema（D 实现，迁移 D_0001）

```text
notifications:
  id BIGINT PK
  event_type VARCHAR(64) NOT NULL          -- 上表枚举
  ref_type VARCHAR(64) NOT NULL
  ref_id BIGINT NOT NULL
  actor_user_id BIGINT NULL                -- 触发者
  recipient_user_id BIGINT NOT NULL        -- 收件人
  payload_json JSON NULL                   -- 业务附加数据（最小化）
  idempotency_key VARCHAR(191) UNIQUE NOT NULL
  status VARCHAR(16) NOT NULL DEFAULT 'pending'   -- pending|sent|failed|read
  failure_reason VARCHAR(500) NULL
  created_at / sent_at / read_at DATETIME
```

## 3. 幂等键规则

`{event_type}:{ref_id}:{业务版本值}`；**多收件人事件**（due_reminder/overdue/extension_decided/workflow.*/talent.gap_alert）对每位收件人追加 `:r{recipient_user_id}`（v1.1）。逐类示例：

| event_type | 幂等键示例 |
|---|---|
| recruitment.stage_changed | `recruitment.stage_changed:{application_id}:{新阶段}:{变更序号}` |
| interview.invited/rescheduled/cancelled | `interview.{动作}:{round_id}:{计划时间}` |
| course.assigned | `course.assigned:{plan_item_id}` |
| course.enrollment_reviewed | `course.enrollment_reviewed:{enrollment_id}:{审核结果}` |
| course.waitlist_promoted | `course.waitlist_promoted:{session_id}:{user_id}:{序号}` |
| training.due_reminder | `training.due_reminder:{record_id}:{截止日期}:r{recipient_user_id}` |
| training.overdue | `training.overdue:{record_id}:r{recipient_user_id}` |
| training.extension_decided | `training.extension_decided:{record_id}:{新截止日期}:r{recipient_user_id}` |
| workflow.* | `workflow.{事件}:{run_id}:{步骤序号}:r{recipient_user_id}` |
| talent.gap_alert | `talent.gap_alert:{demand_id}:{缺口数}:r{recipient_user_id}` |

同键重复投递由 `idempotency_key` 唯一约束拦截，不产生第二条通知。

## 4. 权限继承与失败处理

- 收件人按 AccountScope 继承源对象权限：个人只收/只读本人通知；管理侧按 `can_view_all_persons` 范围查询。`get_account_scope` 是唯一授权入口（A 契约）。
- 投递失败：`status=failed` + `failure_reason`，走 D 的 TaskRunner 有限重试；重试不产生新通知记录。
- 已读/送达用 `read_at`/`sent_at` 时间戳，不另造状态机。

## 5. 生产方接口（已实现，`backend/app/modules/notifications/producers.py`）

A/C/D 按事件调用生产方函数（收件人由调用方按源对象权限解析后传入，多收件人传列表自动拆键）：

```python
# 例（A 域）：招聘阶段变化
producers.recruitment_stage_changed(db, application_id=…, recipient_user_id=…,
                                    new_external_stage="interviewing", change_seq=…,
                                    actor_user_id=…)
# 例（C 域）：必修课逾期（员工 + 直属经理多收件人）
producers.training_overdue(db, record_id=…, recipients=[employee_id, manager_id])
# 例（D 域）：工作流需人工介入
producers.workflow_event(db, event_type="workflow.needs_human", run_id=…,
                         recipients=[admin_id], step_no=…)
```

幂等键由生产方按 §3 规则自动构造；`service.emit()` 为底层入口（14 枚举白名单外 422 拒绝）。投递语义：站内落库即 sent；外部通道钩子 `deliver` 失败转 `failed`+reason，`retry_failed` 重发不新增记录。
