## 通用口径（全目录生效）

- 时间字段：本地时间 Asia/Shanghai；`created_at/updated_at` 由 MySQL 维护
- 权限：查询前按 `get_account_scope` 先过滤后聚合（阶段 1：admin/hr 全量、personal 仅本人；组织范围等 A 扩展契约）
- 软删/硬淘汰：`talent_profiles.deleted_at` 排除出「有效候选人」；`hard_fail=1` 平均分排除或单列
- 去重：结果表唯一键为准；跨批次聚合按 talent_profile_id 取最新批次（指标定义层决定）

## 卡片 1：岗位需求 / 人工推进 / 缺口（A 域，数据源已就绪）

| 字段 | 内容 |
|---|---|
| metric_id | `job.demand_progress_gap` |
| 来源表 | `project_demands`（headcount，**A_0005 已落地**）、`applications`（五阶段状态机枚举）、`screen_results`/`match_results`（人工标记） |
| 公式 | **（A v0.2 §7 复核版）**缺口 = headcount − 已录用数；已录用数 = applications 同 `job_profile_id` 且 `internal_stage='offer_accepted'` 且 `result_confirmed_by IS NOT NULL` 的人数（HR 确认口径，§12.3 人工推进不混入）；逐需求非负后求和。需求侧取 `status IN (open, in_progress)` |
| 时间字段 | project_demands.expected_start_date / created_at；applications 状态变更时间 |
| 去重键 | project_demands.id；applications 按 (job, talent_profile_id) 去重 |
| 允许参数/分组 | 按 department / project_group / 时间窗 / 五阶段 |
| 权限 | 管理侧全量；个人无此指标 |
| 返回 schema | {demand_total, promoted_count, gap_count, by_department[]} |
| 状态 | ✅ **已实现可查**（T-D08；数据源 M3 五表 + 五阶段枚举；公式按 A v0.2 复核；人工推进数不混入本卡——如需另立指标再登记）。多维：group_by=project_group（T-D10） |
