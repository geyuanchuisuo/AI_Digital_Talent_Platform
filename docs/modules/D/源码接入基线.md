# D 接入契约基线

日期：2026-11-06。由本次用户授权的集成整理，后续维护角色 D。状态：公共调用/调度源码已导入；指标、报告和固定流程待实现，本机运行未验证。

现有公共能力为 core/llm_client.py 的 chat_json/chat_text、独立 Embedding、Milvus 适配、prompts loader/schema 和 tasks/runner.py。业务 Prompt 内容归对应人：parse/profile 归 B、match 归 A；D 维护框架与校验协作，不单独改业务评分口径。Agnes 协议待验证，Embedding 不默认跟随对话供应商。

TaskRunner 当前嵌入 API lifespan，单 API worker；扫描 parse/screen/match 三类表。解析常见 pending/running/success/failed/duplicate_pending/cancelled，批次常见 pending/running/done/failed。目标统一任务状态需明确映射后再兼容，不批量替换来源枚举；业务 handlers 各归 A/B。现有注册执行不等于已有工作流实例、人工节点或通用五类任务。

一期新增白名单指标目录：metric_id、来源、公式、时间字段、去重键、允许参数/分组、权限和返回 schema。模型只解析指标与参数，后端受控统计；目录外问题和未授权明细明确拒绝。不执行模型原始 SQL，跨模块自由查询是二期候选。A/B/C 提供业务定义，D 不猜口径或按姓名联表。

一期 Agent 工作流范围按用户最新确认提升为完整工作流能力，沿用现有 TaskRunner 技术，不另建平行调度框架。两条流程“解析→档案→匹配”“测评完成→能力分析→培训草稿”作为首批业务流程，不是一期工作流能力上限；完整范围、人工节点、高影响副作用审批和发布治理由 A 对齐统一需求基线。触发方式支持手动与业务事件；定时触发属于能力范围，默认关闭，仅管理员配置启用并保留运行记录。首期不强制可视化画布，可先以表单或受控配置管理流程。现有 TaskRunner 仅扫描 parse/screen/match，不等于已支持完整工作流实例、人工节点或业务恢复。

D 管理层指标查询遵守服务端组织范围授权：集团管理层仅查获授权集团汇总，部门负责人仅查本人负责部门；HR/组织管理员可按职责授予跨部门范围。授权契约由 A 提供，D 不自行推断组织范围；契约和越权负例测试未落实前不开放管理层指标查询。
