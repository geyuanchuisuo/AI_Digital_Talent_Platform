# D 数字员工契约（T-D21，纯站内版 v1.0）

> 2026-11-10 用户确认方案一（纯站内）：一期不依赖任何 IM 平台凭据；企微凭据到位后仅补 adapter 与 oauth 绑定，无返工。依据 DEC-20261107-DLINE-CONFIRMED（数字员工一期仅入库+站内通知，不做站外外发）。

## 1. 表（D_0012 挂 D_0011，83 表基线）

| 表 | 用途 | 关键约束 |
|---|---|---|
| `member_im_accounts` | 成员 IM 账号绑定 | (user_id, channel) 唯一；channel ∈ {wecom, dingtalk, feishu}；source ∈ {manual, oauth}（一期 manual，无凭据形态） |
| `digital_tasks` | 三类只读任务运行 | idempotency_key 唯一（业务级幂等）；status ∈ {running, success, failed}；trigger ∈ {manual, schedule} |
| `digital_outbound_requests` | 站外外发请求（**只登记不执行**） | status ∈ {pending, approved, rejected, sent, cancelled}；**approved ≠ sent**，发送仅人工接管 |

## 2. 三类只读场景（一期封闭清单）

| task_type | 数据源（全部只读） | 产物 |
|---|---|---|
| `daily_report` | analytics_query_snapshots 近 24h | 快照计数 + 明细列表 |
| `resume_patrol` | parse_tasks / screen_batches 状态计数 | 队列 pending/failed/running 报告 |
| `todo_reminder` | workflow_runs(waiting) + 培训逾期（due_date < today 且未完成，口径与 C emit_overdue 同源） | 等待审批数 + 逾期数 |

执行路径：`run_task()` → collector 读数 → `digital_tasks` 落行 → 站内通知指定管理员（`notifications.producers.workflow_event`，event_type=`workflow.needs_human`——封闭清单内"需人工介入"口径；通知幂等键含 task id，同任务不重复通知）。

## 3. 权限

- 全部端点管理侧（`can_view_all_persons`，复用 `_require_management` 单一实现）；personal 403。
- `run_task`/`request_outbound`：service 层双门禁——actor 必传并校验管理侧；无 actor 但有 triggered_by → 403（防裸奔）；actor=None 且 triggered_by=None 仅留给受控系统调度（定时扫描器，已接线，见 §3.1）。
- 外发审批：管理侧 + 四眼（发起人自批 403）。

## 3.1 定时触发（schedule 接线，2026-11-11）

数字员工定时与工作流定时**相互独立**（各自开关/间隔/参与清单），共用 `WorkflowScheduleLoop.scan_once`（`workflows/schedule.py`）。

- 配置键（`sys_settings`，默认全部关闭/空）：
  - `workflow_digital_schedule_enabled`（"1" 才启用）
  - `workflow_digital_schedule_interval_minutes`（5–1440，默认 60）
  - `workflow_digital_schedule_task_types`（逗号分隔，按 `TASK_TYPES` 白名单过滤，非法项 422）
  - `workflow_digital_schedule_notify_admins`（逗号分隔正整数，去重）
- 到期判定：该场景最近一次 `trigger="schedule"` 的 `digital_tasks.created_at` 距今超过 interval 才执行（第二层限速）。
- 幂等：`idempotency_key = digital:schedule:{task_type}:{window_index}`，`window_index = now // (interval*60)`；同场景同周期窗口重入只落一行、只通知一次。
- 执行主体：`digital_service.run_task(..., trigger="schedule", actor=None, triggered_by=None)`（受控系统入口）；`scan_once` 返回值仅计本轮**真正新建**的任务 id。
- 审计：配置变更写 `sys_settings.updated_by`；任务行 `trigger=schedule` 且 `triggered_by` 为空。
- 管理侧接口：`GET/PUT /api/workflows/schedule-settings`（`digital` 嵌套对象；personal 403）。
- 红线不变：定时只触发三类只读场景，结果仅入库 + 站内通知，**无站外外发**。

## 4. 站外外发红线（验收②③核心）

1. **只登记不执行**：`request_outbound` 落 pending 行即返回，无任何发送副作用；通道未配置不影响登记。
2. **审批 ≠ 发送**：`decide_outbound` 通过后置 approved（仍非 sent）；`mark_outbound_sent` 仅 approved 可置 sent（人工接管回执），pending/rejected 一律 409。
3. **业务状态不动**：外发登记/审批/回执全程不触碰业务表（测试以 ScreenBatch 状态哨兵断言）。

## 5. API（/api/workflows/digital，main.py 注册）

- `GET/POST /im-accounts` 绑定列表/登记（POST 管理侧）
- `POST /tasks/run`、`GET /tasks`、`GET /tasks/{id}` 任务执行与查询
- `POST /outbound`、`GET /outbound` 外发登记与列表
- `POST /outbound/{id}/decision` 审批、`POST /outbound/{id}/mark-sent` 人工回执

## 6. 企微凭据到位后的升级路径（无返工）

- `source=oauth` 绑定流程（替换 manual 登记）；`IM_CHANNELS` 枚举不变。
- adapter 仅在 `mark_outbound_sent` 的人工动作之后、或未来二期批准自动外发时接入；一期枚举外通道（如 sms）422。
- todolist 原文「企微开放平台凭据」前置解除：凭据不再阻塞验收①②③。
