## 1. 组成与职责边界

| 组件 | 职责 |
|---|---|
| `saver.SQLAlchemyCheckpointSaver` | LangGraph 检查点持久化（表：`workflow_checkpoints` / `workflow_checkpoint_writes`，Core 层管理，**不入 ORM 基线**） |
| `models.WorkflowEngineRun` | 引擎运行实例登记（`workflow_engine_runs`，**ORM 基线 53 表**，D_0002 迁移） |
| `registry` | 状态流转函数 + `recover_registry()`（进程重启恢复） |
| `runner.WorkflowEngine` | 编译图 + invoke/resume/state + 登记联动；不理解业务节点语义 |

业务流程定义/版本/节点/审批/触发归 **T-D14**（`app/modules/workflows/`），本引擎是其执行底座。与 TaskRunner 关系：完全隔离（不同表/线程/恢复语义），TaskRunner 保留为解析/OCR 轻任务执行器。

## 2. 检查点存储（关键设计决策）

**未引入** `langgraph-checkpoint-sqlite/-postgres` 额外依赖——自实现 `BaseCheckpointSaver`（langgraph-checkpoint 4.3.1 抽象基类）+ 官方 `JsonPlusSerializer` 序列化，一套代码覆盖：

- SQLite 文件（测试/单机演示，`make_saver("sqlite:///path")`）
- MySQL（生产，`settings.database_url`；D_0002 迁移幂等建表）
- PostgreSQL（T-D02 副本就绪后可直接切换 URL）

序列化注意：`dumps_typed` 返回 (type, blob)，**type 必须原样存取**（json/msgpack 混用会 UnicodeDecodeError——单测覆盖）。langgraph 1.x 中断判定依据 invoke 返回值的 `__interrupt__` 键（`state.tasks[i].interrupt` 在此版本不填充）。

## 3. 人工等待/审批（验收②核心语义）

- 节点内调 langgraph `interrupt(payload)` → 引擎返回 `waiting` + 中断负载，检查点承载挂起位置；
- 恢复：`engine.resume(thread_id, value)`（`Command(resume=value)`），从中断点续跑；
- **等待态不被重置的保证**：①等待态只存在于检查点+登记行，无任何后台扫描触碰；②`recover_registry()` 白名单 `RECOVERABLE_STATUSES=("running",)`——孤儿 running 置 failed 可重试，waiting 明确排除（单测断言 waiting 行原样保留）；③TaskRunner 心跳/恢复只写 parse/screen/match 任务表。
- 引擎异常 → 运行实例置 failed（error 落库）可重试（回退边界，单测覆盖）。

## 4. 运行登记状态机

`running → (waiting | succeeded | failed)`；`waiting → resume → succeeded/failed`；`cancelled` 供管理面。`thread_id` 全局唯一（调用方 ULID/UUID），重复 start 同 thread_id 视为程序错误。

## 5. T-D14 接入方式（预告）

```python
engine = WorkflowEngine(make_saver(settings.database_url), registry_factory=SessionLocal)
result = engine.start("biz_flow", builder, {"resume_id": 1}, thread_id=ulid())
if result.status == "waiting":  # 发审批通知（notifications 生产方函数），等人工 resume
    ...
result = engine.resume("biz_flow", builder, thread_id, {"approved": True, "by": user_id})
```
