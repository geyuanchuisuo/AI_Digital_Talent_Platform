# B08 连续追问设计与计划

- MASTER / Anhoa / 653ae30工作区；用户要求继续下一部分，沿用只做B内独立工作的限制。
- 采用现有ProfileQuestion及JSON快照。POST /talents/{id}/questions新增可选follow_up_to（正整数）；既有客户端不传时行为兼容，不新增模型/列/迁移或公共改动。
- 父记录必须属于当前账号、当前人员且已结束（answered/insufficient_evidence）。不存在、他人记录、其他人员统一403；失败或running不能继续，返回409。追问固定使用父记录的档案版本，显式传不同版本返回409；新问题仍默认最新版本。
- 只读取直接上一轮的问题与回答用于指代消解，不把旧回答当事实依据，不无限遍历对话链。请求父记录及当前档案/版本授权均在检索和模型前核对；拆档后失效版本拒绝。每轮重新检索原文，引用编号重新生成，旧编号不可沿用。无新证据仍拒答。
- 模型输入区分当前question、previous_turn及本轮evidence；历史问题与回答均是不可信数据。检索查询可带父问题及实际引用片段以保留主题，但不将整个历史回答作为检索依据。审计保留follow_up_to、版本、上下文、实际检索query、Prompt版本及当前结果。
- 前端保留本轮回答，用“继续追问”选中父记录并显示固定版本；“新问题”清除追问关联。跟进失败保留父上下文供重试，切人/刷新索引清除关联，迟到响应不更新新对象。历史列表可提供追问入口，仍检查服务器权限，不信任浏览器传来的历史内容。
