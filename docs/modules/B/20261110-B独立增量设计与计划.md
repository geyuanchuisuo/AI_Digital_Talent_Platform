## 设计

1. 合并撤销复用人才修改审计表，不新增表或变更列。新合并在同一事务记录原字段、标签来源、解析关联与任务状态，保留操作者和合并版本。撤销需要当前全量管理授权、原因和可用的原始日志；锁住主档及关联记录，发现后续版本/事实变化则返回冲突，不覆盖其他修改。撤销生成新版本、回到待确认，原件及旧版本不删除；旧合并无日志不猜测还原。向量刷新失败明确标记，不回滚事实撤销。旧向量与问答片段清理失败必须阻止旧索引被当作有效结果。
2. 问答历史复用 ProfileQuestion。仅返回当前账号自己提交、当前仍有档案访问权的记录；按人员分页，展示原问题、当时档案版本、状态、时间、回答和引用，不开放模型原始返回、Prompt 或错误详情。历史只读，不用新版本重新生成旧答案。
3. 前端沿用 Ant Design：查重抽屉可切换待确认/已合并；新合并显示撤销入口及原因确认，失败保留状态。问答卡手动加载历史，切人/卸载忽略迟到响应。
4. B06 独立增量：版本化百级标签目录（技能/行业/级别/通用），只从授权档案的冻结原文匹配候选，保留命中词、原件、页码和待核实状态。目录大小不等于每人标签数量；原文提及不推断熟练程度或胜任力，人工编辑页面可查看候选依据后选用，现有手工确认保存流程不变。

## 方案选择与边界

采用既有审计和版本表，避免引入新公共注册。独立任务表与共享框架接入仍是可靠长任务的正式方案，暂不以 BackgroundTasks 或同步审计 running 行代替。撤销只支持日志完整且没有后续变更的新合并；跨模块历史快照保留，不改写 C/D 记录。历史跨账号共享不在本轮，减少敏感上下文暴露。
