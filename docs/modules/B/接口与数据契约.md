## 1. person_id 契约

### 1.1 定义

- `person_id` 直接使用现有 `talent_profiles.id`（整数主键，非 UUID、非字符串），不新增并行列，不另建第二套主档。
- `person_id` 在创建后终身不变，不因重新解析、人工修订、合并、恢复而改变。
- 删除采用软删除；软删除后 `person_id` 不复用、不重新分配给其他人。
- 对外只暴露 `person_id`，不按姓名、手机号或邮箱联表。
- 若后续引入外部来源标识，另建映射表，不修改现有 `person_id` 语义。

### 1.2 使用方

| 使用方 | 允许用途 | 禁止 |
|---|---|---|
| A | 匹配、流程编排、页面跳转 | 直接改档案字段 |
| C | 测评/面试/培训关联人员 | 自建人才主档、按姓名关联 |
| D | 报告、工作台汇总、指标统计 | 复制档案正文另存为主数据 |
| B | 解析、建档、检索、问答 | 向无权限账号返回人员 |

### 1.3 已确认

- 2026-11-07 用户确认：`person_id` 直接复用 `talent_profiles.id`，不建独立映射表。
- 外部来源 person 编号映射本期不做；以后需要时新增映射表，不改现有语义。
- 账号与 person_id 的绑定由 A 提供，B 不维护登录身份。

## 2. 档案版本契约

- 字段：`profile_version`，整数，从 1 开始，单调递增。
- 触发版本增加的动作：
  1. 重新解析并重建画像；
  2. 人工修订已确认字段；
  3. 合并重复人员；
  4. 恢复软删除档案（生成新版本，不复活旧版本号）；
  5. 重建画像向量不单独增加版本，只更新索引状态。
- 每个版本保存：`person_id`、`version`、结构化快照、字段证据快照、生成原因、操作者、创建时间。
- 历史问答、历史匹配和历史报告引用创建时的 `profile_version`，不随最新版本变化。
- 当前版本查询失败时明确报错，不回退到旧版本冒充最新。

### 4.3 证据结构

每个非缺失字段至少可关联一条证据；AI 归纳字段可标记 `llm_derived` 并保留依据片段。

```json
{
  "field_path": "educations.school",
  "file_id": 2048,
  "page_no": 1,
  "snippet": "原文片段",
  "source": "text",
  "confidence": 0.82,
  "review_status": "confirmed"
}
```

- `source`：`text` / `ocr` / `llm_derived` / `manual`。
- `confidence`：0–1；OCR 页质量单独记录，不用模型置信度替代。
- 片段必须可在原文件页码定位；无法定位的证据不得展示为可核对出处。

## 6. 指标口径（供 D 的 F07/F09）

| 指标 | 口径 | 去重键 | 分母/说明 |
|---|---|---|---|
| 解析成功数 | 指定时间窗内 `task_status=completed` | `parse_task_id` | 按任务完成时间统计 |
| 解析失败数 | `task_status=failed` | `parse_task_id` | 不含重复待处理 |

| 去重合并数 | 已确认合并的重复记录数 | 去重记录 ID | 保留、合并分别统计 |
| 授权范围 | 调用方可见 person 数 | `person_id` | 与全量人数分开 |

时间范围、时区、数据更新时间必须随指标返回；不得把语义召回 top-k 当作全量人数。
