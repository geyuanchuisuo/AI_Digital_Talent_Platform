## 2. 项目目标与材料依据

建设面向企业集团多部门与外部候选人的 AI 辅助人才平台，使授权人员完成招聘、测评、人才盘点、培训、知识问答与受控数据决策，使员工处理本人发展与学习，使候选人按岗位申请并查看获准对外进度。本机演示只是验证路径，不是完整交付边界。

业务范围包含统一人才主档、岗位/申请与匹配、自适应测评与人工面试/AI 面试间、独立盘点、课程与成长、授权知识问答、自由问数与报告、受控工作流及身份/组织/通知/审计公共能力。项目需求、JD、邀约、面试与缺口统计属于招聘闭环；评级及课程正式完成分别有独立人工确认和证据要求。

2026-11-05 的检查仅见文档；2026-11-06 已按用户授权原样导入 hhy_gycs_master ZIP 的后端、Next.js 前端与 Milvus 编排。源码提供 HR 招聘链路，尚未在本机运行验证。来源设计、旧日志和评测报告保存在 imports/hhy_gycs_master/，是历史证据，不覆盖本稿范围。原型数字仍为示意；来源测试结果不等于本次测试通过。

各模块须完成原始 PRD 的真实闭环：自适应测评（千人千卷）、岗位匹配、培训管控、授权 RAG、可视化 Agent/Skills 编排及自由问数报告；人工面试与 AI 面试间、盘点等细化与其并存，不降低基础。学习全流程管控（防挂机）按原需求纳入一期，人脸/生物识别启用前须完成隐私评审。不能以空页面或历史测试证明功能完成。

## 3. 角色与权限

### 3.1 管理员

管理岗位、人才需求、简历和档案；发起匹配；维护候选人及面试记录；创建题库、发布测评和查看成绩；维护课程、安排培训；上传知识文档；查看全局业务统计和任务日志。

一期不以一个演示管理员代表全部管理角色。按员工、候选人、HR/招聘、业务负责人/部门经理、面试人员、培训管理员/讲师、管理层、组织管理员和系统管理员的业务职责定义权限；一人可以有多职责，但每个动作必须按角色、组织/项目、对象关系和字段范围由服务端判定。系统/组织管理员不因技术身份默认获取全部简历与评价。集团管理层只看获授权汇总，部门负责人只看负责范围，跨部门授权需记录依据和期限；具体资源×动作×数据范围矩阵及敏感字段清单在需求冻结前审批。问数、导出、检索和后台任务不允许先开全量权限再补过滤。

### 3.2 员工/候选人

员工可查看本人获准档案与测评、个人发展建议、分配/报名课程及学习记录，并使用授权知识问答；内部评级、九宫格和人才池不可见。外部候选人仅维护本人资料和岗位申请、查看各申请对外进度及本人面试安排；内部匹配分与面试评价不可见，候选人阶段不分配员工培训。内部员工与外部候选人账号身份域隔离，同邮箱/手机号不自动共享权限；身份可以在入职时由授权人关联同一人才主档，历史来源和旧权限不因关联而扩张。用户不能修改请求 ID 读取他人数据。

### 3.3 登录

内部员工由 HR/组织管理员预先导入名单或邀请，验证手机号/邮箱后激活；不开放未经授权的员工自助注册。激活后可用验证码或平台企业账号密码登录，不要求客户 SSO 为强制前置。外部候选人经手机号/邮箱验证注册和登录，身份与员工隔离，并支持安全密码找回；验证码登录与密码/找回的账号绑定、验证和重置流程须在身份设计阶段定稿，不得以验证码登录为由删去已确认的找回能力。退出、停用、改岗与撤权须使旧会话在确定的时限内失效，认证失败提示不泄露账号存在性。预置账号仅作隔离测试数据，不代表完整登录交付。

## 4. 总体业务流程

招聘：岗位/需求与审批 → 已授权来源简历导入/复核 → 同一人才主档 → 独立岗位申请与输入快照 → 可解释的匹配建议 → 人工推进 → 多轮人工面试及内部反馈 → HR 确认最终对外结果。一个人申请多个岗位时，各申请进度独立。

员工发展：员工当前/目标岗位固定结构测评 → 可见成绩/能力差距 → 经理初评与 HR 确认盘点 → 个人发展计划 → 自主或指派培训、审批/候补 → 按课程条件完成 → 实践成果及经理评价、HR 审核后方能变更正式评级。课程反馈与学习完成分离。

并行公共流程：授权知识文档/人才档案问答、管理层自由问数和同快照报告、站内通知，以及可配置工作流的手动/业务事件触发与人工审批。三条业务链都须覆盖失败、重试、越权和人工接管，不用单一招聘链代替盘点或培训闭环。

## 5. 一期功能需求与验收

### F01 人才需求、岗位与招聘记录

管理员新建、编辑、查询人才需求，至少包含岗位、需求人数、说明和状态；维护岗位名称、职责、要求、技能与经验条件。人才需求按原需求保留项目（projects）、项目群（project_groups）与项目人才需求（project_demands）实体结构（design 数据库表设计），支持按项目/项目群归属和缺口统计。支持由 AI 根据岗位内容生成一份可编辑的 JD 草稿。

候选人可同时申请多个岗位；共用一份人才主档，但每条申请分别保存岗位/JD 版本、简历快照、内部阶段、匹配、邀约及面试引用，一条申请关闭不影响另一条。维护需求人数、组织/项目、优先级、时间与审批记录；岗位/申请修改保留版本。阶段迁移由有权人执行并记录原因；岗位关闭时在途申请的处置、候选人退出/爽约、终态重开、跨阶段跳转和面试官离职交接须分别确定处理人、合法迁移与通知边界，细化稿的示例状态不得直接当作正式枚举。对外仅展示本人该申请的“已提交、筛选中、待面试、待决定、已结束”和本人预约，内部评分与评价不外露。对外阶段映射已确认（2026-11-07）：内部新建/待筛选→“已提交”；筛选/匹配/复核中→“筛选中”；已邀约/安排面试→“待面试”；面试完成待决策→“待决定”；任何终态（录用/未通过/撤销/岗位关闭）→“已结束”。普通对外阶段随内部流程按此映射自动更新；终态及最终结果须 HR 确认后才发布。终态结果展示已确认（2026-11-07）：候选人终态显示“已结束”阶段及结果类别（录用/未录用），不展示原因、评分或内部评价。邀约时间/方式、取消/改期与通知失败留痕；面试邀约、改期、取消按已确认清单以独立站内事件通知本人，其余事件同样按 F09 封闭清单处理，邮件/短信等外部发送按客户需求另行启用，不默认连招聘平台。

验收：创建岗位后可重新打开修改，真实模型 JD 草稿可人工编辑保存；同人多岗位申请分别查看版本、状态、邀约与面试引用，一岗结束不改变另一岗。仅本申请对外阶段可见且按已确认五阶段映射更新，内部评价不可见，终态及最终结果在 HR 确认前不泄漏；终态仅显示结果类别（录用/未录用），无原因与内部评价内容。需求人数、人工推进人数和缺口写明统计口径；异常迁移、重复提交与越权请求均有可核对结果。

### F02 简历解析与人才档案

支持文本型 PDF、DOCX、图片（建议 JPG/PNG）和扫描版 PDF，一次选择多份文件批量上传，也允许只选择一份。图片和扫描页先识别文字，再由 AI 提取姓名、联系方式、学历、专业、技能、工作经历及年限；生成档案摘要、优势和待核实信息。保留原文件、识别文本和页码关联，供人工核对。

批次展示文件总数、等待数、处理中数、成功数和失败数；每份文件分别记录接收、解析及匹配状态与失败原因。上传时可选择目标岗位，使用预置流程衔接解析与匹配；未选择岗位时先形成档案，再由管理员选择岗位运行匹配。单份失败不回滚整批，支持仅重试失败项，解析成功但匹配失败时只重试匹配。相同请求重试不重复创建成功结果。

文件数量、大小和任务并发采用可配置上限，在上传前显示并校验；具体数值按本机能力验证后确定，不承诺无限批量或全部同时执行。部分文件接收失败时明确返回逐份结果，已接收文件继续处理。原文件记录来源、上传人、时间、文件标识和处理状态；不支持、损坏或经安全检查发现恶意内容的文件不伪装成功；文件类型校验、恶意内容处置与安全存储策略由安全负责人审批，受理失败不影响已受理文件。上传、下载、批量导出分别执行服务端授权；数据保留期限及告知依据待业务/安全确认。

提供档案列表、关键词搜索、语义化自然语言检索、详情与人工修正。档案显示原文依据，缺失字段为空或标记待核实。智能查重与合并属于原始必达能力（2026-11-07 改回）：自动识别按相似度分层提供建议，高置信自动合并、中置信转授权人确认，支持追溯与撤销。

任务展示等待、处理中、成功或失败，失败显示可理解的原因并支持手动重试。文本型 PDF 直接提取文字；扫描页和图片进入文字识别流程，混合 PDF 按页处理。无有效文字、损坏、加密或无法识别的文件给出具体提示，不返回虚构档案。无法可靠识别的字段标记待核实，支持人工修正。

验收：文本型 PDF、DOCX、图片及扫描版 PDF 各至少一份样例能形成真实档案；一批混合正常与错误文件上传后，正常项可完成解析及已选择岗位的匹配，错误项单独提示并可重试；批次计数与逐项状态一致；人工修改持久化；识别或模型失败不会显示成功；重试不会产生多份相同任务结果；识别原文与 AI 生成内容能区分。

整合补充：人才主档使用稳定 `person_id`；基本信息、经历、技能标签、画像摘要和能力快照保留来源及版本，标签体系按原需求支持向量级百级标签画像。人工修订记录修改人、时间、修改前后值；后续自动解析不得无提示覆盖人工确认值。智能查重合并按相似度分层：高置信自动合并、中置信人工确认，同名不直接判同人；自动合并保留原件、冲突字段记录、操作历史与可撤销关联，误合并由授权人撤销。档案删除建议可恢复软删，历史匹配与报告保留当时合法快照；更正、撤回、删除、停止处理分别处理原件、索引、缓存、下游和备份，依法保留期限及执行时限待业务/安全负责人确定。

### F03 岗位匹配与复核

管理员选择岗位及候选人，发起单人或所选名单匹配，查看 0–100 分、分项说明、符合项、不符合项及待核实信息。结果支持按岗位筛选和分数排序。

已确认一期采用 AI 综合评分：模型分析岗位与档案，给出 0–100 分、匹配依据和不足；后台校验分值范围和输出字段，保存所用岗位、档案、提示词版本及模型返回结果。重复评分可能存在波动，页面展示已保存结果，刷新不触发重新评分。不得将模型自报的“准确率”作为实际准确率。

按岗位配置分数线，系统保存分数及相对阈值的**内部参考标签**；达到阈值（含等于）与低于阈值的判定口径写清楚，具体阈值由管理员配置，不设置来源示例默认值。内部标签不得称作最终“通过/淘汰”、自动隐藏候选人、改变申请阶段或自动对外发布。评分失败单独显示，不计为不满足条件；HR/招聘人员人工决定是否推进，结果与理由和评分分开留痕。

人工复核记录待复核、建议进入下一步或暂不推进及备注；评分、内部达线参考标签和招聘决定分开保存。岗位或档案变更后创建新轮结果，保留旧输入版本与人工意见。硬条件或分数线不符合者仍显示不符项与资料缺口，不自动关闭申请或对外披露评分。

验收：至少两份档案对同一岗位生成有差异、有依据的匹配结果；缺失显示待核实，按岗位分数线标注内部参考结果并保留人工决定；硬条件不符者仍显示，低分不自动淘汰或更新对外阶段；复核状态刷新后保留，失败可重试。

整合补充：批量匹配开始时保存岗位版本、分数线及本批人员名单和档案输入快照；重试只补失败项，不重新圈选新增人员。需要使用修改后的岗位/档案时创建新一轮计算。语义相似度不等于业务匹配分，不强制加入 0.7/0.3 或 40/30/15/15 的公式。明确技能时避免把 Java 当作 JavaScript、把 C 当作 C++；缺失证据不直接判为不满足。年龄、性别不参与本版岗位评分。

岗位空缺预警与储备推荐（2026-11-07 按原需求 PRD §2.3 与原型改回）：按岗位需求人数与在库匹配结果生成岗位空缺预警，并向授权人推荐储备人才名单；系统可起草邀约，但外发与推进仍经人工确认，与本章人工决策原则一致。

### F04 智能测评与能力分析

管理员维护经确认题库，题目支持单选与简答，按岗位、专业/通用维度、知识点及难度标记；AI 出题和评分说明须经管理员审核后入库。招聘测评依据本次应聘岗位，员工测评依据当前岗位或管理员指定目标岗位；分别保存用途、方案与结果。管理员为每次测评配置固定总题量、维度权重（合计 100%）及**总分线**，不设置维度单独淘汰线；系统自动分配维度题量、覆盖选定维度，题量不足时阻止发布并提示缺口。

两类测评均在发布时冻结岗位方案、题库及答案版本、维度、题量边界、选题/难度策略和评分说明；方案冻结的是题库版本、选题与难度策略、评分标准和结束规则，不提前冻结每人的全部题目；须根据已答表现或经批准的自适应策略调整后续内容并留痕，有限随机抽题不得冒称自适应。题库不足或总题量无法覆盖全部维度时提示并阻止发布；自适应已属基础必达，题库不足须按明确规则停止/补库，不得伪称已完成。管理员可按岗位选用固定结构组卷作异常兜底，两种模式均不得在考试中途静默换卷。

个人端逐题保存答案并支持刷新恢复；单选按标准答案计分，简答由可用模型按说明真实评分，模型失败独立留待重试，不能计作零分。交卷幂等，未答题提示后依确认规则处理；未作答题的标准答案和评分细则不提前返回。各维度折算百分制，按配置权重合成总分，用未舍入值与总分线比较；笔试分数仅作辅助，不能自动关闭招聘申请。

已完成的试卷、作答、评分、复核与公布状态保留版本。管理员主观题修分须记原分、理由、修改人和时间并重算结果；招聘成绩经管理员确认具体结果版本后本人可见，员工成绩在评分完成后本人可见。题目答案是否开放与成绩公开分开管理，错题/复习事项引用原答题快照；是否提供可调整、完成或取消的独立复习计划，及答案/解析开放时点、题目版权与使用范围须单独审批，不能从错题清单推断复习计划已纳入一期。复测新增记录，不覆盖首次成绩。

一期支持**多轮人工面试与 AI 面试间**（按原需求 PRD §2.2 于 2026-11-07 改回）：人工面试各轮保存岗位/申请、时间、方式、面试人员、状态与修改历史，面试官记录事实依据、优势、不足和推进建议，不另计面试总分；AI 面试间承担在线考试与结构化问答的组织与记录，AI 自动评判、音视频情绪推断涉及个人信息处理的，须先完成告知授权与隐私评审后启用，未经批准不自动作录用决定。反馈仅授权管理员及对应面试人员可见，候选人仅见本人安排与经确认公开的申请阶段。

验收：招聘/员工测评在同岗位同策略版本下验证可解释的不同选题路径，答对/答错或策略输入变化确实影响后续选题，并保存输入与理由；总分线可人工复算，等于阈值处理正确；刷新和重复交卷不丢失/重复评分，模型失败不冒充低分。招聘成绩确认前本人不可见、员工成绩评分完成后仅本人可见；另账号访问被拒。人工面试可新增多轮并追溯改期/取消、授权人保存反馈；候选人不能读取内部评价。

### F05 培训计划、课程参与与成长记录

培训管理员维护有版本的真实课程及按课程配置的完成条件（可含学习进度、线下出勤、测验通过）；培训计划仅分配给在职员工。基于获授权的岗位、测评能力差距及个人发展目标生成可编辑课程推荐和依据；课程缺口须说明，不生成假课程，推荐不自动报名、分配或改变盘点结果。

培训管理员或部门经理可指派课程并设必修，员工可自主报名。普通课程由培训管理员配置免审批或直属经理审批，涉及费用或占用工作时间再由培训管理员复核。需审批的申请临时占位，通过转正式占用，拒绝/撤回释放；名额满时按序候补，有空位通知下一位，员工 24 小时内确认，超时通知下位，确认仍走课程审批规则，不自动报名。开课前员工可取消自选课程并释放名额；必修由指派人/管理员处理；开课后退出需管理员审核并记原因。占位超时、并发容量和审批补偿须在详细设计定稿。

个人学习进度与**正式课程完成**分别保存：员工可记录未开始/学习中/自报完成及备注，正式完成仅在满足课程所配置条件后记入，不因打开页面或在线时长判定。必修逾期时站内通知员工及直属经理，培训管理员看到逾期；管理员延期须保存原因、新旧截止日期及既有逾期历史，不自动扣绩效或调整盘点。培训完成仅生成培训事实，正式能力评级需要员工实践成果、经理评价及负责范围 HR 审核后更新。

课程结束后，仅有该期次出勤的员工可自愿评价课程与讲师（各 1–5 分），评价非完成条件。结束后 7 天内可提交、修改、撤回，之后本人仍可查看但不能更改；同员工对同课程跨期仅计一份有效反馈。少于 5 份不展示课程/讲师整体汇总，文字只展示有至少 5 份支持的主题归纳，绝不向讲师/部门经理开放单条原文或逐条公开回复；培训管理员可发布统一改进说明。评分统计口径已确认（2026-11-07）：反馈跨期累计并合并不同期次与不同讲师，仅展示课程整体与讲师整体两个匿名汇总，不拆分期次、小群体或单个讲师，不发布某位讲师的个人评分，也不以小群体拆分推断个人。

成长记录按时间追加实际测评、面试、培训与经 HR 确认的能力事件，保留数据来源/版本；无数据标未评估，不用自报学习进度冒充正式完成或能力提升。验收覆盖审批中/拒绝/撤回容量、候补确认超时、完成条件、延期审计、匿名样本门槛、跨期跨讲师仅课程整体与讲师整体汇总及越权反例；复测不覆盖历史。防挂机与学习过程管控为原始必达，须定义有效学习证据和服务端校验；人脸/生物识别不是原始必达的唯一实现方式，不自动引入，采集启用前须完成隐私评估并提供替代路径。

### F05a 人才盘点与个人发展（独立业务闭环，沿用 F01–F09 编号；C 侧契约与归属登记使用编号 F10，指同一闭环，冻结前统一采用 F10）

岗位技能、工作/项目经历、测评能力、培训成长、员工自评和经理评价组成盘点依据；能力维度按岗位族留版本。五档能力评级与绩效×潜力九宫格仅用于内部分析：绩效取最近经 HR 确认的已完成周期，缺失时标“待评估”，不得臆补进入九宫格；潜力由经理依据统一维度提出初评，记录可复核事实，负责范围 HR 审核确认后生效；维度建议包括学习敏捷性、适应变化、承担复杂职责的意愿与能力、跨团队影响力，岗位族行为标准须 HR 批准。年度复核记录周期、责任人和逾期状态，明显变化提前复核记录触发原因；两类复核经 HR 确认后均生成新版本，保留原结果、人才池类别、确认人和时间，不自动批准晋升/调薪。

人才池分类及进出标准由 HR 配置审批；经理可提议，负责范围 HR 确认后生效并留进出原因。员工仅查看本人的可公开能力评估、经理反馈和发展建议，可提出异议/资料更正，由经理复核、HR 确认后更新正式版本；员工不可见内部评级、九宫格、人才池及进出建议/结果，也不收到相关通知。经理只查看负责部门当前盘点及人才池类别与原因，HR 按授权范围查看历史；系统/组织管理员不默认有业务明细权。

普通员工和部门经理不可导出个人盘点明细；经理可看/导出本部门匿名汇总，任一统计项样本少于 5 人隐藏；授权 HR 明细导出按组织/字段范围校验并记审计。经理可发起汇总疑问，HR 审核是否更正正式数据，申请本身不直接改结果。能力差距可转员工与经理共同制定的个人发展计划，目标、行动、期限和复盘留痕，但不自动报名课程或发起人事审批。

五档名称、绩效口径、九宫格阈值/象限、潜力维度及岗位族行为标准、人才池准入退出、年度周期、提前复核触发条件和异议时限仍待 HR/业务负责人批准，不使用示意数值。验收包含缺绩效不得入格、经理初评未审不得生效、年度复核责任/逾期与提前复核原因可追溯、部门/员工越权拒绝、小于 5 人的匿名项隐藏、导出审计与历史版本不覆盖。

### F06 RAG 知识库与问答

知识管理员按授权上传、更新、停用文本型 PDF、DOCX 或 TXT，保存文档来源、版本、可访问范围、处理状态与片段/索引关系；撤权或删除后须在约定时限内停止新检索召回，失败可定位阶段并安全重试。文档所有人、过期与内容审批责任须在公共权限契约确认。

用户提问时先检索可访问片段，再将片段与问题发送模型生成答案。回答展示文档名称和引用片段；没有足够依据时明确说明。支持重新处理及删除文档，删除后不再召回。

知识片段先按调用者授权范围过滤，再送入模型；员工和候选人端不得检索受限知识，引用也须在展示时重查访问权与版本。公共/管理员知识是最低分类，实际组织/项目范围按权限矩阵细化。问答与通用 AI 聊天分开，不以模型常识冒充知识来源；无足够依据时拒答或说明覆盖不足，模型不可用时明确提示。

已确认增加人才档案问答。管理员可选择一名或多名候选人作为提问范围，询问项目经验、技能及条件符合情况，或在所选人员中做比较；个人端只能查询自己的档案。回答须关联人员 ID、档案版本和原文片段或字段依据，不能将不同人的经历混用。姓名相同或提问对象不明确时要求明确对象。

档案修改后使用新版本回答，历史问答保留原版本引用；删除或取消访问的档案不再参与新检索。查询前按调用者权限限制片段，返回前再次核对引用版本和当前授权，禁止将越权内容送入模型上下文；历史问答只在原有授权范围内可见。无记录不能推断为没有能力，应说明资料不足。批量问题显示本次查询范围；涉及精确人数或完整名单时，应使用所选档案的实际字段或逐项核对，不将少量召回结果当作全量统计。若部分档案解析未完成或处理失败，必须提示覆盖不完整。

人才档案问答与制度问答提供明确的数据范围选择；基于人员事实的解释由档案问答处理，跨测评、培训等结构化统计由 F07 指标问数处理，两者保留对应依据。

知识图谱（Neo4j，原需求指定，2026-11-07 确认补写）：实体覆盖人才、技能、岗位、制度与证书；关系在档案确认与知识文档入库后由系统自动抽取写入，服务 RAG 溯源与技能推荐；图谱数据模型、抽取失败处理与图谱/关系库双写一致性在设计中冻结。抽取质量一期验收门槛（2026-11-07 三次确认）：抽取关系人工抽检准确率≥85% 且 RAG 溯源引用可定位，数值可在评测集冻结时调整。

验收：上传一份文档后回答其中的问题并显示可核对的出处；无关问题不编造依据；个人端无法召回受限文档；模型失败有提示。单人档案问题能定位项目经验原文；批量问题返回人员及各自依据，不混淆同名人员，不将未覆盖档案视为不符合；个人端不能通过指定他人 ID 查询其档案。

### F07 自由自然语言问数、多维分析与报告

面向获授权管理层提供**口语化自由问数**：自然语言数据查询、自动多维分析、自动出图、一键生成 Word/PDF 报告与智能决策建议，行/字段级权限随角色数据范围联动。白名单指标目录保留为受控查询第一层：每个指标明确 metric_id、名称、数据来源、计算口径、时间字段、去重键、允许筛选/分组、组织/字段权限和返回字段，首批覆盖岗位需求/人工推进/缺口、解析成功失败、匹配参考达线、已完成测评通过率、课程正式完成率及单列的学习自报进度；目录由 A/B/C 数据维护人登记口径、D 汇总冻结，联调前未登记指标不得进入白名单快速路径。首批目录冻结为上述六类；盘点（F10）域与知识域指标二期追加。

自然语言问数必须覆盖授权数据范围内的自由组合与多维分析，Vanna.ai 作为原始指定组件落地；已登记指标目录用于复用统计口径与校验，不是最终可问范围上限。执行方案必须同时满足 ORM 全对象映射、禁止裸 SQL、组织/行/字段授权及可追溯要求；不得将模型输出的原始 SQL 直接执行。NL2SQL 引擎一期严格采用 Vanna.ai 本地部署（挂接已选大模型），不引入替代或自研等价引擎；其生成的候选 SQL 一律经 SQL 校验器（表/字段/行权限、只读与行数限制检查、必要改写）后由受控执行引擎运行，禁止直连执行或绕过 ORM 授权边界。校验器默认参数（2026-11-07 确认）：执行超时 30 秒、单次返回上限 1000 行，均可配置。自由问数与报表查询运行在 PostgreSQL 只读副本（分析宽表）上，业务主库仍为 MySQL；Redis 承担缓存、会话与接口限流。PgSQL 只读副本同步一期采用定时 ETL 批同步（分钟级延迟），二期按需升级 CDC 实时同步（2026-11-07 确认）。Redis 故障时降级为直查库并退化限流策略，不阻塞核心业务（2026-11-07 确认）。跨模块问数经各域明确的授权数据/结果契约获取输入，不使未公布招聘成绩、内部面试反馈或人才池信息进入统计与解读；歧义澄清、无数据、非法或越权请求分别返回，不能伪造结果。管理层入口在授权契约和越权负例验证前不开放。

返回指标定义、筛选范围、数据更新时间、实际表格、适用图表和解读；零分母显示暂无数据。查询与导出重新校验权限，记录操作者、查询意图/参数及结果快照。问数结果提供反馈/纠错入口：用户可对单次问数结果标记不准确并附说明，反馈关联该次查询快照（指标、参数、数据时间）写入审计，用于纠错与模型/提示词改进；反馈不改变当次结果，也不自动修改统计数据（2026-11-07 确认）。测评未通过、未参加及评分失败分别统计；培训自报进度与依据课程条件判定的正式完成率分开计算，均不伪称经过有效学时证明。

支持从同一已保存分析快照生成 DOCX 和 PDF，包含问题、指标定义、参数、数据时间、表格/图表和解读，不在导出时重新问数。无数据、数据截断或解读失败均如实显示，两格式中文及图表可读。导出前重新验证调用者对快照和原始数据范围的权限，记录导出操作者、范围、时间与结果；AI 解读须区分实际统计事实和推断，不把相关关系描述为因果关系。

验收：实际指标目录至少覆盖招聘、盘点与测评/培训等已批准域，验证允许的组织范围、筛选和分组；与授权范围内人工核算一致。跨模块自由组合查询属于基础必达，须在可授权的数据模型范围验证多维组合、歧义澄清、非法请求拒绝与结果正确性，不允许绕过行/字段授权或执行裸 SQL；越权表/字段/行查询被拦截，无法安全映射的请求被拒答，模型不可用时明确提示，不返回缓存示例或伪造结果。另检查空数据、零分母与模型失败。DOCX/PDF 来自同一快照并可正常打开。

### F08 受控 Agent 工作流与任务

一期具备可配置、可运行的 Agent 工作流能力，不限于两条硬编码流程，也不允许执行任意代码或未经批准的外部副作用。授权人员须能通过界面以受控表单/模板创建、修改、检查和提交流程定义，管理员审核发布、停用及回滚；不能把仅能修改后台配置文件当成已具备业务人员可配置能力。节点采用批准的能力白名单、明确输入/输出与调用者权限。执行覆盖顺序、分支与条件、人工等待/审批、手动及业务事件触发、状态追踪、超时、有限重试、取消、重启恢复和版本锁定；定时触发属于能力范围但默认关闭，仅管理员显式启用并保存配置/运行审计。可视化编排属于基础必达，须落实流程节点与连线的交互式配置和运行追踪；具体画布/交互方案在设计中冻结，纯后台文件或表单不能替代原始编排要求。数字员工与成员 IM 账号管理按原需求纳入一期（2026-11-07 改回，PRD §2.7/§2.8），外发与业务副作用仍经授权并按批准规则人工确认。

首批业务流程是“简历解析→档案生成→岗位匹配”和“员工测评完成→能力分析→培训建议草稿”；招聘测评不生成候选人培训，草稿不自动分配。外部发送、招聘/人才/培训状态变更等高影响节点须按对象授权及已批准规则等待人工确认。Agent/模型只能调用受控业务服务，不能绕开权限层直接操作数据库。保存不可变流程/模型/Prompt 版本、步骤输入输出引用、耗时、尝试次数、失败阶段及责任人；失败重试不得重复生成已成功业务结果。

工程细化（2026-11-07 确认）：流程定义、版本、节点及连线为可审阅的落库数据；一期节点白名单覆盖档案解析、岗位匹配、测评分析、培训建议、数据分析五类任务节点与人工审批节点。运行实例逐节点记录输入/输出引用、状态、耗时、尝试次数、失败阶段与责任人。人工等待/审批中的实例处于独立等待状态，不得被任务调度的心跳或启动恢复机制自动重置、重跑或判为失败；等待超时按流程定义转催办、失败或人工接管。业务事件触发仅限已按公共事件契约登记的事件，未登记事件不得触发流程。执行引擎采用 LangGraph 实装（有状态图与检查点恢复，支撑人工等待状态与断点续跑）；现有单进程 TaskRunner 降级保留，负责简历解析、OCR 等轻量任务执行。首批业务事件登记：简历解析成功→自动触发匹配流程；测评提交→能力分析→培训建议草稿；知识文档入库→索引更新；其余事件二期追加。

AI 中台管理面（2026-11-07 按原需求 PRD §2.7 与原型“Agent 编排中心”改回）：智能体注册、发布、退役与运行看板，模型供应商管理（多供应商接入、启停与密钥配置，密钥仅本地安全配置读取），以及任务调度管理页纳入一期，与上方受控工作流共用版本、审批与审计框架。数字员工/机器人与成员 IM 账号管理按原需求同步纳入（2026-11-07 改回），仅自动整理/只读任务可直接运行，对外发送与业务状态变更须审批、幂等、限速并可人工接管。一期通过私有化部署的 Dify 承载可视化编排与 Agent 中台管控（编排画布、应用发布、模型供应商管理），自研 agent_management/agent_publish/agent_workflow/model_provider 模块作为其 API 对接层与业务数据落库，不另造第三套编排；Dify 采用私有化社区版并锁定版本，其许可对商用/多租户的限制条款在选型评审时核对（2026-11-07 确认）。Skills 可编排组件库（原需求必达）：组件 schema=提示词模板+参数 JSON Schema+工具绑定+输出解析器，支持创建、审核、版本化、发布与在编排节点中引用，复用行为进入运行审计；一期仅内部组件库，组件市场化按原需求排在后续阶段（2026-11-07 确认）。AI 中台管理矩阵覆盖：模型供应商配置与启停、Prompt 版本库、流程发布/回滚审批、调用日志与用量统计、错误率看板。IM 对接目标确定为企业微信；首批数字员工场景为数据日报整理、简历队列巡检、待办提醒三类只读任务，其余场景二期评估；数字员工一期结果仅入库并通过站内通知报送指定管理员，不做站外外发（2026-11-07 确认）。

五类任务（档案解析、岗位匹配、测评分析、培训建议、数据分析）共用模型调用/状态框架，但不能以原有 parse/screen/match runner 冒充完整引擎。验收除两条首批流程的真实上下游输入外，还须分别覆盖分支条件、人工等待/审批、版本发布/回滚、事件触发、定时默认关闭及授权启用、失败/重试/取消/恢复与越权拒绝；中断或依赖失败不能显示为成功。

### F09 工作台与系统基础

管理员工作台显示岗位、档案、待复核、待评分、培训计划与人才缺口预警等真实数量，提供业务入口；个人工作台显示自己的待测评、培训和近期结果。工作台与报告统计一律经各域授权结果服务或公开契约读取，不直连其他模块业务表；未公布成绩、内部面试反馈与人才池信息不得进入任何统计。

基础能力包含模型配置检查、业务错误提示、必要操作日志、AI 调用状态、站内通知与本地/客户部署说明。站内通知一期事件清单为封闭清单（2026-11-07 用户确认）：招聘阶段变化；面试邀约、面试改期、面试取消（各自独立事件）；课程指派；报名审批结果；候补递补；必修课到期提醒；必修课逾期与延期；Agent 审批待办；Agent 运行失败及需人工介入；人才缺口预警（2026-11-07 二次确认追加为第 12 类，通知管理员与业务负责人）。清单外事件一期不发送站内通知，新增事件须另行批准。接收者必须继承源对象权限，发送留幂等键、状态与失败重试，不能向员工泄露人才池进出或向讲师发送匿名单条反馈。邮件、短信、企业微信等外部渠道仅在客户确认渠道及授权后启用。密钥不返回浏览器、不写入日志；日志最小化记录执行信息与必要审计。

验收：切换账号后工作台与可见数据正确；新增业务数据后数量随之变化；重启系统后原有数据仍在；工作台数字可回查业务记录核对，未公开数据不出现在统计；清单内事件按收件人权限送达且同一事件重复触发不重复通知，清单外事件不产生站内通知。

## 6. 数据对象与关联

至少保存内部/候选账号及验证、组织与授权、项目/项目群与项目人才需求、岗位与需求、在职员工花名册与任职记录、简历原件/解析及版本化人才主档、多岗位独立申请、匹配及人工决策、固定试卷/答案/成绩与公开版本、多轮人工面试、绩效周期/潜力初评与 HR 确认/盘点历史/人才池/发展计划、课程/期次/报名审批/名额候补/完成证据/匿名反馈、知识文档与引用、指标快照与报告、工作流定义/版本/节点运行/人工审批、站内通知及操作审计。仅源文件/索引与报告实际产物按授权保存，不由数据清单宣称已有库表。

关联链路保持统一的人员 ID，个人账号绑定人员档案；题目和岗位变更不修改已完成答卷及历史匹配的输入快照。身份关联不得依赖姓名相同来判断。

## 7. 实现建议与运行要求

已有源码采用 Next.js + React + Ant Design、FastAPI + SQLAlchemy + MySQL 及本地存储，TaskRunner 当前只在单 API 进程执行三类旧任务；这是实施输入而非未来架构的批准约束。先按已批准需求明确身份/组织授权、人才主档、任务与流程、通知/审计、版本快照、数据迁移等公共能力，再评估现有组件复用与改造；不得因现成代码裁剪完整工作流、盘点或培训。Agnes 文本与结构化输出、独立 Embedding、本地推理服务的兼容均需实测，来源 Spark 历史结果不等于 Agnes 已通过。

已有 Embedding/Milvus 人才语义检索适配可作为复用候选；知识与档案问答仍须补授权分段、来源关系和真实引用，检索结果不能代替问答。Embedding 独立配置，不假定 Agnes 提供该能力；Milvus 按原始指定技术落地，版本与部署参数在目标环境核对；其他检索组件可补充，不替代指定组件。

简历文字识别需在目标部署环境验证图片与扫描 PDF 的实际处理能力；可评估本地 OCR，不以 Agnes 已支持图片输入为前提。相关依赖和识别模型应包含在安装说明中，处理耗时与错误在任务状态中体现。

长任务后台执行并可查询状态，设调用超时和有限重试。单个步骤失败应保留记录，不使其他模块无法使用。模型不可用时明确告知，不切换到伪造成功结果。上传文件、知识文档、用户输入和模型输出均视为不可信内容；提示注入不得改变授权范围或触发未经批准的命令、查询和外部副作用。传输/存储加密、密钥轮换与访问策略由安全设计审定，不能以“密钥不入库”代替完整保护。

原始 PRD §7 的全部数值现为必须达到的验收目标：并发在线≥2000、页面渲染≤1s、向量检索≤500ms、普通接口≤1s、大数据报表≤3–5s、系统可用率≥99.9%、AI 服务≥99.5%、热点缓存命中≥98%、RAG 检索准确率≥95%、匹配准确率≥90%、简历解析准确率≥99%。这些是目标，不是达标声明。必须补齐负载、资源、计时边界、P95/P99、样本与公式、标注复核、可用率窗口及排除项后执行验收；参数未冻结不能用来删除或降低原值，不能用模型自报、静态原型或历史报告代替实测。评测方法保留分项口径：解析字段级质量、匹配排序质量、RAG 检索/回答/引用/拒答及越权零泄漏分别评测；评测数据来源及授权、双人复核/仲裁、盲测集隔离和版本记录须经业务/安全批准，模型/Prompt/配置变更按门槛回归。

当前先梳理项目整体需求，消除已确认事项与旧分期、验收之间的冲突；不得以四人既有工作包或旧 3–4 天试行周期反推产品范围。完整需求确认后，先审批公共能力契约、跨域数据与权限、失败补救、质量评测和部署边界，形成项目级 Todo，再分解交付责任与工期。既有[四人分工与试行方案](四人分工与试行方案.md)和[技术框架](技术框架.md)是旧版实施记录，需待主需求冻结后更新，不作为本次业务取舍依据。

## 9. 演示验收与交付物

## 12. 统一数据、状态与页面契约

本节为目标契约。现有源码使用 talent_profile_id、pending/success/done 等状态及 request_id；先在各模块接入契约登记映射，再实施兼容，不据文档批量改写旧状态或重建主档。

### 12.1 数据事实与快照

业务数据库保存人才、岗位、测评、学习、引用和任务事实；全文/向量索引属于可重建派生数据。数据库提交后索引更新失败，应分别显示“业务已保存、索引待处理”，不把整次操作伪报为未保存，也不把索引失败伪报为全成功。文档、档案、模型输入、任务日志和报表的访问都必须继承源业务对象的授权；撤权后的新查询不得继续召回旧索引内容。

跨模块用 person_id 关联，禁止按姓名联表；账号绑定、人员状态及招聘阶段分开。上传批次是文件集合，人才批次是去重后的人员集合，二者不能混作一个总数。一个人可有多份原文件；同任务重试只新增执行尝试记录，不重复创建档案、答卷或结果。

报告保存数据快照和查询口径；历史匹配保存岗位/档案输入快照；固定岗位测评保存发布试卷及题目、答案、评分与公开版本；课程、能力及盘点历史按时间追加。不能用新题库、岗位或当前课程覆盖历史依据。

### 12.2 状态边界

长任务建议采用 waiting/running/completed/failed/cancelled，共用执行状态定义，保留阶段、attempt、耗时和错误。解析、OCR、索引、匹配及报告状态分别记录。运行中进程退出后需按检查点恢复或明确失败可重试；不得永久卡在处理中。批次/任务显示最后更新时间、逐项错误与可安全重试项，失败项下载需单独授权。自动重试次数及退避有上限，耗尽后转交有明确责任角色的人工待办；人工重跑记录处理人、原因、结果及是否重新触发，不得静默丢失或无限重试。取消为尽力停止，不抹除已完成结果，批次取消不得重复处理已成功项或重复发送通知。

业务状态单独定义：匹配建议、人工招聘决定与候选人对外阶段彼此分开；笔试执行状态与成绩公开状态分开；学习自报、课程完成条件、报名/审批/候补与必修逾期分开；盘点经理初评与 HR 正式确认分开。评分失败不算不合格，低分不自动淘汰，候补通知不等于正式占位，课程自报完成不等于合格完成。状态枚举及合法迁移由领域契约统一定义，不由页面自由造字符串。

### 12.3 指标口径建议

- 匹配建议达线率：有效评分中达到岗位内部参考线的人数/有效评分人数；仅表示参考标签，失败和待处理另列，不得称为录用或自动初筛通过率。
- 人工推进人数：按人员与岗位去重后，人工标记进入下一步的人数；不是已录用人数。
- 人才需求缺口：需求人数减去所选业务阶段人数，最小为 0；显示采用“人工推进”还是“已录用”口径，不能混称。
- 测评通过率：已完成有效评分且达到配置通过标准的人数/已完成有效评分人数；未参加、评分中及失败分别列出。
- 课程正式完成率：满足当期课程配置的完成条件数/有效分配或报名数；另列学习自报进度、审批中及候补，不混用分母。
- 所有统计标注时间范围、去重键、分母及更新时间；零分母显示暂无数据，不虚构 0% 或 100%。

### 12.4 页面与接口建议

管理端覆盖组织/用户/授权、岗位与多岗位申请、简历批次和人才档案、匹配与人工招聘决定、固定结构测评/多轮面试、人才盘点与审核、课程/名额/审批/候补/反馈、知识与档案问答、指标报告、工作流定义/审批/运行、智能体管理（注册/发布/退役/看板）、模型供应商管理与任务调度管理、通知及审计。员工端覆盖本人档案、获准的测评与盘点反馈/异议、个人发展与培训、授权知识问答；候选人端仅覆盖本人资料、岗位申请及对外阶段、本人面试安排和获准公布的成绩。页面可按角色合并标签，但服务端字段授权与任务状态必须完整。

所有页面具备加载、无数据、部分失败、权限不足、校验错误和可重试提示；长任务只显示真实阶段/已完成数量，不虚构精确百分比。前端隐藏按钮不能代替后端授权。受保护的读写、搜索、问答、导出和后台任务均在服务端校验身份、对象和字段范围；授权变更、敏感查看、人工修订、导出和高影响动作留可查询审计，不写密钥或不必要的个人原文。具体多角色/组织矩阵仍待确认。

API 建议沿用 /api，统一 {code,message,data}，列表带 items/total/page/page_size 并限制上限。异步操作返回持久化任务 ID，随后轮询或订阅状态；鉴权、错误码、幂等键和版本在接口契约中定义。接口级限流、熔断、降级与黑名单，以及 SSE 实时推送端点为原需求强制约定（PRD §6，2026-11-07 改回）；一期长任务进度推送采用 SSE，轮询保留为降级手段，断线恢复与终态持久化为验收项（2026-11-07 确认）。具体阈值、策略与端点设计在接口/性能设计阶段确认。具体 HTTP 路径以实际生成的 OpenAPI 为准，不从旧文档推断接口已存在。
