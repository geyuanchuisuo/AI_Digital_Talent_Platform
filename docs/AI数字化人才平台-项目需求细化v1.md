## 0. 阅读说明与确认规则

### 0.1 目标

将现有 PRD、原型、概要/详细/接口/数据库设计和测试材料整理为可追踪、可讨论、可验收的单一需求基线，明确业务范围、角色权限、AI 质量、安全、交付边界和未决选择。

### 0.2 状态标记

- **建议**：为便于讨论提出的默认方向，未经用户确认不得自动升级为承诺。
- **待确认**：需要产品/业务/技术负责人回答的问题。
- **目标值（待确认）**：源材料出现的指标，尚未完成可测性、成本与可达性论证。
- **示意**：原型中的虚构/样例数据或交互，不构成正式需求或现状证明。

### 0.3 需求变更与实施门槛

1. 先确认本文件中的范围、优先级、角色权限、指标及技术约束。
2. 需求确认后，再形成独立开发计划与待办清单，交用户审核批准。
3. 用户明确说“开始”之前，不编写或修改业务代码；需求文档、原型讨论和分析不视为开始开发。
4. 需求冻结后，每项变更须记录原因、影响模块、验收口径、数据/安全影响及批准人；同步更新需求追溯关系。

### 1.1 已确认范围方向与待细化项

**已确认的一期范围方向：**

- 面向企业集团多个部门，覆盖招聘、人才盘点、培训发展三大业务模块。
- 包含完整 Agent 工作流能力；系统按解耦、分模块方式建设，不以人手不足为由将完整工作流推迟到后续阶段。授权业务人员可视化创建/修改工作流，提供预设模板，发布前由管理员审核；外部通知和招聘/人才/培训数据变更等高影响节点按权限审批。
- 包含基础知识库问答：知识管理员维护文档；用户仅检索其有权访问的内容；回答附来源，证据不足时说明或拒答。
- 包含受限自然语言指标问数：限白名单指标、按管理层组织权限过滤，结果展示指标口径/范围/更新时间/来源并留审计；不开放任意 SQL 或未经审批的个人明细下钻。
- 支持模板批量导入现有人事、招聘和培训历史数据用于初始化；外部系统实际对接按需启用。
- 服务内部 HR、招聘人员、部门经理、培训管理员/讲师、全体员工及外部候选人；内部员工账号由 HR/组织管理员预先导入名单或发送邀请，员工完成手机号/邮箱验证后激活，不开放未经授权的内部员工自助注册。激活后可使用手机号或邮箱验证码登录，也可使用平台单独提供的企业账号密码登录，不要求必须接入客户现有统一身份认证/SSO。候选人可使用邮箱或手机号验证码注册/登录，并支持安全的密码找回；候选人身份与员工账号隔离，权限仅限自助填写/维护本人资料、查看本人进度及预约面试。
- 首期支持中文/英文界面切换；至少支持手机浏览器，候选人流程适配手机，复杂内部管理优先电脑端。
- 容器化交付，客户可拉取部署到客户指定云环境或私有化环境；默认联网，同时支持离线部署。具体资源规格和部署拓扑留待架构阶段按客户环境评估；对统一身份认证、企业微信/钉钉、邮件/日历、招聘网站等预留接口，客户按需启用。
- AI 模型服务支持可配置的 API 服务、本地模型/本地推理服务等方式。没有可用模型服务时，相关 AI 能力明确提示“暂时不可用”，禁止使用假数据、伪造结果或静默降级。

**招聘主线建议仍作为端到端验收主线之一：**授权导入简历 → 解析并由 HR 复核 → 建立/关联人才档案 → 创建招聘需求 → 查看可解释的候选匹配 → 人工推进候选人阶段 → 邀约面试并记录反馈。人才盘点、培训发展与完整 Agent 工作流也属于一期范围，需要分别定义独立模块闭环，并明确与人才主档、招聘流程和权限服务的接口。

首期不包含 AI 人脸识别、视频面评、情绪推断或 AI 自动评判；采用人工面试与结构化反馈。岗位匹配仅用于排序和解释，由 HR/招聘人员决定是否推进；硬性条件不符的候选人也须展示并标明原因，不自动淘汰。首期人才盘点规则详见 D-28/REQ-INV-001~004：员工可见本人获准的能力评估、经理反馈和发展建议，但内部评级、九宫格位置和人才池归类不展示；晋升/调薪仍走独立审批。未来如考虑视频转写/摘要，须另行确认告知与授权、保留/删除、人工审核等要求，不自动作录用判断。未经审批的数字员工外部副作用等仍未确认；不得仅因原型出现而默认列入一期。基础知识库问答、完整 Agent 工作流和受限自然语言指标问数已纳入一期范围；Dify、自研及指标语义层等属于架构阶段选型问题，不影响已确认业务能力范围。具体模块边界、工作流节点、权限和验收仍需在需求阶段逐项确认。

## 2. 项目定位与目标

### 2.1 暂定定位

面向企业人才招聘与人才发展场景的 AI 辅助平台。通过结构化人才数据、岗位/项目需求、测评培训、知识检索和可控 AI 工作流提升人才信息处理与决策效率。AI 输出用于辅助，不自动替代招聘、晋升、薪酬等需要人工负责的决定。

> “企业级、AI 原生、全流程智能化”来自既有材料；具体面向外部招聘还是内部人才发展、哪些流程纳入首版，待 D-02/D-03 确认。

### 2.2 暂定业务目标

1. 建立统一的人才档案与来源可追踪的数据基础。
2. 减少简历录入、筛选、岗位匹配等重复操作，并支持人工复核。
3. 将岗位要求、匹配依据及候选人评估过程结构化留存。
4. 为已批准的知识内容提供有权限、可溯源的问答。
5. 在权限、审计和评测机制到位后，逐步扩展人才发展和数据决策能力。

### 2.3 七问（需求基线）

| 问题 | 当前理解 | 待确认 |
|---|---|---|
| 为谁解决 | HR/招聘、业务负责人、员工、管理层、平台管理员 | D-03、D-09 |
| 解决什么 | 人才数据分散、筛选匹配效率低、评估与培养信息不连贯 | 业务方是否认同、优先痛点 |
| 核心价值 | 减少人工重复处理，提升人才信息可用性与可解释性 | 量化基线/目标 |
| 关键流程 | 人才入库、岗位需求、匹配评估；其他流程待选 | D-02、D-08 |
| 数据来源 | 简历、组织/岗位、测评、课程、知识文档、外部系统 | 系统清单、授权、数据负责人 |
| 成功标准 | 功能闭环、权限正确、AI 指标经标注集验证、交付可部署 | D-15、D-16、D-20 |
| 明确不做 | 未获批准的自动录用/淘汰决定；未批准的数据外发；未确认范围的模块 | 还需补充排除项 |

## 5. 角色与权限（候选模型）

以下为最小候选角色，不代表最终授权。权限以用户身份、组织归属、业务关系、角色与显式授权组合判定；“管理员”不能默认绕过所有数据访问审计。

| 候选角色 | 可能业务职责 | 默认数据范围建议（待确认） |
|---|---|---|
| 普通员工 | 个人档案、测评、学习、员工可见知识问答 | 仅本人及明确授权数据 |
| HR/招聘 | 候选人、岗位、招聘流程与邀约 | 授权组织/招聘项目；敏感字段按权限最小化 |
| 业务负责人 | 项目需求、岗位匹配与面试反馈 | 所属组织/项目及被授权人才 |
| 面试官/评估人 | 受邀面试、提交评估 | 仅被分配的招聘/面试对象 |
| 管理层 | 汇总指标与授权决策信息 | 授权组织汇总；避免默认暴露个人敏感信息 |
| 组织管理员 | 用户、组织与部门配置 | 管理授权范围内的组织数据 |
| 系统管理员 | 系统配置、运行维护 | 配置管理与必要的受控运维访问；访问业务敏感数据需单独授权/留痕 |

### 5.1 权限验收要求

1. 未登录或凭证失效访问受保护资源时拒绝访问；拒绝响应不泄露资源是否存在等不必要信息。
2. 每个读写/导出/搜索/问答/报表/后台任务入口都须进行服务端授权；前端隐藏菜单不算权限控制。
3. 行级范围在查询执行前生效；字段级规则同时作用于详情、列表、搜索、导出、日志和 AI 上下文，避免侧信道泄漏。
4. AI/RAG/问数的检索候选集须先按调用用户权限过滤；不得仅在生成后过滤答案。
5. 角色变更、撤权、停用后，后续请求按新权限生效；缓存/会话失效时限由 D-10 决定。
6. 越权行为应拒绝并按安全策略记录审计事件；日志避免记录不必要的简历正文、凭证或敏感提示词。
7. 导出、批量下载、敏感字段查看及管理员授权变更须明确授权、审计、限额/审批策略。

> 行级/字段级权限矩阵需根据 D-09 的最终角色逐资源逐字段补齐，当前不可将源测试文档中的示例矩阵当作已批准策略。

## 6. 功能需求（草案）

所有条目状态均为**待范围确认**。下列验收标准描述需求应达到的可观察行为；未确认的数据源、指标、角色、页面和目标值均以待确认处理。

### 6.1 身份、组织与权限（IAM）

#### REQ-IAM-001 身份认证与会话

系统应提供分离的内部人员和外部候选人身份认证路径。内部员工账号由 HR/组织管理员预先导入名单或发送邀请，员工完成手机号/邮箱验证后激活；不开放未经授权的内部员工自助注册。激活后可使用手机号或邮箱验证码登录，也可使用平台单独提供的企业账号密码登录；不要求必须接入客户现有统一身份认证/SSO。候选人支持邮箱或手机号验证码注册/登录及安全密码找回。两类身份不得因邮箱/手机号相同而自动共享权限。

- AC-1：内部员工账号须由 HR/组织管理员预先导入或邀请，员工完成手机号/邮箱验证后激活；外部候选人可使用邮箱或手机号验证码注册。激活/注册时完成手机号或邮箱验证，不额外要求 MFA。无效/过期验证码、密码或会话不能访问受保护接口。
- AC-2：退出或管理员停用/撤销身份后，旧会话在确认的失效窗口内不可继续访问。
- AC-3：认证失败提示不泄露账号是否存在或敏感认证细节。
- 来源：PRD 的登录/令牌测试要求；认证供应商与流程待 D-10。

#### REQ-IAM-002 用户、组织、角色与授权

授权管理员按权限维护用户状态、组织关系、角色及数据范围，并能查询授权变更记录。

- AC-1：未授权用户无法创建/变更角色、组织或授权。
- AC-2：用户停用、离职或组织变化后，已定义的访问与任务处置规则生效。
- AC-3：授权变更记录操作者、时间、对象、变更前后值及结果，敏感值按策略脱敏。
- 来源：PRD 系统管理；现有角色与组织归属待 D-09。

#### REQ-IAM-003 权限贯穿与审计

所有业务查询、写入、批量操作、导出和 AI 调用均执行统一权限策略并产生必要的审计记录。

- AC-1：跨组织/跨候选人未授权访问在服务端被拒绝，列表、详情、搜索和导出结果一致受限。
- AC-2：审计可按用户、时间、对象、操作、结果查询；不得将秘密或不必要的个人数据写入日志。
- AC-3：高风险权限变更、数据导出与敏感信息访问产生可追溯事件。
- 来源：PRD 2.8、测试用例权限/审计章节；字段清单待确认。

### 6.2 人才档案与简历（TAL）

#### REQ-TAL-001 简历导入与来源登记

授权人员可导入单份或批量简历；系统保存来源、上传人、上传时间、文件标识、处理状态及必要的授权/告知信息。

- AC-1：支持格式、大小、数量及恶意/损坏文件处理规则明确后，合法文件可提交并返回逐文件受理结果。
- AC-2：不支持或无法读取的文件明确失败原因，不伪报成功；不会生成不完整的“成功”档案。
- AC-3：重复请求不会重复创建文件/解析任务；批次部分失败时可区分成功与失败项。
- AC-4：原始文件访问受权限控制，存储与保留期限遵从确认的合规策略。
- 来源：PRD 2.1、TC-RES-01；格式与限制待确认。

#### REQ-TAL-002 简历解析与人工校正

系统通过当前配置且可用的 AI 模型服务，按已确认的字段字典从简历提取结构化信息，显示字段来源/置信度或待复核提示，并允许有权人员校正。若模型服务不可用，应明确提示暂时不可用并保留可重试状态，不得返回假解析结果。

- AC-1：解析结果与原文件及解析版本关联；字段包括经确认的姓名/联系方式/教育/经历/技能等。
- AC-2：低置信度、缺失或冲突字段可被识别并进入人工复核，不擅自补造事实。
- AC-3：失败任务说明可理解的原因，并按策略安全重试；同一任务重复执行不会重复创建人才实体。
- AC-4：人工修订记录操作者、时间及字段变更；可区分原始抽取值与确认值。
- AC-5：解析准确率目标及统计方式依据 D-15 确认后验收；不得用少量示例样本宣称达标。
- 来源：PRD 2.1、TC-RES-02/03、评测集 `docs/test/data/resume_parse_eval.json`（当前示例规模不足）。

#### REQ-TAL-003 人才档案、标签与查重

授权人员可查看/维护人才档案，生成或维护标签及档案完整度；系统提示潜在重复记录，合并由有权人员确认。

- AC-1：档案字段、标签分类/词典、来源及更新时间可追溯。
- AC-2：疑似重复项提供可比较依据；未经确认不得不可逆地自动合并。
- AC-3：合并保留来源记录和可审计的关联/撤销方案，不丢失原始文件和关键历史。
- AC-4：个人敏感字段按权限掩码显示，导出同样受限。
- 来源：PRD 2.1、原型人才画像/查重区域；“百级标签”及自动合并阈值待确认。

#### REQ-TAL-004 人才检索与档案问答

授权人员可用结构化条件及自然语言检索授权范围内人才；档案问答仅依据有权访问的档案内容，并展示依据。

- AC-1：组合筛选、分页/排序及空结果状态符合接口契约。
- AC-2：搜索结果不能包含调用者无权访问的个人或字段信息。
- AC-3：AI 回答区分事实、推断与无依据内容；引用可定位到档案字段/来源材料。
- AC-4：无足够依据时明确说明无法判断；问答输入、输出和引用遵循审计/保留策略。
- 来源：PRD 2.1、原型人才画像页；检索范围与模型待确认。

### 6.3 岗位、需求与招聘（JOB）

#### REQ-JOB-001 岗位/JD 与项目人才需求

授权业务人员可维护岗位要求及项目人才需求；需求包含数量、职责/技能、组织、优先级、时间范围和审批信息等经确认字段。

- AC-1：必填字段、合法状态流转、组织/项目授权规则有统一定义。
- AC-2：变更保留历史版本；匹配任务可追溯到使用的岗位/JD 版本。
- AC-3：项目需求未经授权不可见/修改；重复提交同一创建请求不产生重复需求。
- 来源：概要设计项目需求/岗位域、PRD 2.3；字段和审批规则待确认。

#### REQ-JOB-002 人才—岗位匹配

系统根据经批准的岗位条件和可访问人才数据计算候选匹配结果，提供排序、分项依据、缺失数据及人工复核入口。匹配仅用于排序和解释，由 HR/招聘人员决定是否推进；即使候选人不符合硬性条件，也展示并说明原因，不自动淘汰。

- AC-1：匹配结果关联岗位版本、人才档案版本、规则/模型版本及计算时间。
- AC-2：评分范围、维度权重与阈值可解释；不得将模型分数描述为客观录用结论。匹配只用于排序和解释，推进/淘汰由 HR 或招聘人员决定；不符合硬性条件的候选人仍须展示并注明原因，不自动淘汰。
- AC-3：无关/缺失资料不被默认为满足条件；结果展示不确定性和需要人工核验项。
- AC-4：候选集合严格受调用者权限约束；重复触发具备去重/幂等或明确任务语义。
- AC-5：匹配质量指标按 D-15 定义的标注集和判定方法评估。
- 来源：PRD 2.3、TC-MAT-01~04、`match_eval.json`（现有样例规模不足）。

#### REQ-JOB-003 候选人流程与人工决策

授权招聘人员可管理候选人阶段、负责人、面试/评估记录及决策结果；状态变更须合法且可追踪。

- AC-1：阶段、可执行动作、必填条件及驳回/撤回规则定义为单一状态机。
- AC-2：每次状态变更记录操作者、时间、原因及关联招聘需求。
- AC-3：AI 建议不能自动淘汰、录用或改变候选人阶段，除非另有经批准且合规的明确流程。
- AC-4：被授权面试官只可访问分派范围内信息；评估记录访问/修改留痕。
- AC-5：候选人仅能按本人各岗位申请查看对外阶段（已提交、筛选中、待面试、待决定、已结束）及本人面试预约信息；不能看到内部匹配分、面试官评价或其他申请的内部处理记录。一个岗位的进度变化不改变其他岗位的对外状态；普通阶段自动更新，“已结束”及最终结果须经 HR 确认后对候选人展示。具体内部阶段映射及最终结果文案待确认（D-27）。
- 来源：PRD 中候选人管理、概要设计招聘流程；具体阶段及人工决策责任待确认。

#### REQ-JOB-004 邀约、面试与通知

按批准范围创建邀约、安排面试时间/参与者、发送通知并记录反馈与后续状态。

- AC-1：日历冲突、取消/改期、通知失败、候选人拒绝等路径有明确状态和用户提示。
- AC-2：外部消息只发往已确认的渠道/接收方；重试不重复发送造成重复邀约。
- AC-3：面试记录及附件仅向授权人员开放；保存期限待确认。
- 来源：概要设计 `jd_publications`、`interview_invites`、`multi_round_interviews`；渠道与模态待 D-08/D-14/D-19。

### 6.4 测评与面试评估（ASM）

#### REQ-ASM-001 题库、测评配置与作答

授权人员维护题目及测评配置；参与者仅能访问分配给自己的有效测评并提交作答。

- AC-1：题目、选项/标准答案、评分规则、版本和可见范围明确；题库变更不追溯篡改已开始的测评。
- AC-2：重复提交、超时、断线恢复、已提交再次提交均有明确且一致的处理。
- AC-3：评分结果可追溯到测评配置/试卷版本；人工评分可记录评分人和理由。
- 来源：PRD 2.2、测试用例 TC-EXM-01/03；考试模式和规则待确认。

#### REQ-ASM-002 能力分析与面试辅助

系统可根据测评及经授权的人工面试反馈形成辅助分析，标明数据来源与评估局限。首期面试由面试官人工开展并提交结构化反馈；不包含 AI 人脸识别、视频面评、情绪推断或 AI 自动评判。

- AC-1：能力维度、评级规则及雷达图指标定义明确，不以无数据的静态示意数值冒充结果。
- AC-2：面试反馈由授权面试官提交，可按权限复核/更正并留审计记录。
- AC-3：首期不采集或分析面试音视频用于 AI 评判；未来如考虑视频转写/摘要，须另行确认告知授权、录制/保留/删除规则和人工审核流程。
- AC-4：输出为辅助评估，可被人工复核、更正并记录；不自动作出雇佣决定。
- 来源：PRD 2.2、原型智能测评、TC-EXM-04/06；D-14。

#### REQ-ASM-003 错题复盘与复习计划

在范围内时，系统依据已提交测评生成错题清单和可调整的复习计划。

- AC-1：错题与原题/答案/测评版本关联，权限仅限本人及被授权管理者。
- AC-2：计划可查看、调整、完成或取消；建议来源可追溯，不声称未验证的能力提升。
- 来源：PRD 2.2、TC-EXM-05；首版范围待确认。

### 6.5 人才盘点与成长发展（INV）

#### REQ-INV-001 人才档案维度与信息更正

人才盘点档案由岗位技能、工作/项目经历、测评能力、培训成长、员工自评及经理评价构成，能力维度可按岗位族配置。员工可查看本人可见档案并提交资料更正申请；更正经 HR 审核后更新正式记录，保留原值、修改值、申请/审核人、时间和理由。

- AC-1：员工仅能查看本人获准信息，不能查看其他员工盘点资料。
- AC-2：经理仅能访问本部门范围内的盘点数据；负责范围内 HR 可查看完整盘点信息。
- AC-3：员工资料更正申请在 HR 审核通过前不改变正式记录；驳回时记录原因并通知员工。对于下述经理提出的潜力初评，负责范围内 HR 审核确认后方形成正式盘点结果。
- AC-4：能力维度及版本可追溯；岗位族维度调整不能静默改写历史评估。
- 注意/阻塞：需明确岗位族、技能词典、字段来源、员工自评/经理评价模板及敏感字段；这些口径未定前不能冻结档案模板。

#### REQ-INV-002 能力评级与九宫格

能力评级采用五档；人才盘点以“绩效×潜力”九宫格作为内部分析视图。绩效取最近一个已完成且经 HR 确认的周期；没有正式绩效结果时标记“待评估”，不进入九宫格。潜力由部门经理按统一维度提出初评及依据，由负责范围内 HR 审核确认后生效。潜力维度包括学习敏捷性、适应变化、承担更复杂职责的意愿与能力、跨团队影响力，具体行为标准可按岗位族配置。

- AC-1：九宫格仅使用已确认绩效及 HR 已确认潜力；任何一项缺失/未确认时显示待评估，不推断填补。
- AC-2：经理初评须填写依据；HR 可确认、退回补充或调整并记录理由、时间和责任人。
- AC-3：九宫格、五档评级和岗位族标准为内部管理分析工具，不自动触发录用、淘汰、晋升、调薪或任命审批。
- AC-4：员工本人不展示评级、九宫格位置或人才池归类；部门经理仅查看本部门当前结果，负责范围内 HR 可查看完整结果及授权历史。
- 注意/阻塞：五档评级的正式名称和逐档标准、绩效口径、九宫格轴阈值/象限命名、岗位族规则尚未定义，必须由 HR 批准后才可形成正式评价，不能直接采用原型示意值。

#### REQ-INV-003 定期复核与历史追溯

人才盘点结果每年定期复核；员工岗位或能力发生明显变化时可提前发起复核，更新结果仍须 HR 确认。系统保留历次评级、人才池归类、绩效周期、潜力依据、确认时间和操作人，供授权 HR 追溯；部门经理默认只看本部门当前结果。

- AC-1：年度复核有周期/责任人/逾期状态；提前复核须记录触发原因。
- AC-2：HR 确认后形成新的版本，不覆盖历史记录；可比较前后变化并追溯依据。
- AC-3：历史访问权限受控；候选人/员工本人不因历史留存而获得内部评级或人才池可见权限。
- 注意/阻塞：需定义“岗位或能力明显变化”的触发条件、年度盘点周期、历史保留期限及更正/争议流程。

#### REQ-INV-004 人才池管理与员工反馈

人才池类别及准入/退出标准由 HR 按组织需要配置并审批，部门经理可提出员工加入/退出建议，由负责范围内 HR 确认后生效。部门经理可查看负责范围内员工所属的人才池类别及进入/退出的具体原因；员工本人不得查看所属人才池或类别，也不获知针对本人的加入/退出建议及 HR 处理结果。盘点完成后，员工可查看本人获准的能力评估、经理反馈和发展建议，但不展示内部评级或九宫格位置；员工可以就这些可见内容提出异议或补充说明，由部门经理复核、HR 确认后再决定是否更新正式结果；该异议流程不涉及人才池归属。能力差距可转为员工与经理共同制定、跟进的个人发展计划；计划独立管理，不自动触发课程报名、晋升或调薪。

- AC-1：负责范围 HR 可查看负责范围内完整人才池信息；部门经理仅可查看负责范围内员工的当前人才池类别及进入/退出原因；员工本人及候选人不可查看人才池或类别。
- AC-2：人才池加入/移出需由 HR 确认生效，并记录建议人、HR 确认人、具体原因、时间及前后分类；不向员工发送加入/退出建议或结果通知。
- AC-3：员工仅可对本人可见的能力评估、经理反馈和发展建议提出异议/补充说明，不得看到或申诉未对其披露的人才池归属；异议不直接覆盖正式盘点结果，经复核确认后产生新版本并保留原记录。
- AC-4：个人发展计划记录目标、行动、责任人、期限、进展和复盘；员工与经理共同参与，和盘点记录可追溯关联。
- AC-5：个人发展计划本身不自动报名课程或触发晋升/调薪审批；相关流程如需联动由用户另行发起并按各自审批流程执行。
- AC-6：本盘点模块中，负责范围 HR 可查看完整盘点结果及历史；部门经理仅可查看本部门当前结果；员工仅可查看本人的能力评估、经理反馈和发展建议，无法查看评级、九宫格位置、人才池分类或他人数据。
- AC-7：普通员工和部门经理不可导出包含个人评估明细；负责范围内授权 HR 可导出，系统记录导出人、时间和数据范围，导出内容不得超出 HR 权限范围。
- AC-8：部门经理可查看并导出本部门匿名汇总；任一统计项样本少于 5 人时隐藏该项，且汇总不得包含可识别个人的信息。
- AC-9：部门经理可针对本部门汇总中的疑似错误发起复核，提交所见异常/依据；HR 审核后决定是否更正正式盘点数据。申请不直接修改汇总或个人正式结果；处理结论和更正均留痕。
- 注意/阻塞：人才池名称/标准、员工可见反馈字段、异议处理时限、计划字段/提醒/完成口径需 HR 确认。

### 6.6 培训与成长（TRN）

#### REQ-TRN-001 培训方案与课程

一期由授权人员维护课程和培训计划；培训管理员或部门经理可指派课程，指派时可设为必修。员工也可自行报名，报名需遵守课程名额和审批规则：普通课程由培训管理员配置为免审批或需直属经理审批；涉及费用或占用工作时间的课程，还须培训管理员复核。员工可查看本人课程、进度与完成记录。一期支持根据能力差距和个人发展计划推荐课程，并展示员工有权查看的推荐依据；员工或经理自行选择，不自动报名，也不改变盘点或考核结果。

- AC-1：课程内容版本、目标人群和学时有明确口径；培训管理员按课程配置完成条件，可包含学习进度、线下签到或测验通过。只有满足配置条件才记为完成，不能仅凭打开课程页面或累计在线时长判定。
- AC-2：培训管理员或部门经理可指派课程并选择是否必修；员工可自主提交报名。普通课程按培训管理员所设规则免审批直接确认，或由直属经理审批；涉及费用或占用工作时间的课程，还需培训管理员复核通过后才确认报名。需审批的申请不得误记为已通过；提交申请后临时占位，审批通过后正式占用，审批拒绝或员工撤回申请时释放名额。免审批报名确认后直接占用名额。
- AC-3：课程名额已满时可进入候补名单；出现空位后按候补顺序通知员工，员工须在收到通知后 24 小时内确认是否参加；逾期未确认则通知下一位候补员工，不自动报名；确认后仍需遵守该课程既定审批规则。
- AC-4：开课前员工可自行取消自选课程，取消后释放已占名额；必修课程不能自行取消，须由指派人或培训管理员处理。开课后的退出由培训管理员审核并记录原因。
- AC-5：必修课程到期未完成时，向员工及直属经理发送站内提醒，并在培训管理员视图标记逾期；不自动扣减绩效或调整人才盘点结果。培训管理员可填写延期原因和新截止日期后延期，并通知员工及直属经理；原截止日期、延期操作与已产生的逾期记录保留，不直接覆盖。
- AC-6：仅该期次有签到或出勤记录的实际参加员工可评价课程内容和讲师；评价非课程完成条件。课程结束后开放 7 天提交窗口，员工可在窗口内提交、修改或撤回；窗口关闭后锁定，员工仍可查看本人提交内容。课程与讲师分别采用 1–5 分。每名员工对同一课程跨期最多计一份有效反馈；反馈跨期累计并合并不同讲师，不拆分期次或小群体展示。有效反馈少于 5 份时不展示汇总，达到 5 份后展示课程整体及讲师整体匿名汇总并随新反馈更新。开放文字意见不展示原文，仅展示归纳主题；每个主题须至少获 5 份反馈支持。讲师、部门经理仅查看匿名汇总，不针对单条反馈公开回复；培训管理员主要查看匿名反馈，并可依据汇总反馈发布统一改进说明。具体问题调查另走明确告知的实名渠道，不从匿名反馈推断或披露提交者；反馈不直接改变员工能力评级或考核结果.
- AC-7：报名/指派、候补与通知、审批、开始、进度、完成、逾期、取消/退出的状态和记录一致可追溯。
- AC-8：课程推荐应关联获准使用的能力差距或个人发展计划目标，并展示员工可见的依据；不得在员工侧泄露内部评级、九宫格位置或人才池归类。推荐仅供员工或经理自行选择，不自动报名、改变盘点或考核结果；模型服务不可用时提示暂时不可用，不伪造 AI 推荐。
- 来源：PRD 2.4、概要设计培训域；课程指派、自主报名、审批人、候补、取消和按课程配置完成条件的规则已确认（D-31），候补确认期限为 24 小时；临时占位最长时限仍待确认。

#### REQ-TRN-002 学习有效性与隐私

学习时长统计应采用已批准的低侵入策略；任何人脸/生物识别处理必须先过隐私与法律评估。

- AC-1：有效学时口径、心跳/活动判定、断线恢复、重复播放等规则公开且可复现。
- AC-2：不采集未批准的摄像头/生物特征数据；如经批准，提供告知、授权、访问/留存/删除和非生物识别替代路径。
- AC-3：异常判定允许人工复核与申诉，不能仅凭自动检测直接惩罚员工。
- 来源：PRD 2.4、原型“人脸抽检”内容；D-12。

#### REQ-TRN-003 成长轨迹

一期按权限展示员工的测评、学习和能力变化，并区分事实记录与推断。课程完成时自动记录培训完成情况，不自动更新能力评级；员工可补充实践成果，由经理评价，负责范围 HR 审核后才更新正式能力评级。

- AC-1：每个时间点可追溯到实际测评/学习事件；无数据时显示空态而非虚构曲线。
- AC-2：完成课程后仅自动记录培训完成情况；员工补充实践成果、经理提出评价，经负责范围 HR 审核确认后才更新正式能力评级，保留前后记录与确认人。
- AC-3：本人可见范围、管理者访问范围和敏感评价字段按权限策略执行；员工仍不可见内部评级、九宫格位置及人才池归类。
- 来源：PRD 2.4、原型培训页；培训结果与能力评级衔接已确认（D-32），成长指标口径待确认。

### 6.7 知识库与 RAG（KNO）

#### REQ-KNO-001 知识内容管理与索引

授权人员导入、更新、停用知识内容；系统记录文档版本、来源、权限标签、处理状态和索引版本。

- AC-1：重复导入、失败重试、更新及删除/停用的索引一致性有明确规则。
- AC-2：处理失败可定位阶段与原因；重试不会产生重复有效内容。
- AC-3：文档原件、切片和向量访问均执行权限策略；删除/撤权在确认的时限内影响检索。
- 来源：PRD 2.6、TC-RAG-01、知识库设计；支持格式/切片策略待确认。

#### REQ-KNO-002 有权限、可溯源的问答

系统在 AI 模型服务可用时，仅用调用者有权访问的知识检索并回答；回答展示可验证的来源引用，对证据不足的问题拒答或说明不确定性。模型服务不可用时明确提示暂时不可用，不得返回预设/伪造答案或示意数据。

- AC-1：引用可定位文档及经确认的章节/页码/片段，引用内容确实支持回答。
- AC-2：越权知识不进入模型上下文，答案/引用/摘要均不得泄漏。
- AC-3：无依据问题不编造政策条款；拒答原因对用户清晰。
- AC-4：评测集规模、样本分层、答案正确及引用正确的判定方法按 D-15 批准后验收。
- AC-5：记录必要的模型/索引/提示版本、耗时和结果状态；日志最小化保存个人信息。
- 来源：PRD 2.6、TC-RAG-02~04、`rag_eval.json`（当前示例规模不足）。

### 6.8 Agent 与工作流（AGT）

#### REQ-AGT-001 Agent 配置、版本与运行记录

授权管理员可查看/维护经批准的 Agent 配置及版本；运行任务可追踪输入引用、状态、结果与失败原因。

- AC-1：草稿、测试、发布、停用/回滚等生命周期明确；发布有权限检查与版本记录。
- AC-2：运行日志不暴露凭证或不必要的个人数据；敏感输入按策略脱敏/限制访问。
- AC-3：模型/外部工具调用有超时、失败处理、人工重试或取消机制。
- 来源：PRD 2.7、测试用例 TC-AGT-01；D-05。

#### REQ-AGT-002 工作流编排与人工确认

一期必须提供完整 Agent 工作流能力，覆盖经批准的业务模块所需的流程定义/配置、触发、运行、状态追踪、失败恢复及人工介入。工作流能力需按模块解耦，通过明确接口组合；具体编排器技术按 D-05 在架构阶段决定。涉及外发、数据变更或影响候选人/员工业务状态的操作须经过明确授权及配置的人工确认。

- AC-1：每个节点定义输入/输出契约、错误路径、超时与重试上限；流程版本不可静默改变正在执行的实例。
- AC-2：外部副作用具备幂等保护；失败实例可追踪并按权限重试/取消。
- AC-3：Agent 不直接绕过业务服务/权限层修改数据库；所有写入经受控业务接口及审计。
- AC-4：一期工作流至少覆盖经确认业务流程所需的顺序/分支、条件判断、人工等待/审批、任务状态查询、超时/失败/重试/取消/恢复、版本与运行记录；“完整”不等于不受限地执行任意代码或任意外部副作用。
- AC-5：可视化拖拽画布是否为必须交互形式需在原型/验收阶段确认；无论采用画布、表单配置或受控模板，都必须满足 AC-1~AC-4 的运行能力。
- 来源：概要/详细设计工作流、PRD 2.7；工作流一期范围已确认，底层选型待 D-05。

#### REQ-AGT-003 定时任务与数字员工

定时任务/数字员工仅在已确认的具体场景、授权和责任人下执行；每次运行可暂停、取消或转人工处理。

- AC-1：调度时区、错过执行、重叠执行、失败重试、最大重试与告警策略明确。
- AC-2：外发消息、资料变更和候选人阶段变更须限制权限并按需人工批准。
- AC-3：能够查看任务责任人、执行记录、错误与人工接管情况。
- 来源：PRD 2.7、概要设计 `task_scheduling`/`digital_bot`；D-18。

### 6.9 数据决策（DEC）

#### REQ-DEC-001 受控指标查询

一期需提供面向有权管理层的受限自然语言指标查询；用户只能查询已批准的白名单指标，数据集、指标定义和组织范围由服务端授权并限制。

- AC-1：查询只能访问白名单数据集/指标；禁止任意写操作、DDL、越权表/字段访问。模型服务或指标查询服务不可用时须明确提示暂时不可用，不得返回缓存示例、假数据或伪造分析结果。
- AC-2：自然语言请求无法安全映射时，系统拒答或请求澄清，不执行猜测查询。
- AC-3：结果携带查询范围、数据更新时间、指标定义及必要的来源信息。
- AC-4：生成图表/报告不扩大原查询数据权限；导出另行校验授权并审计。
- AC-5：自然语言解析与指标查询引擎在架构阶段选型；可采用指标语义层/预定义查询映射等方式，不能绕过白名单、组织权限、查询限额或审计。
- 来源：PRD 2.5、TC-DEC-01~03；D-06、D-09。

#### REQ-DEC-002 决策建议与审计

AI 建议须区分事实与建议，显示数据依据与限制；不得将相关性描述为因果性，或自动执行人事决策。

- AC-1：建议关联查询结果、时间范围、生成版本和用户权限范围。
- AC-2：无足够或过期数据时显式提示；用户可反馈/标记不准确。
- AC-3：问数审计记录操作者、查询意图、数据范围、执行状态和耗时；按数据最小化原则处理具体 SQL/提示词。
- 来源：PRD 2.5；准确性与审计口径待确认。

### 6.10 通知与运营（OPS）

#### REQ-OPS-001 通知与任务状态

首期提供站内通知能力，对经确认的重要事件提供可见状态/通知，区分待办、成功、失败和需要人工处理的事件。邮件、短信、企业微信/钉钉等外部渠道按需启用。

- AC-1：站内通知事件、订阅规则、频率、模板和保存期需进一步确认；外部渠道启用前确认渠道授权、模板、频率、退订和供应商回执。
- AC-2：通知失败可查看并按策略重试；幂等防止重复通知。
- AC-3：站内通知权限与源业务对象权限保持一致。
- 来源：原型/概要设计工作流输出通知；D-19（首期站内通知已确认）。

#### REQ-OPS-002 运营指标与健康状态

系统按权限展示可验证的业务/运行指标，明确数据窗口和更新时间；示意数据不可作为真实运行数据。

- AC-1：每个指标有定义、计算口径、数据来源和更新时间。
- AC-2：无数据或采集失败时显示不可用/空态，不以常量填充。
- AC-3：敏感业务数据的汇总结果也执行权限与最小群体披露策略（如适用）。
- 来源：原型智能工作台/技术差距页、PRD 非功能要求；页面是否对用户开放待 D-08。

### 6.11 首版招聘闭环（流程细化与业务审批）

下表将推荐主线拆为可验收步骤。建议由业务负责人确认每一步是否属于首版、责任角色、必填信息及完成条件；审批前仅作讨论稿。

| 步骤 | 操作人建议 | 输入与输出 | 完成条件 | 失败/例外需确认 |
|---|---|---|---|---|
| 1. 创建招聘需求 | HR 发起，业务负责人审批 | 岗位/JD版本、人数、组织、优先级、目标日期、技能要求；输出需求编号与状态 | 必填项完整且审批通过，进入可匹配状态 | 退回补充、撤回、冻结、岗位关闭、版本变更如何处理 |
| 2. 导入简历 | HR/招聘人员 | 文件、来源、授权/告知依据；输出逐文件受理结果和任务状态 | 每份简历均可追踪为成功、失败或待处理 | 部分失败、重复文件、格式不支持、批次取消与重试 |
| 3. 解析与复核 | 系统解析，HR确认 | 抽取字段、来源证据、低置信度提示；输出已确认档案 | 必要字段由人员复核；解析失败不得伪装成功 | 复核超时、无法识别、字段冲突及原件访问权限 |
| 4. 查重及关联 | HR/授权档案管理员 | 联系方式等经批准的匹配信号；输出疑似重复列表及关联关系 | 由授权人员确认合并/保持独立 | 同人多份简历、同名、联系方式变更、误合并撤销 |
| 5. 人才匹配 | HR/招聘人员 | 已批准岗位版本和授权人才集；输出排序、分项理由、数据缺口 | 有权人员查看并确认进入候选流程的对象 | 匹配任务失败/过期、岗位变更后的旧结果如何标识 |
| 6. 推进候选人 | HR/招聘人员 | 候选人、招聘需求、当前阶段及操作原因；输出状态历史 | 合法状态迁移并记录负责人和时间 | 退回、拒绝、退出、爽约、重开、跨岗位复用 |
| 7. 邀约与面试 | HR发起，面试官参与 | 时间、渠道、参与人、面试轮次；输出邀约状态与反馈 | 邀约结果可追踪；面试反馈由授权人员提交 | 改期、取消、候选人拒绝/未到、通知失败、面试官离职 |
| 8. 决策与收尾 | HR/业务负责人按授权决策 | 面试反馈及必要记录；输出录用、淘汰、候选人退出或待定 | 人工责任人确认决定，原因与时间留痕 | 岗位关闭、撤回、争议/申诉、后续重新激活 |
| 9. 入职转关联（如纳入） | HR/档案管理员 | 候选人记录、员工身份标识；输出候选人—员工关联 | 不丢失招聘历史，员工档案权限按新身份生效 | 背调失败、延期入职、撤销录用、重复建档 |

### 6.12 候选人状态机建议（待业务审批）

建议候选流程状态为：**新建 → 待筛选 → 待面试 → 面试中 → 待决策 → 录用 / 淘汰 / 候选人退出**。每次迁移需校验当前状态、操作权限和必填信息，并记录操作者、时间、原因、来源渠道及关联岗位/JD版本。拒绝、爽约、取消、暂停、岗位关闭、退回补充及重新开启建议作为迁移原因或受控的次级状态，由业务方确认是否需要独立状态。

审批时需逐项决定：谁可创建/推进/回退/关闭；哪些阶段要求必填评语或原因；是否允许跨阶段跳转；终态能否重开；岗位关闭时在途候选人如何收尾；阶段变化是否触发通知；重复提交/并发更新如何提示。同一候选人可同时参与多个岗位，进度按申请独立管理（D-26）。候选人只看该申请的已提交、筛选中、待面试、待决定、已结束等对外阶段和本人预约信息，不看内部匹配分及面试评价（D-27）；普通阶段自动更新，“已结束”及最终结果必须经 HR 确认后发布。内部阶段到对外阶段的具体映射及最终结果文案仍待确认。未经批准，不将其余示例直接作为系统状态枚举。

### 6.14 人才身份、重复档案与删除规则建议

建议采用“人才主档 + 候选人参与招聘记录 + 员工任职档案”的关联模型作为讨论基线：候选人录用入职时关联同一人才主档并新增员工身份/任职记录，不复制出不可关联的第二份个人主档；每次应聘仍保留独立招聘流程记录。该建议需结合身份标识、权限边界和合规要求审批。

需确认的规则：

1. **同一候选人可同时申请多个岗位**；每次申请独立关联岗位版本、简历版本、招聘状态、匹配结果、邀约与面试反馈。人才主档共用，岗位间决策和进度相互独立；一个岗位的淘汰/关闭不自动影响其他岗位申请。候选人跨申请更新共用资料时须记录版本，并保留各申请实际使用的历史快照。
2. 查重信号及优先级（如经授权的邮箱/电话、来源系统标识、人工核验）；不得仅凭姓名自动合并。
3. 合并为可审计、可撤销操作；保留来源、原始文件引用、字段来源、合并人及时间；冲突字段由人工选定。
4. 候选人撤回应聘或提出删除/更正请求时，分别处理人才主档、招聘记录、原始简历、面试/测评记录、消息副本、向量索引及备份；由法务/隐私负责人确定依法保留的最小记录和期限。
5. 逻辑删除、物理删除、匿名化、停止处理的定义及完成时限分别明确；删除/撤权需传播到搜索索引、缓存、导出副本和下游系统，并提供执行结果记录。
6. 同一人由候选人转员工、员工离职后再次应聘、同一人才应聘多个岗位、重复导入等情形需通过验收场景验证，不能导致跨用途权限自动扩大。

### 6.15 批量处理、通知与人工补救建议

批量导入应有批次编号、总数、成功/失败/处理中计数、逐项错误原因、可安全重试项、失败项下载（需授权）及操作者可见的最终状态。批次重试不得重新处理已成功项或重复发送通知；取消只影响尚未开始或可安全取消的任务，并清晰提示已完成项不会回滚。

解析、模型、通知、日历、存储或索引服务故障时，系统需保留可恢复任务状态、显示最后更新时间和可执行人工步骤。自动重试须有次数/退避上限；超过上限进入人工待办并告警到明确责任角色。人工补救需记录处理人、结果、失败原因及是否重新触发，避免静默丢失或无限重试。D-19/D-21需明确渠道、模板、退订/联系偏好、送达状态、供应商回执和失败后的替代联系流程。

### 6.16 首版业务指标与 AI 评测审批建议

**业务指标**建议先建立基线再承诺收益目标：简历从提交到可复核的中位数/P90耗时、单份简历人工复核耗时、批次处理成功率、候选人阶段停留时间、邀约送达/改期/未到比例、每名招聘人员每周处理量。每项须确定起止点、排除项、组织/岗位分层、数据源、统计窗口、责任人及是否构成验收门槛；首版可先批准“采集并报告基线”，后续再定改善目标。

**AI 评测**建议审批如下口径后再设目标值：

- 简历解析以字段级准确率/召回率/F1为主，关键字段（如联系方式、日期、公司/职位、学历）与非关键字段分层；错误分为阻断/重大/一般，并由 HR 双人抽样复核及指定仲裁人处理分歧。
- 匹配优先评估排序质量（如 Top-K 人工相关性、NDCG/Recall@K 等选定指标），而非简单通过/不通过；按岗位族、资历层级和数据完整度分层，同时审查不同群体的错误差异。分数只用于辅助排序，不自动淘汰。
- RAG 分开统计检索召回、答案事实正确、引用支持度、拒答适当性与越权泄漏；安全越权用例必须零泄漏，不与普通准确率平均抵消。
- 评测集由业务标注人、复核人和仲裁负责人批准，记录抽样来源、授权、版本、盲测集隔离、评测周期；模型、提示词、字段规则、重排器或权限过滤变更触发回归，未达阈值则阻止发布或回滚。
- 目标值、最低样本量、置信区间、复核比例、分层边界、错误严重度和重新验收门槛由 D-15 逐项批准；现有“99%/95%/90%”不应直接视作首版承诺。

### 6.17 待审批事项汇总

仍需逐项确认的事项：

1. **具体业务闭环与优先级**：招聘、培训发展及基础知识问答的端到端流程、模块优先级和验收仍需细化；人才盘点的已确认规则见 D-28/REQ-INV-001~004，具体指标标准和人才池准入条件另待 HR 确认；完整 Agent 工作流为一期范围，不因技术选型而延后。
2. **身份模型**：采用人才主档关联候选人招聘记录与员工任职记录；合并需人工确认、可审计/撤销。
3. **权限模型**：按资源×操作×组织/项目数据范围审批矩阵；管理员不默认获得业务内容访问权限；导出和敏感查看单独授权审计。
4. **招聘状态**：采用本节建议状态及受控迁移，确认阶段、角色、必填字段、终态重开和异常流程。
5. **删除保留**：建立按数据类别配置的保留/删除规则，覆盖附件、评估、日志、索引、下游副本和备份。
6. **指标与 AI**：先确定测量口径和基线；业务目标与 AI 阈值经评测集和风险分层验证后另行批准。
7. **人工补救**：批量部分失败、外部服务故障和通知失败均进入可见、可追踪、有限重试并可人工接管的流程。

## 7. 数据、接口与状态要求

1. **接口契约先行**：写接口前确认请求/响应、错误码、分页/排序、过滤、权限、幂等键、版本与兼容策略；OpenAPI 与需求保持一致。
2. **边界统一**：外部输入在接口层校验；服务端执行权限与业务规则，数据访问经统一的数据访问层；AI 工具不得绕过业务服务直写数据库。
3. **失败可见**：网络/模型/文件解析/存储/索引/消息失败须可识别、可重试或明确终止；不向用户谎报成功，不泄露内部密钥和堆栈。
4. **幂等与并发**：导入、创建、提交、任务触发、消息发送等可能重复的操作定义幂等范围、并发冲突处理及唯一约束策略。
5. **审计**：授权变更、敏感信息访问、导出、人工校正、AI 决策辅助及高风险任务须按策略记录谁、何时、对什么对象、做了什么、结果如何。
6. **枚举单一来源**：所有状态、角色、权限、错误码和任务类型由契约/领域定义生成或共享，禁止前后端各自维护不一致的字符串。
7. **迁移与数据质量**：每次 schema 变更需有可审查迁移、回滚/恢复策略（适用时）、数据校验及升级顺序；迁移操作可审计。
8. **种子数据**：仅用于开发/测试，不得混入生产；数据字典、SQL 与测试说明需保持一致，不使用真实个人简历或未经授权个人信息。
9. **历史材料差异**：`docs/test/seed_data.sql` 的表数量与 `测试数据.md` 所称核心表数量不一致；`knowledge_chunks.milvus_id` 的 NULL 占位说明与 SQL 示例值不一致。需在技术设计冻结前统一，不据此推断生产 schema。
10. **未定义表/模块**：历史材料提及 `workflow_run` 等对象但没有完整表定义；须先明确是否纳入需求，再更新数据模型。

## 8. 非功能、安全与 AI 质量要求

### 8.1 性能与容量（均待 D-16 确认）

现有材料提出：在线并发≥2000、页面渲染≤1s、普通接口≤1s、报表≤3–5s、向量检索≤500ms、全年可用率≥99.9%、AI 服务≥99.5%、缓存命中率≥98%。这些数字尚缺负载模型、统计分位数、部署规格和测量环境，当前仅作待确认目标。

验收前至少定义：并发用户与请求混合、数据规模、冷/热缓存、外部模型响应是否计入、P95/P99、错误率、采样窗口、压测工具/环境和报告格式。不得把原型静态指标当成实测。

### 8.2 安全与隐私

- 个人信息处理遵循目的明确、最小必要、权限最小化、保留期限和删除机制；具体合规义务须由项目法务/安全负责人确认。
- 简历、联系方式、评估、面试录音录像、学习监控、人脸/生物识别属于需重点评估的数据；默认不扩展采集用途。
- 传输、存储加密与密钥管理方案待安全设计；密钥不得进入源码、日志或错误响应。
- 文件上传实施类型/大小校验、恶意内容检测与安全存储；文件下载防止未授权访问与路径越权。
- 防止提示注入、越权 RAG、模型输出注入、敏感信息泄露；模型输出作为不可信数据处理，不直接执行命令/SQL或外部副作用。
- 保留审计、备份、恢复、删除和事件响应策略；备份也须执行访问控制和保留策略。
- 国产化、私有化目标按 D-17 明确供应商、版本和验证标准。

### 8.3 AI 评测与人工监督

| 能力 | 历史材料目标 | 评测要求草案 | 现状/风险 |
|---|---:|---|---|
| 简历解析 | ≥99% | 明确字段级/样本级口径、精确率/召回率/F1、字段权重、文档类型分层与人工抽查 | 现有 `resume_parse_eval.json` 仅示例规模；不足以验收 |
| RAG | ≥95% | 分别衡量检索命中、答案正确、引用正确、拒答；纳入越权与无依据问题 | `rag_eval.json` 仅示例规模；定义混合“准确率”会误导 |
| 岗位匹配 | ≥90% | 定义正例/负例、排序指标或阈值一致率、岗位分层及人工标注一致性 | `match_eval.json` 仅示例规模；偏差/公平性规则未定 |

- 数据集至少覆盖目标场景、困难样本、不同输入质量和越权/拒答边界；样本数应通过统计与业务风险评估确定，而不是仅达到固定数量。
- 评测集需版本化、去重、标注双人复核/仲裁，记录数据授权和敏感信息处理；生产数据用于评测须经批准。
- 模型、Prompt、检索配置或规则变更需回归评测；上线阈值、回滚条件和人工复核抽样率待确认。
- AI 输出需能追溯模型/配置版本和必要输入来源；不承诺“零幻觉”。
- 人才筛选/评估须有人类监督、纠错和申诉路径；不得把未经验证的分数当作唯一决策依据。

### 8.4 可用性与可维护性

系统需为无数据、加载中、部分失败、无权限、服务不可用、模型超时、提交重复和任务失败提供一致可理解的反馈；运维侧可定位请求/任务并关联日志指标。具体可用率、恢复时间目标、恢复点目标、告警渠道与值班责任待 D-16/D-20 确认。

### 8.5 多端与无障碍

需确认 D-11 后定义支持的浏览器/视口、响应式断点、键盘操作、表单错误提示和图表替代文本。现有原型主要为桌面静态线框，不能视为移动端验收依据；原型亦未完整覆盖登录、空态、错误态。

## 10. 测试与验收策略

### 10.1 需求追溯

每条批准需求须关联至少一个验收场景；P0 需求关联端到端测试、权限测试和失败路径测试。接口、原型、测试用例与用户手册的名称/状态枚举须基于同一契约。

### 10.2 测试层次

- 单元/组件：业务规则、状态流转、评分/权限决策。
- 集成：真实测试数据库/对象存储/向量检索/模型替身边界；对外部供应商可用受控契约测试，但不能以 mock 代替关键数据安全与持久化验收。
- 端到端：经批准主流程，使用可复现测试数据并验证失败/重试/重复提交。
- 安全：角色、行级、字段级、导出、RAG、问数及管理操作越权测试。
- AI 评测：固定版本标注集、基线对比、模型/配置回归和人工抽检。
- 性能/恢复：按确认的容量方案压测，验证任务积压、外部模型超时与恢复行为。

### 10.3 交付验收门槛（草案，待批准）

1. 所有批准的 P0 需求通过率 100%，阻断级安全问题为零；P1 门槛由项目方确认。
2. P0 端到端流程以真实后端持久化数据通过，包含失败、重复请求、权限与审计断言。
3. AI 指标只在 D-15 批准的评测集/公式上验收，并提交数据集版本、评测报告和误差分析。
4. 性能、安全、隐私、兼容性达到经批准的目标，并提供可复核报告。
5. 数据迁移/备份恢复/部署文档、运维手册、已知限制、交付清单和验收记录齐备。
6. 所有示意数据与演示账户清楚标识，不将原型静态内容作为验收通过证据。

## 12. 工程与协作纪律（项目执行约束）

1. 先确认需求，再制订开发计划/todolist；用户明确说“开始”前不写代码。

8. 报告工作状态必须区分已完成、已验证、推断与待确认，不把历史 PRD 的“已落地”作为当前代码事实。
