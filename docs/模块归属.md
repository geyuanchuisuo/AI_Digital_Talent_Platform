# 模块归属与公共文件维护

日期：2026-11-06。角色沿用四人分工；真实姓名/远端用户名待组内绑定。机器路径清单为 [.collaboration/ownership.json](../.collaboration/ownership.json)，本文件是说明，不维护第二套冲突通配规则。

A 管身份、数据库底座、前端 app/shared、招聘及匹配；B 管 files/talents/knowledge；C 管 assessments/interviews/training；D 管 ai/tasks 与 analytics/reports/workflows/dashboard，任务进度组件放 features/tasks，不侵入 A 的 shared。

每人拥有 tasks/<本人>.md、tests/<本人>/、scripts/<本人>/、docs/modules/<本人>/、docs/updates/<本人>/ 和 docs/requests/<本人>/。业务目录中的局部测试随本目录归属。

公共文件的唯一维护角色为 A：根文档和规则、依赖清单/锁、主路由、共享组件/类型、数据库连接、Alembic 环境与迁移链整合。D 独立维护 worker.py、模型与任务核心。公共框架不是开放编辑区。

各人可以提交 backend/migrations/versions/<角色>_*.py，只涉及本人模型；迁移文件名角色前缀仅用于归属，Alembic 内部 revision/down_revision 仍应合法且由 A 协调。共同基线分叉产生多个 head 时，由 A 整理合并迁移，不让 B/C/D 改别人迁移修冲突。

全部 AGENTS.md/CLAUDE.md 统一由 A 维护，其他角色不得修改自己目录中的规则文件。AGENTS.override.md 禁止；新目录未分配默认不可写。旧 PRD、原型、design/test、requirements 来源保持只读，目录 data/ 与秘密永不提交。

跨包请求走 docs/requests/<本人>/，维护人用自己的更新记录响应。路由注册、依赖增加等最终由 A 接入；模型/任务入口变更由 D 接入。A 集成也不获得任意重写 B/C/D 的业务权限，冲突回原维护人处理。

角色与路径检查没有防伪身份能力，不能阻止蓄意改规则。远端负责人应绑定真实 Git 账号、保护集成分支，并在平台支持时设置评审/CI；当前尚未配置这些远端措施。
