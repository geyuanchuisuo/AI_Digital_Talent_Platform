## 一、统一响应格式

### 成功（HTTP 200）
```json
{ "code": 0, "message": "success", "data": { } }
```

### 已受理（HTTP 202）
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_id": 12,
    "upload_batch_id": "01J...",
    "duplicates": [],
    "rejected": []
  }
}
```

### 错误（HTTP 4xx/5xx）
```json
{
  "code": 400,
  "message": "weights 总和必须为 100",
  "data": null,
  "request_id": "req-..."
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 只用 §二 的 9 个值；成功恒为 0 |
| `message` | string | 中文业务提示，直接展示给用户 |
| `data` | any \| null | 错误时恒为 `null`；成功时为业务数据 |
| `request_id` | string | **仅错误响应携带**；中间件生成，错误排查用。成功/202 不返回该字段（接口 §1.1、架构 §5.1） |

> 不再使用 `detail` 字段。需要调试信息时写日志，不放进响应体。
> **唯一例外**：`GET /health` 直接返回健康检查结构，不套 `{code,message,data}`（接口 §3），也不参与本文件的统一封装。

## 二、错误码（严格对齐接口 §1.2）

| code | HTTP | 含义 | 触发场景 |
|---|---|---|---|
| 0 | 200 / 202 | 成功 | — |
| 400 | 400 | 参数/业务校验失败 | 权重≠100、pass≤pending、批次范围无对象、状态不可重试、硬淘汰不可改判、岗位停用、resolve 状态不对、上传格式/大小非法 |
| 401 | 401 | 未认证 / token 失效 | 无 token、token 过期、token 篡改、登录用户名或密码错误 |
| 403 | 403 | 账号停用 | `users.is_active=0` 登录或访问 |
| 404 | 404 | 资源不存在 | 画像/任务/批次/岗位/查重记录不存在；重复 DELETE 也统一 404 |
| 409 | 409 | 唯一键冲突 | 数据库唯一约束冲突（非文件重复；文件重复走 202 + `duplicates`） |
| 422 | 422 | Pydantic 结构校验失败 | 字段缺失、类型错误、枚举非法 |
| 500 | 500 | 服务内部错误 | 未捕获异常、DB/LLM/Embedding/文件系统错误 |
| 503 | 503 | 依赖不可用，**且请求尚未产生任何业务写入** | 语义检索时 Milvus 不可用；`revector` 时 Embedding/Milvus 不可用 |

### 半写例外（决策 D-B）
同步接口 `PATCH /talents/{id}`、duplicates `merge`/`restore` 在 MySQL 事务已提交后，若 embedding 或 Milvus 失败 / 超过 `VECTOR_SYNC_TIMEOUT`（5s，运行配置 v1.4）：
- **HTTP 200**，`data.vector_status="failed"`，`message` 提示「画像已保存，向量同步失败，可稍后重试」；
- 不回滚业务数据，**不返回 503**。

## 三、业务提示语清单（message 文案，不是错误码）

| 场景 | HTTP | code | message |
|---|---|---|---|
| 登录失败 | 401 | 401 | 用户名或密码错误 |
| 未登录/过期 | 401 | 401 | 未登录或登录已过期 |
| 账号停用 | 403 | 403 | 账号已停用 |
| 上传格式不支持 | 400 | 400 | 仅支持 PDF / DOCX 文件 |
| 文件超过上限 | 400 | 400 | 单个文件不能超过 20MB |
| 文件为空/损坏 | 400 | 400 | 文件内容为空或损坏 |
| 权重总和不等于 100 | 400 | 400 | weights 总和必须为 100 |
| pass ≤ pending | 400 | 400 | pass_threshold 必须大于 pending_threshold |
| min_degree 非法 | 400 | 400 | min_degree 必须是 博士/硕士/本科/大专/高中中专/其他 之一 |
| 批次范围无对象 | 400 | 400 | 筛选/匹配范围未圈定有效人才 |
| 批次运行中不能 retry | 400 | 400 | 批次正在执行，请完成后再重试 |
| 任务状态不允许 retry | 400 | 400 | 当前任务状态不允许该操作 |
| 硬淘汰不可改判 | 400 | 400 | 硬淘汰结果不可改判 |
| 查重记录状态不对 | 400 | 400 | 该查重记录已处理，不能重复操作 |
| master 不是 profile_a | 400 | 400 | master_profile_id 必须等于 profile_a_id |
| 岗位停用 | 400 | 400 | 岗位已停用，不能创建筛选/匹配批次 |
| 画像已软删 | 404 | 404 | 画像不存在或已删除 |
| 资源不存在 | 404 | 404 | 记录不存在 |
| 唯一键冲突 | 409 | 409 | 数据已存在，请勿重复提交 |
| Pydantic 校验失败 | 422 | 422 | 请求参数结构不合法 |
| 语义检索依赖不可用 | 503 | 503 | 语义检索服务暂时不可用，请稍后重试 |
| revector 依赖不可用 | 503 | 503 | 向量化服务暂时不可用，请稍后重试 |
| 内部错误 | 500 | 500 | 服务器内部错误 |

> 同一 code 下允许不同 message；前端按 code 分支，按 message 展示。

## 四、JWT 鉴权

### 配置
- `JWT_SECRET`（架构 §5.6）、`JWT_EXPIRE_HOURS=24`（架构 §6.1、接口 §2）。
- 算法固定 `HS256`，不配置算法键。

### Payload
```json
{
  "sub": "1",
  "username": "hr",
  "role": "hr",
  "iat": 1730000000,
  "exp": 1730086400
}
```

| 字段 | 来源 |
|---|---|
| `sub` | `users.id`（字符串） |
| `username` | `users.username` |
| `role` | `users.role`（一期只有 `hr`） |
| `exp` | `iat + JWT_EXPIRE_HOURS * 3600` |

### 认证规则
- 除 `POST /auth/login`、`GET /health` 外，全部接口要求 `Authorization: Bearer <JWT>`。
- 无 token / 过期 / 篡改 → 401。
- token 合法但 `users.is_active=0` → 403。
- 一期不做 RBAC；不存在 `require_admin` 依赖，也不校验角色。

### 依赖注入参考
```python
from fastapi import Depends, HTTPException
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials

bearer_scheme = HTTPBearer(auto_error=False)

def get_current_user(
    creds: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> Users:
    if creds is None:
        raise HTTPException(status_code=401, detail="未登录或登录已过期")
    try:
        payload = jwt.decode(
            creds.credentials, settings.jwt_secret, algorithms=["HS256"]
        )
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="未登录或登录已过期")
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail="未登录或登录已过期")

    user = dao.users.get_by_id(int(payload["sub"]))
    if not user:
        raise HTTPException(status_code=401, detail="未登录或登录已过期")
    if not user.is_active:
        raise HTTPException(status_code=403, detail="账号已停用")
    return user
```

> `GET /auth/me`、所有业务路由统一挂 `Depends(get_current_user)`；不再额外写角色依赖。

## 五、登录接口（补全接口 §2 的响应细节）

### `POST /auth/login`

**Request**
```json
{ "username": "hr", "password": "hr123456" }
```

**Response 200**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 86400,
    "user": {
      "id": 1,
      "username": "hr",
      "display_name": "HR",
      "role": "hr"
    }
  }
}
```

**错误**
- 401 `用户名或密码错误`（不区分用户不存在/密码错误）
- 403 `账号已停用`

**实现要点**
1. 按 `username` 查 `users`；
2. `bcrypt.verify(password, user.password_hash)`；
3. 成功签发 HS256 JWT，`expires_in = JWT_EXPIRE_HOURS * 3600`；
4. 更新 `last_login_at`；
5. `is_active=0` 不签发 token，返回 403。

### `GET /auth/me`
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "username": "hr",
    "display_name": "HR",
    "role": "hr"
  }
}
```

## 六、全局异常处理

```python
class BizError(Exception):
    """service 层抛这个；code 取 400/409/422/500/503（401/403/404 用 HTTPException）"""
    def __init__(self, code: int, message: str):
        self.code = code
        self.message = message
        self.status_code = code


@app.exception_handler(BizError)
async def biz_error_handler(request: Request, exc: BizError):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "code": exc.code,
            "message": exc.message,
            "data": None,
            "request_id": request.state.request_id,
        },
    )


@app.exception_handler(RequestValidationError)
async def validation_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content={
            "code": 422,
            "message": "请求参数结构不合法",
            "data": None,
            "request_id": request.state.request_id,
        },
    )


@app.exception_handler(Exception)
async def unknown_handler(request: Request, exc: Exception):
    logger.exception("unhandled", extra={"request_id": request.state.request_id})
    return JSONResponse(
        status_code=500,
        content={
            "code": 500,
            "message": "服务器内部错误",
            "data": None,
            "request_id": request.state.request_id,
        },
    )
```

> FastAPI 原生 `HTTPException` 用 `detail` 传 message；全局 handler 把它转成 `{code: status_code, message: detail, data: null, request_id}`。401/403 的 `detail` 直接写中文文案。

## 七、前端 Axios 约定

```typescript
import { message as antdMessage } from 'antd'

instance.interceptors.response.use(
  (response) => {
    const { code, data, message: msg } = response.data
    if (code === 0) return data
    antdMessage.error(msg)
    return Promise.reject(new Error(msg))
  },
  (error) => {
    const { status, data } = error.response ?? {}
    const msg = data?.message ?? error.message
    if (status === 401) {
      localStorage.removeItem('token')
      router.push('/login')
    }
    if (status === 503) {
      notifyDegraded(msg) // 页面顶部黄色告警条，不自动重试
    }
    antdMessage.error(msg)
    return Promise.reject(error)
  }
)
```

> 变量不要命名为 `message`，否则会遮蔽 antd 的 `message` 实例，`message.error(...)` 运行时必报错。
> 图片/文件下载走 `responseType: 'blob'`，不走统一 `code` 判断；失败时按 HTTP status 提醒。
